Error Boundaries Beyond React: Global Error Handling Patterns in Node, Bun, Deno
When it comes to web development, handling errors is a crucial aspect that can significantly impact user experience and the reliability of an application. While React offers a built-in component for error boundaries, the concept of error handling extends beyond the frontend. In this article, we'll explore global error handling patterns in Node.js, Bun, and Deno, providing real-world scenarios, code examples, and actionable takeaways.
Real-World Scenario
Let's consider the scenario of an e-commerce platform. Aiko, a software engineer, is responsible for handling errors in a Node.js server that processes and serves orders. One day, an unexpected error occurs when the system attempts to fetch customer data, leading to a complete server outage. To prevent such situations, Aiko needs to implement a robust error handling strategy.
Global Error Handling in Node.js
1. Custom Error Handling Middleware
Node.js provides middleware functions that can be used to handle errors globally. Aiko can create a custom middleware that catches any unhandled exceptions or rejections and logs them.
javascript // /src/middleware/errorHandler.js const errorHandler = (err, req, res, next) => { console.error('Unhandled Error:', err); res.status(500).send('Something went wrong!'); };

module.exports = errorHandler; 


In the server's main file, Aiko can apply this middleware:
javascript // /src/server.js const express = require('express'); const errorHandler = require('./middleware/errorHandler');

const app = express();

app.use(errorHandler);

const PORT = process.env.PORT || 3000; app.listen(PORT, () => { console.log(Server running on port ${PORT}); }); 



2. UncaughtException and UnhandledRejection
Node.js also allows catching uncaught exceptions and unhandled rejections globally using the process object.
javascript // /src/server.js process.on('uncaughtException', (err) => { console.error('Uncaught Exception:', err); process.exit(1); });

process.on('unhandledRejection', (reason, promise) => { console.error('Unhandled Rejection at:', promise, 'reason:', reason); process.exit(1); }); 



Global Error Handling in Bun
Bun, a new runtime for Node.js applications, provides similar features for global error handling. Here's how Aiko can implement it:
1. Bun's bun:handler
Bun's bun:handler allows Aiko to define a global error handler.
javascript // /src/server.js const { bun: handler } = require('bun');

handler((req, res) => { try { // Application logic } catch (err) { console.error('Error in Bun application:', err); res.status(500).send('Something went wrong!'); } });

const PORT = process.env.PORT || 3000; await bun.run(http://localhost:${PORT}); 



Global Error Handling in Deno
Deno also offers a straightforward way to handle global errors.
1. Deno's Deno.core.setGlobalErrorHandler
Aiko can use Deno.core.setGlobalErrorHandler to define a global error handler for Deno applications.
javascript // /src/server.js const { core } = require('deno');

core.setGlobalErrorHandler((err) => { console.error('Global Error:', err); Deno.exit(1); });

// Application logic 



Comparison Table
| Feature               | Node.js            | Bun                | Deno               |
|-----------------------|--------------------|--------------------|--------------------|
| Error Handling Method | Middleware, process events | bun:handler     | Deno.core.setGlobalErrorHandler |
| Flexibility           | High               | High               | High               |
| Performance           | Moderate           | Moderate           | Moderate           |
Lessons Learned
  • Implement Global Error Handling: Don't rely solely on application-level error boundaries; always have a global error handling strategy to catch unhandled exceptions and rejections.
    • 

  • Customize Error Messages: Provide meaningful error messages to help with debugging and improve user experience.
    • 

  • Log Errors for Audit: Keep logs of errors for audit purposes and to understand the root causes of issues.
    • Actionable Takeaways
  • Learn and Implement Global Error Handling: Familiarize yourself with the global error handling patterns in Node.js, Bun, and Deno and implement them in your applications.
    • 

  • Choose the Right Pattern: Evaluate your application's needs and choose the appropriate global error handling pattern.
    • 

  • Test Your Error Handling: Regularly test your error handling mechanisms to ensure they work as expected.
    • By implementing these global error handling patterns, Aiko was able to ensure the reliability and stability of the e-commerce platform's backend. Remember, robust error handling is key to delivering a high-quality user experience and maintaining the integrity of your applications.
