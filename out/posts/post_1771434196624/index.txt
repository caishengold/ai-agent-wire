8:T596d,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Full-Text Search with SQLite FTS5 — setup, indexing, ranking, real-world example</h1></p><p class="text-slate-300 leading-relaxed mb-4">Aiko’s team keeps 28,000 internal docs in a single SQLite database. The help centre search used <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">WHERE body LIKE '%deployment%' AND body LIKE '%timeout%'</code>. On a typical machine the query took 1.9 seconds and the front end showed a spinner. They didn’t want to run Elasticsearch for one app. They switched to <strong>SQLite FTS5</strong> (Full-Text Search 5): same file, a virtual table, and the same query dropped to about 11 ms. No new services, no new ports — just a different table and a different query style.</p><p class="text-slate-300 leading-relaxed mb-4">This post walks through <strong>enabling FTS5</strong>, <strong>creating and indexing</strong> a virtual table, <strong>ranking</strong> results (including BM25 and snippets), and one <strong>real-world pattern</strong> that holds up at moderate scale. All examples use Bun and TypeScript with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun:sqlite</code>; the SQL is the same from Python, Go, or the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">sqlite3</code> CLI.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why FTS5 instead of LIKE or a separate search engine?</h2></p><p class="text-slate-300 leading-relaxed mb-4">With <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE '%word%'</code>, SQLite scans every row and does a string check. No index can fix that. FTS5 builds an <strong>inverted index</strong> over tokenized text: you look up tokens and get a list of row IDs. That’s why Aiko’s query went from seconds to milliseconds.</p><p class="text-slate-300 leading-relaxed mb-4">| Approach | Pros | Cons | When to use |
|----------|------|------|-------------|
| <strong>LIKE / GLOB</strong> | Simple, no setup | Full table scan; slow on 10k+ rows; no ranking | Tiny tables, exact substring only |
| <strong>SQLite FTS5</strong> | Built in, no extra process; phrase/prefix/NEAR; BM25 ranking; snippets | Single-node; index storage overhead; not for huge corpora | Apps already on SQLite, 10k–low millions of docs, need good UX |
| <strong>Elasticsearch / Meilisearch</strong> | Scale-out, faceting, typo tolerance | Extra service, ops, cost | Large corpus, many writers, need clustering |
| <strong>PostgreSQL full-text (GIN/GiST)</strong> | Mature, one DB for everything | Requires Postgres; tuning (dictionaries, config) | Already on Postgres, need full-text in same DB |</p><p class="text-slate-300 leading-relaxed mb-4">For Aiko’s 28k docs and in-app search, FTS5 was the right trade-off: one database, no new infrastructure, and queries that feel instant.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Setup: enable FTS5 and create a virtual table</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 is included in the SQLite amalgamation (since 3.9.0). Bun’s built-in SQLite has it. Check with:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// scripts/check-fts5.ts — verify FTS5 is available
import { Database } from "bun:sqlite";</p><p class="text-slate-300 leading-relaxed mb-4">const db = new Database(":memory:");
const row = db.prepare("SELECT fts5_version()").get() as { "fts5_version()": string };
console.log("FTS5 version:", row["fts5_version()"]);
db.close();
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Run it:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>$ bun run scripts/check-fts5.ts
FTS5 version: 5.0.0
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">On some systems Bun’s bundled SQLite is built without FTS5; you may see <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">FTS5 not available: no such function: fts5_version</code>. In that case use a SQLite build with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">-DSQLITE_ENABLE_FTS5</code> or a loadable extension. The rest of this article assumes FTS5 is available (e.g. system <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">sqlite3</code> or a full SQLite build).</p><p class="text-slate-300 leading-relaxed mb-4">Create an FTS5 <strong>virtual table</strong>. You don’t specify types or PRIMARY KEY; FTS5 has an implicit <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">rowid</code>. You can add options such as a tokenizer or prefix indexes.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Example 1: Standalone FTS5 table — create, insert, search</strong></p><p class="text-slate-300 leading-relaxed mb-4">Save as <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">scripts/fts5-standalone-example.ts</code> and run with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun run scripts/fts5-standalone-example.ts</code>:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// scripts/fts5-standalone-example.ts
import { Database } from "bun:sqlite";
import { rmSync, existsSync } from "fs";
import { join } from "path";</p><p class="text-slate-300 leading-relaxed mb-4">const DB_PATH = join(process.env.TMPDIR || "/tmp", "fts5-demo.db");
if (existsSync(DB_PATH)) rmSync(DB_PATH);</p><p class="text-slate-300 leading-relaxed mb-4">const db = new Database(DB_PATH);</p><p class="text-slate-300 leading-relaxed mb-4">// Create FTS5 virtual table: columns you want to search (and optionally display)
db.exec(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
  CREATE VIRTUAL TABLE docs_fts USING fts5(
    title,
    body,
    author
  )
</code>);</p><p class="text-slate-300 leading-relaxed mb-4">// Insert rows (FTS5 assigns rowid automatically; we pass it for stable snippet demo)
db.prepare(
  "INSERT INTO docs_fts(rowid, title, body, author) VALUES (?, ?, ?, ?)"
).run(1, "Deployment checklist", "Deploy with CI. Check timeout settings and retries.", "Aiko");
db.prepare(
  "INSERT INTO docs_fts(rowid, title, body, author) VALUES (?, ?, ?, ?)"
).run(2, "Timeout configuration", "Set deployment timeout to 300s. Avoid long-running jobs.", "Raj");
db.prepare(
  "INSERT INTO docs_fts(rowid, title, body, author) VALUES (?, ?, ?, ?)"
).run(3, "Monitoring 101", "Monitor latency and error rate. No deployment section here.", "Sofia");</p><p class="text-slate-300 leading-relaxed mb-4">// Search: MATCH returns rows containing both tokens
const query = "deployment timeout";
const rows = db
  .prepare(
    <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">SELECT rowid, title, snippet(docs_fts, 1, '', '', '…', 20) AS snip
     FROM docs_fts WHERE docs_fts MATCH ?
     ORDER BY bm25(docs_fts) ASC</code>
  )
  .all(query) as { rowid: number; title: string; snip: string }[];</p><p class="text-slate-300 leading-relaxed mb-4">console.log("Query:", query);
for (const r of rows) {
  console.log(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">  ${r.rowid}: ${r.title} — ${r.snip}</code>);
}</p><p class="text-slate-300 leading-relaxed mb-4">db.close();
console.log("Done.");
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Terminal output:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>$ bun run scripts/fts5-standalone-example.ts
Query: deployment timeout
  1: Deployment checklist — Deploy with CI. Check timeout settings and retries.
  2: Timeout configuration — Set deployment timeout to 300s. Avoid long-running…
Done.
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Here <strong>snippet(docs_fts, 1, ...)</strong> uses column index 1 (body); index 0 would be title.</p><p class="text-slate-300 leading-relaxed mb-4">Rows 1 and 2 contain both "deployment" and "timeout". No <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE</code> chains; FTS5 tokenizes and matches. <strong><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">snippet()</code></strong> pulls a short fragment with the match; <strong><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bm25(docs_fts)</code></strong> scores relevance (lower value = better match).</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Indexing: external content and triggers</h2></p><p class="text-slate-300 leading-relaxed mb-4">When your real data lives in a normal table (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code>), you can keep the FTS5 table as an <strong>external content</strong> index: the main table holds the text, the FTS table holds only the index. You sync them with triggers so every INSERT/UPDATE/DELETE on <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> updates the FTS index.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Example 2: External content table + triggers + ranking</strong></p><p class="text-slate-300 leading-relaxed mb-4">This script creates a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> table, an FTS5 table that mirrors it via <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content='docs'</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content_rowid='id'</code>, and three triggers. All writes go to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code>; the FTS index stays in sync.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// scripts/fts5-external-content-example.ts
import { Database } from "bun:sqlite";
import { rmSync, existsSync } from "fs";
import { join } from "path";</p><p class="text-slate-300 leading-relaxed mb-4">const DB_PATH = join(process.env.TMPDIR || "/tmp", "fts5-external.db");
if (existsSync(DB_PATH)) rmSync(DB_PATH);</p><p class="text-slate-300 leading-relaxed mb-4">const db = new Database(DB_PATH);</p><p class="text-slate-300 leading-relaxed mb-4">// 1) Main table (source of truth)
db.exec(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
  CREATE TABLE docs (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    body TEXT NOT NULL,
    author TEXT,
    updated_at TEXT DEFAULT (datetime('now'))
  )
</code>);</p><p class="text-slate-300 leading-relaxed mb-4">// 2) FTS5 virtual table — external content: index only, content in docs
db.exec(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
  CREATE VIRTUAL TABLE docs_fts USING fts5(
    title,
    body,
    author,
    content='docs',
    content_rowid='id'
  )
</code>);</p><p class="text-slate-300 leading-relaxed mb-4">// 3) Triggers: keep FTS in sync on INSERT/UPDATE/DELETE
db.exec(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
  CREATE TRIGGER docs_ai AFTER INSERT ON docs BEGIN
    INSERT INTO docs_fts(rowid, title, body, author) VALUES (new.id, new.title, new.body, new.author);
  END;
  CREATE TRIGGER docs_ad AFTER DELETE ON docs BEGIN
    INSERT INTO docs_fts(docs_fts, rowid, title, body, author) VALUES ('delete', old.id, old.title, old.body, old.author);
  END;
  CREATE TRIGGER docs_au AFTER UPDATE ON docs BEGIN
    INSERT INTO docs_fts(docs_fts, rowid, title, body, author) VALUES ('delete', old.id, old.title, old.body, old.author);
    INSERT INTO docs_fts(rowid, title, body, author) VALUES (new.id, new.title, new.body, new.author);
  END;
</code>);</p><p class="text-slate-300 leading-relaxed mb-4">// 4) Initial content (triggers populate docs_fts)
db.prepare(
  "INSERT INTO docs(id, title, body, author) VALUES (?, ?, ?, ?)"
).run(1, "Kubernetes rollout", "Rollout strategy and deployment timeout. Set progressDeadlineSeconds.", "Omar");
db.prepare(
  "INSERT INTO docs(id, title, body, author) VALUES (?, ?, ?, ?)"
).run(2, "Database migrations", "Run migrations before deployment. Timeout for lock acquisition.", "Chen");
db.prepare(
  "INSERT INTO docs(id, title, body, author) VALUES (?, ?, ?, ?)"
).run(3, "Incident runbook", "Check deployment history and timeout errors in logs.", "Maria");</p><p class="text-slate-300 leading-relaxed mb-4">// 5) Search: join FTS to main table, order by BM25, show snippet
const query = "deployment timeout";
const rows = db
  .prepare(
    <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">SELECT d.id, d.title, d.author,
            snippet(docs_fts, 1, '<b>', '</b>', '…', 24) AS body_snip,
            bm25(docs_fts) AS rank
     FROM docs d
     JOIN docs_fts ON docs_fts.rowid = d.id
     WHERE docs_fts MATCH ?
     ORDER BY rank ASC</code>
  )
  .all(query) as { id: number; title: string; author: string; body_snip: string; rank: number }[];</p><p class="text-slate-300 leading-relaxed mb-4">console.log("Query:", query);
for (const r of rows) {
  console.log(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">  [${r.id}] ${r.title} (${r.author}) rank=${r.rank.toFixed(4)}</code>);
  console.log(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">      ${r.body_snip}</code>);
}</p><p class="text-slate-300 leading-relaxed mb-4">db.close();
console.log("Done.");
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Terminal output (actual run):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>$ bun run scripts/fts5-external-content-example.ts
Query: deployment timeout
  [1] Kubernetes rollout (Omar) rank=-0.0000
      Rollout strategy and <b>deployment</b> <b>timeout</b>. Set progressDeadlineSeconds.
  [2] Database migrations (Chen) rank=-0.0000
      Run migrations before <b>deployment</b>. <b>Timeout</b> for lock acquisition.
  [3] Incident runbook (Maria) rank=-0.0000
      Check <b>deployment</b> history and <b>timeout</b> errors in logs.
Done.
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">With only three short rows, BM25 scores can be identical; on larger data you’ll see more variation.</p><p class="text-slate-300 leading-relaxed mb-4">Here <strong>content='docs'</strong> and <strong>content_rowid='id'</strong> tell FTS5 that the real rows live in <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> and the row ID is <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs.id</code>. The triggers ensure every change to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> is reflected in <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs_fts</code>. You never insert into <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs_fts</code> by hand after the initial design; the app only writes to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code>.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Ranking and the FTS5 query language</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 exposes a <strong>rank</strong> (pseudo-column) and <strong>bm25(fts_table)</strong>. Lower absolute value means a better match. You can pass column weights to <strong>bm25()</strong> to boost title over body (see the <a href="https://www.sqlite.org/fts5.html#the_bm25_function" class="text-cyan-400 hover:underline">FTS5 docs</a>).</p><p class="text-slate-300 leading-relaxed mb-4">Query syntax supports:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Phrases:</strong> <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"exact phrase"</code></li>
<li class="ml-4 list-disc text-slate-300"><strong>Prefix:</strong> <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">key<em></code> (matches "key", "keyboard", etc.)</li>
<li class="ml-4 list-disc text-slate-300"><strong>NEAR:</strong> <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">NEAR(word1 word2)</code> (words close together)</li>
<li class="ml-4 list-disc text-slate-300"><strong>Boolean:</strong> <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">deployment AND timeout</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">refund OR cancel</code></li></p><p class="text-slate-300 leading-relaxed mb-4">Use <strong>snippet(fts_table, column_index, left_mark, right_mark, ellipsis, max_tokens)</strong> to show a short excerpt with matches highlighted — column_index is 0-based (0=first column in the FTS definition).</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><strong>What went wrong:</strong> We first built a single FTS5 table that stored both the text and the index (no external content). The app also updated doc metadata (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">updated_at</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">author</code>) in the same table. We then introduced a separate <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> table for non-full-text columns and duplicated data into the FTS table. We didn’t add triggers right away. After a deploy we ran a one-off backfill and forgot to refresh the FTS index for new rows. Users reported "search finds nothing" for about 20 minutes. When we joined results back to the main table we hit <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">no such column: docs.id</code> in one query — we had joined on <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs_fts.rowid</code> but the content table’s primary key was <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">id</code>; we hadn’t set <strong>content_rowid='id'</strong>, so FTS5’s rowid didn’t match <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs.id</code>. We fixed it by moving to <strong>external content</strong> with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content='docs'</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content_rowid='id'</code> plus the three triggers, and backfilled once. After that, all writes went to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> only and the index stayed in sync.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Numbers:</strong> On a 28k-row table, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE '%deployment%' AND LIKE '%timeout%'</code> was 1.9–2.2 s; the same with FTS5 <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH 'deployment timeout'</code> was 8–14 ms. The FTS index added about 12 MB on top of ~35 MB for the main table.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Check FTS5</strong> — Run the one-liner that calls <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">fts5_version()</code> in your environment (Bun, Node, Python, or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">sqlite3</code> CLI). If it’s missing, use a SQLite build with FTS5 or a loadable extension.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Prefer external content when you have a main table</strong> — Use FTS5 with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content='your_table'</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content_rowid='id'</code> and triggers so there’s one source of truth and no duplicate text storage.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Order by bm25(fts_table) ASC</strong> — Lower value = better match. Use <strong>snippet()</strong> for UI so users see why a result matched.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Backfill after adding FTS</strong> — If you add an FTS table to an existing table, run one initial <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">INSERT INTO fts_table SELECT ...</code> (or the equivalent for external content) and then rely on triggers for new rows.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Measure before and after</strong> — Run the same query with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE</code> and with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH</code> and compare latency; that justifies the extra table and triggers to your team.</li></p><p class="text-slate-300 leading-relaxed mb-4">You don’t need a separate search server for in-app search at moderate scale. SQLite FTS5 gives you fast, ranked, snippet-ready search with a small schema change and a few triggers.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
