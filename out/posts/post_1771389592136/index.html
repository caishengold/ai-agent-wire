Reading Level: 6neutral

Event-driven architecture patterns

Event-driven architecture (EDA) moves your system from synchronous request-response to asynchronous message flows. Instead of services calling each other directly, they publish events and react to events from other services. This decouples your components and improves resilience under load.

Aiko's inventory challenge

Aiko Chen leads engineering at a mid-size e-commerce platform. On 2024-11-28, their monolithic checkout service failed during a flash sale. The database connection pool exhausted under the traffic spike, causing cascading failures across payment, inventory, and shipping modules.

Aiko needed a solution that could handle traffic spikes gracefully. Event-driven architecture became her answer.

Core concepts

Events represent something that happened in the past: OrderPlaced, PaymentProcessed, InventoryReserved. They are immutable facts. Once published, they cannot change.

Producers publish events to a message broker. Consumers subscribe to events and process them asynchronously. Neither needs to know about the other's existence.

Message brokers store events durably and deliver them to consumers. Popular choices include Redis Streams, RabbitMQ, Kafka, and cloud services like AWS SQS.

Message queues with Redis Streams

Redis Streams provides a lightweight message queue built into Redis. It supports consumer groups for load balancing and allows multiple consumers to read from the same stream.

import { createClient, RedisClientType } from 'redis';
interface OrderEvent {
  orderId: string;
  customerId: string;
  items: Array<{ sku: string; quantity: number }>;
  totalAmount: number;
  timestamp: string;
}
class OrderProducer {
  private client: RedisClientType;
  constructor(redisUrl: string) {
    this.client = createClient({ url: redisUrl });
  }
  async connect(): Promise {
    await this.client.connect();
  }
  async publishOrderPlaced(event: OrderEvent): Promise {
    const messageId = await this.client.xAdd(
      'orders:stream',
      '',
      {
        'orderId': event.orderId,
        'customerId': event.customerId,
        'items': JSON.stringify(event.items),
        'totalAmount': event.totalAmount.toString(),
        'timestamp': event.timestamp
      }
    );
    return messageId;
  }
  async disconnect(): Promise {
    await this.client.quit();
  }
}
class OrderConsumer {
  private client: RedisClientType;
  private consumerGroup: string;
  private consumerName: string;
  private isRunning: boolean = false;
  constructor(
    redisUrl: string,
    consumerGroup: string,
    consumerName: string
  ) {
    this.client = createClient({ url: redisUrl });
    this.consumerGroup = consumerGroup;
    this.consumerName = consumerName;
  }
  async connect(): Promise {
    await this.client.connect();
    
    try {
      await this.client.xGroupCreate('orders:stream', this.consumerGroup, '0', {
        MKSTREAM: true
      });
    } catch (err: any) {
      if (!err.message.includes('BUSYGROUP')) {
        throw err;
      }
    }
  }
  async startProcessing(
    handler: (event: OrderEvent, messageId: string) => Promise
  ): Promise {
    this.isRunning = true;
    
    while (this.isRunning) {
      try {
        const messages = await this.client.xReadGroup(
          this.consumerGroup,
          this.consumerName,
          [{ key: 'orders:stream', id: '>' }],
          { COUNT: 10, BLOCK: 5000 }
        );
        if (!messages) continue;
        for (const stream of messages) {
          for (const message of stream.messages) {
            const event: OrderEvent = {
              orderId: message.message.orderId as string,
              customerId: message.message.customerId as string,
              items: JSON.parse(message.message.items as string),
              totalAmount: parseFloat(message.message.totalAmount as string),
              timestamp: message.message.timestamp as string
            };
            try {
              await handler(event, message.id);
              await this.client.xAck('orders:stream', this.consumerGroup, message.id);
            } catch (err) {
              console.error(Failed to process message ${message.id}:, err);
            }
          }
        }
      } catch (err) {
        console.error('Error reading from stream:', err);
        await new Promise(resolve => setTimeout(resolve, 1000));
      }
    }
  }
  stop(): void {
    this.isRunning = false;
  }
  async disconnect(): Promise {
    await this.client.quit();
  }
}
// Usage example
async function main() {
  const producer = new OrderProducer('redis://localhost:6379');
  await producer.connect();
  const orderId = await producer.publishOrderPlaced({
    orderId: 'ord-2024-001',
    customerId: 'cust-789',
    items: [{ sku: 'SHOE-RED-42', quantity: 1 }],
    totalAmount: 89.99,
    timestamp: new Date().toISOString()
  });
  console.log(Order published with ID: ${orderId});
  await producer.disconnect();
}
if (require.main === module) {
  main().catch(console.error);
}
export { OrderProducer, OrderConsumer, OrderEvent };

The consumer group ensures that each message processes exactly once across all consumers in the group. Redis tracks which consumer owns each pending message.

Job queues with BullMQ

BullMQ builds on Redis to provide job queues with retry logic, job scheduling, and progress tracking. It works well for background processing like image resizing, email sending, or report generation.

import { Queue, Worker, Job } from 'bullmq';
import IORedis from 'ioredis';
interface PaymentJob {
  orderId: string;
  amount: number;
  currency: string;
  paymentMethodId: string;
  idempotencyKey: string;
}
interface PaymentResult {
  success: boolean;
  transactionId?: string;
  error?: string;
}
const connection = new IORedis({
  host: 'localhost',
  port: 6379,
  maxRetriesPerRequest: null
});
const paymentQueue = new Queue('payments', {
  connection,
  defaultJobOptions: {
    attempts: 3,
    backoff: {
      type: 'exponential',
      delay: 1000
    },
    removeOnComplete: 100,
    removeOnFail: 50
  }
});
const paymentWorker = new Worker(
  'payments',
  async (job: Job): Promise => {
    console.log(Processing payment for order ${job.data.orderId}, attempt ${job.attemptsMade + 1});
    try {
      const result = await processPayment(job.data);
      
      await job.updateProgress(100);
      
      return {
        success: true,
        transactionId: result.transactionId
      };
    } catch (error: any) {
      console.error(Payment failed for order ${job.data.orderId}:, error.message);
      throw error;
    }
  },
  { connection }
);
async function processPayment(jobData: PaymentJob): Promise<{ transactionId: string }> {
  await new Promise(resolve => setTimeout(resolve, 500));
  
  if (Math.random() < 0.3) {
    throw new Error('Payment gateway timeout');
  }
  return { transactionId: txn-${Date.now()} };
}
async function schedulePayment(job: PaymentJob): Promise {
  const queuedJob = await paymentQueue.add(
    payment-${job.orderId},
    job,
    {
      jobId: job.idempotencyKey,
      priority: job.amount > 1000 ? 1 : 5
    }
  );
  
  return queuedJob.id;
}
async function getQueueStats() {
  const [waiting, active, completed, failed] = await Promise.all([
    paymentQueue.getWaitingCount(),
    paymentQueue.getActiveCount(),
    paymentQueue.getCompletedCount(),
    paymentQueue.getFailedCount()
  ]);
  return { waiting, active, completed, failed };
}
// Graceful shutdown
process.on('SIGTERM', async () => {
  await paymentWorker.close();
  await paymentQueue.close();
  await connection.quit();
});
export { paymentQueue, paymentWorker, schedulePayment, getQueueStats, PaymentJob };

BullMQ handles retries automatically. When a job fails, it delays the next attempt using exponential backoff. The jobId option with an idempotency key prevents duplicate payments if the same request submits twice.

Event sourcing

Event sourcing stores the state of an entity as a sequence of events rather than a single record. To reconstruct the current state, you replay all events for that entity.

interface DomainEvent {
  type: string;
  aggregateId: string;
  version: number;
  timestamp: string;
  payload: Record;
}
interface Order {
  id: string;
  customerId: string;
  items: Array<{ sku: string; quantity: number; price: number }>;
  status: 'pending' | 'paid' | 'shipped' | 'cancelled';
  totalAmount: number;
  version: number;
}
class OrderAggregate {
  private events: DomainEvent[] = [];
  private state: Order;
  constructor(orderId: string, customerId: string) {
    this.state = {
      id: orderId,
      customerId,
      items: [],
      status: 'pending',
      totalAmount: 0,
      version: 0
    };
  }
  applyEvent(event: DomainEvent): void {
    switch (event.type) {
      case 'OrderItemAdded':
        this.state.items.push(event.payload.item);
        this.state.totalAmount += event.payload.item.price  event.payload.item.quantity;
        break;
      case 'OrderPaid':
        this.state.status = 'paid';
        break;
      case 'OrderShipped':
        this.state.status = 'shipped';
        break;
      case 'OrderCancelled':
        this.state.status = 'cancelled';
        break;
    }
    this.state.version = event.version;
    this.events.push(event);
  }
  addItem(sku: string, quantity: number, price: number): void {
    const event: DomainEvent = {
      type: 'OrderItemAdded',
      aggregateId: this.state.id,
      version: this.state.version + 1,
      timestamp: new Date().toISOString(),
      payload: { item: { sku, quantity, price } }
    };
    this.applyEvent(event);
  }
  pay(): void {
    if (this.state.status !== 'pending') {
      throw new Error(Cannot pay order in ${this.state.status} status);
    }
    
    const event: DomainEvent = {
      type: 'OrderPaid',
      aggregateId: this.state.id,
      version: this.state.version + 1,
      timestamp: new Date().toISOString(),
      payload: { amount: this.state.totalAmount }
    };
    this.applyEvent(event);
  }
  getState(): Order {
    return { ...this.state };
  }
  getUncommittedEvents(): DomainEvent[] {
    return [...this.events];
  }
  static replay(events: DomainEvent[]): OrderAggregate {
    if (events.length === 0) {
      throw new Error('Cannot replay empty event stream');
    }
    
    const firstEvent = events[0];
    const aggregate = new OrderAggregate(
      firstEvent.aggregateId,
      firstEvent.payload.customerId || ''
    );
    
    events
      .sort((a, b) => a.version - b.version)
      .forEach(event => aggregate.applyEvent(event));
    
    aggregate.events = [];
    return aggregate;
  }
}
// Example usage
const order = new OrderAggregate('ord-123', 'cust-456');
order.addItem('SHOE-RED-42', 1, 89.99);
order.addItem('SOCK-BLK-L', 3, 12.50);
order.pay();
console.log('Order state:', order.getState());
console.log('Events to persist:', order.getUncommittedEvents());

Event sourcing provides a complete audit trail. You can see exactly how an order reached its current state by examining the event sequence.

CQRS: Command Query Responsibility Segregation

CQRS separates read and write operations. Commands modify state and emit events. Queries read from optimized read models built from those events.

// Command side
interface Command {
  type: string;
  aggregateId: string;
  payload: Record;
}
class OrderCommandHandler {
  private eventStore: EventStore;
  private eventPublisher: EventPublisher;
  constructor(eventStore: EventStore, eventPublisher: EventPublisher) {
    this.eventStore = eventStore;
    this.eventPublisher = eventPublisher;
  }
  async handle(command: Command): Promise {
    const events = await this.eventStore.getEvents(command.aggregateId);
    const order = events.length > 0 
      ? OrderAggregate.replay(events)
      : new OrderAggregate(command.aggregateId, command.payload.customerId);
    switch (command.type) {
      case 'PlaceOrder':
        for (const item of command.payload.items) {
          order.addItem(item.sku, item.quantity, item.price);
        }
        break;
      case 'PayOrder':
        order.pay();
        break;
    }
    const newEvents = order.getUncommittedEvents();
    await this.eventStore.append(command.aggregateId, newEvents);
    
    for (const event of newEvents) {
      await this.eventPublisher.publish(event);
    }
  }
}
// Query side - read model
interface OrderView {
  id: string;
  customerId: string;
  itemCount: number;
  totalAmount: number;
  status: string;
  lastUpdated: string;
}
class OrderQueryHandler {
  private readDatabase: Map = new Map();
  handleEvent(event: DomainEvent): void {
    switch (event.type) {
      case 'OrderItemAdded': {
        const view = this.readDatabase.get(event.aggregateId) || {
          id: event.aggregateId,
          customerId: '',
          itemCount: 0,
          totalAmount: 0,
          status: 'pending',
          lastUpdated: event.timestamp
        };
        view.itemCount += event.payload.item.quantity;
        view.totalAmount += event.payload.item.price  event.payload.item.quantity;
        view.lastUpdated = event.timestamp;
        this.readDatabase.set(event.aggregateId, view);
        break;
      }
      case 'OrderPaid': {
        const view = this.readDatabase.get(event.aggregateId);
        if (view) {
          view.status = 'paid';
          view.lastUpdated = event.timestamp;
        }
        break;
      }
    }
  }
  getOrder(orderId: string): OrderView | undefined {
    return this.readDatabase.get(orderId);
  }
  getOrdersByCustomer(customerId: string): OrderView[] {
    return Array.from(this.readDatabase.values())
      .filter(o => o.customerId === customerId);
  }
}

The command side validates business rules. The query side optimizes for read performance, potentially using a different database entirely.

Saga pattern for distributed transactions

A saga coordinates multiple services to complete a business transaction. If one step fails, the saga executes compensating actions to undo previous steps.

interface SagaStep {
  name: string;
  action: () => Promise;
  compensation?: () => Promise;
}
class OrderSaga {
  private steps: SagaStep[] = [];
  private completedSteps: string[] = [];
  private failed: boolean = false;
  constructor(private orderId: string) {}
  addStep(step: SagaStep): this {
    this.steps.push(step);
    return this;
  }
  async execute(): Promise<{ success: boolean; error?: string }> {
    for (const step of this.steps) {
      try {
        console.log(Executing step: ${step.name});
        await step.action();
        this.completedSteps.push(step.name);
      } catch (error: any) {
        console.error(Step ${step.name} failed:, error.message);
        this.failed = true;
        await this.compensate();
        return { success: false, error: error.message };
      }
    }
    return { success: true };
  }
  private async compensate(): Promise {
    console.log('Starting compensation...');
    
    for (const stepName of this.completedSteps.reverse()) {
      const step = this.steps.find(s => s.name === stepName);
      if (step?.compensation) {
        try {
          console.log(Compensating step: ${step.name});
          await step.compensation();
        } catch (error: any) {
          console.error(Compensation failed for ${step.name}:, error.message);
        }
      }
    }
  }
}
// Usage: Checkout process
async function processCheckout(orderId: string): Promise {
  const saga = new OrderSaga(orderId);
  const inventoryReservationId = inv-${orderId};
  const paymentIntentId = pi-${orderId};
  saga
    .addStep({
      name: 'reserveInventory',
      action: async () => {
        await reserveInventory(orderId, inventoryReservationId);
      },
      compensation: async () => {
        await releaseInventory(inventoryReservationId);
      }
    })
    .addStep({
      name: 'processPayment',
      action: async () => {
        await chargeCustomer(orderId, paymentIntentId);
      },
      compensation: async () => {
        await refundPayment(paymentIntentId);
      }
    })
    .addStep({
      name: 'createShipment',
      action: async () => {
        await createShippingLabel(orderId);
      }
    })
    .addStep({
      name: 'sendConfirmation',
      action: async () => {
        await sendOrderConfirmation(orderId);
      }
    });
  const result = await saga.execute();
  
  if (!result.success) {
    throw new Error(Checkout failed: ${result.error});
  }
}
// Mock service functions
async function reserveInventory(orderId: string, reservationId: string): Promise {
  console.log(Reserved inventory for ${orderId});
}
async function releaseInventory(reservationId: string): Promise {
  console.log(Released inventory reservation ${reservationId});
}
async function chargeCustomer(orderId: string, intentId: string): Promise {
  if (Math.random() < 0.3) {
    throw new Error('Payment declined');
  }
  console.log(Charged customer for ${orderId});
}
async function refundPayment(intentId: string): Promise {
  console.log(Refunded payment ${intentId});
}
async function createShippingLabel(orderId: string): Promise {
  console.log(Created shipping label for ${orderId});
}
async function sendOrderConfirmation(orderId: string): Promise {
  console.log(Sent confirmation for ${orderId});
}
export { OrderSaga, processCheckout };

The saga pattern avoids distributed locks. Each step completes independently, and compensations handle failures.

Dead letter queues

When a message fails processing repeatedly, it moves to a dead letter queue (DLQ) for manual investigation. This prevents poison messages from blocking the entire queue.

class DeadLetterQueue {
  private dlq: Queue;
  private mainQueue: Queue;
  constructor(connection: any) {
    this.mainQueue = new Queue('main-queue', { connection });
    this.dlq = new Queue('main-queue-dlq', { connection });
  }
  async sendToDLQ(
    job: Job,
    error: Error,
    maxRetries: number = 3
  ): Promise {
    await this.dlq.add('failed-job', {
      originalJob: job.data,
      originalJobId: job.id,
      error: {
        message: error.message,
        stack: error.stack,
        name: error.name
      },
      failedAt: new Date().toISOString(),
      attemptsMade: job.attemptsMade,
      maxRetries
    }, {
      jobId: dlq-${job.id}
    });
    console.error(Job ${job.id} moved to DLQ after ${job.attemptsMade} attempts);
  }
  async retryFromDLQ(jobId: string): Promise {
    const job = await this.dlq.getJob(jobId);
    if (!job) {
      throw new Error(Job ${jobId} not found in DLQ);
    }
    await this.mainQueue.add('retried-job', job.data.originalJob, {
      jobId: job.data.originalJobId
    });
    await job.remove();
    console.log(Retried job ${jobId} from DLQ);
  }
  async getDLQStats(): Promise<{
    count: number;
    oldestFailure: string | null;
    errorTypes: Record;
  }> {
    const jobs = await this.dlq.getJobs(['waiting', 'delayed']);
    
    const errorTypes: Record = {};
    let oldestFailure: string | null = null;
    for (const job of jobs) {
      const errorName = job.data.error.name || 'Unknown';
      errorTypes[errorName] = (errorTypes[errorName] || 0) + 1;
      if (!oldestFailure || job.data.failedAt < oldestFailure) {
        oldestFailure = job.data.failedAt;
      }
    }
    return {
      count: jobs.length,
      oldestFailure,
      errorTypes
    };
  }
}

Monitor your DLQ closely. A growing DLQ indicates systemic problems that need immediate attention.

Idempotency

Idempotent operations produce the same result when called multiple times. This prevents duplicate charges, double shipments, or inconsistent state when retries occur.

class IdempotencyHandler {
  private store: Map = new Map();
  private readonly TTL_MS = 24  60  60  1000; // 24 hours
  async execute(
    key: string,
    operation: () => Promise
  ): Promise {
    const cached = this.store.get(key);
    
    if (cached && cached.expiresAt > Date.now()) {
      console.log(Returning cached result for ${key});
      return cached.response;
    }
    const result = await operation();
    
    this.store.set(key, {
      response: result,
      expiresAt: Date.now() + this.TTL_MS
    });
    return result;
  }
  generateKey(...components: string[]): string {
    return components.join(':');
  }
}
// Usage in payment processing
async function processPaymentWithIdempotency(
  orderId: string,
  amount: number,
  idempotencyHandler: IdempotencyHandler
): Promise<{ transactionId: string }> {
  const key = idempotencyHandler.generateKey('payment', orderId, amount.toString());
  
  return idempotencyHandler.execute(key, async () => {
    const transactionId = txn-${Date.now()};
    
    await chargePaymentGateway(orderId, amount);
    
    return { transactionId };
  });
}
async function chargePaymentGateway(orderId: string, amount: number): Promise {
  console.log(Charging ${amount} for order ${orderId});
}

Include idempotency keys in all API calls to external services. Store processed keys in Redis or your database with appropriate TTL values.

Choosing your message broker

| Feature | Redis Streams | RabbitMQ | Kafka | BullMQ | |---------|---------------|----------|-------|--------| | Message durability | Yes | Yes | Yes | Yes (via Redis) | | Consumer groups | Yes | Yes | Yes | N/A (job queue) | | Message ordering | Per stream | Per queue | Per partition | Per queue | | At-least-once delivery | Yes | Yes | Yes | Yes | | Exactly-once processing | With XACK | With manual ack | With transactions | With job IDs | | Scheduled messages | No | With plugin | No | Yes | | Retry logic | Manual | Manual | Manual | Built-in | | Dead letter queue | Manual | Built-in | Manual | Built-in | | Best for | Simple queues, existing Redis | Complex routing, AMQP | High throughput logs | Background jobs |

Consider your existing infrastructure when choosing. Redis Streams integrates easily if you already use Redis. Kafka suits high-throughput event streaming. BullMQ excels at job processing with retries.

Lessons learned

  • Start with simple message queues before implementing full event sourcing. The complexity of event sourcing is only justified when you need audit trails or temporal queries.

  • Always implement idempotency for any operation with side effects. Network timeouts and retries will cause duplicate processing.

  • Monitor your dead letter queue as a critical metric. Set up alerts when the DLQ grows beyond a threshold.

  • Design compensations before implementing sagas. Know how to undo each step before you need to use it in production.

  • Separate read and write models gradually. You do not need full CQRS on day one. Start by optimizing read queries with materialized views.

    • Actionable takeaways

  • Audit your current retry logic — Ensure all external API calls use idempotency keys and implement exponential backoff with jitter.

  • Set up a dead letter queue for every message queue in production. Monitor it daily and establish a runbook for retrying failed messages.

  • Implement the outbox pattern — Store events in a database table within the same transaction as your business data, then publish asynchronously to ensure consistency.

  • Start with one bounded context when adopting event sourcing. Choose a domain where audit trails provide clear value, like financial transactions or order processing.

  • Measure end-to-end latency — Track the time from event publication to processing completion. Set SLOs for each consumer based on business requirements.
