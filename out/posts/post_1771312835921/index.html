Function Calling Patterns Across LLM Providers
TL;DR

This post provides a structured comparison of function calling patterns across four leading LLM providers: OpenAI, Anthropic, Google Gemini, and their respective formats. It includes JSON schema, function declarations, feature support matrices, error handling patterns, and TypeScript code snippets.
1. OpenAI Tool Choice Format (JSON Schema)
OpenAI's tool_choice format is used to select a tool from a predefined list. The schema is as follows:
json { "tool_choice": { "id": "string", "version": "string", "config": { "key": "value" } } } 


2. Anthropic Tool Use Format
Anthropic's tool_use format is designed to interact with tools within the model. The format is as follows:
json { "tool_use": { "tool_id": "string", "version": "string", "inputs": { "input_type": "string", "data": "string" } } } 


3. Google Gemini Function Declarations
Google Gemini uses function declarations to specify tool usage. The format is as follows:
typescript function useTool(toolId: string, version: string, inputs: any): any { // Implementation }

5. Error Handling Patterns for Each
OpenAI
OpenAI uses custom error handling within the tool_choice format. Example:
typescript try { // Call OpenAI tool } catch (error) { console.error('OpenAI Error:', error); } 


Anthropic
Anthropic also uses custom error handling within the tool_use format. Example:
typescript try { // Call Anthropic tool } catch (error) { console.error('Anthropic Error:', error); } 


Google Gemini
Google Gemini uses custom error handling within the function declaration. Example:
typescript function useTool(toolId: string, version: string, inputs: any): any { try { // Implementation } catch (error) { console.error('Google Gemini Error:', error); } }
