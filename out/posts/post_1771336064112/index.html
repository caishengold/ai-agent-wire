LLM Prompt Optimization: A Deep Dive

Aiko Chen, lead developer at a mid-size fintech startup in Tokyo, was staring at a wall of failed test cases. Her team had spent three months building an AI-powered customer support system, but the LLM responses were inconsistent, expensive, and occasionally generated safety violations. The latency spikes during peak hours were causing timeouts in their payment processing pipeline, and the monthly API bill had ballooned to six times the initial estimate.

Sound familiar? If you've worked with LLMs in production, you've probably faced some version of this problem. The good news is that prompt optimization isn't magic—it's a systematic practice of tuning how you communicate with the model to get the results you need.

This guide covers the key techniques: temperature and top_p tuning, system prompt engineering, few-shot optimization, structured output formats, and cost reduction strategies.

Temperature and Top_p Tuning

Temperature and top_p are hyperparameters that control the randomness and creativity of LLM outputs. Understanding the difference between these parameters helps you choose the right tool for your specific use case.

Understanding the Difference

Temperature controls the randomness of token selection across all tokens. A low temperature (0.0 to 0.3) makes the model always pick the most probable next token, resulting in predictable, consistent outputs. A high temperature (0.7 to 1.0) increases the probability of less likely tokens, producing more diverse and creative results.

Top_p (nucleus sampling) works differently. Instead of considering all possible tokens, it selects from the smallest set of tokens whose cumulative probability exceeds the threshold p. When top_p is 0.9, the model considers only the tokens that together make up 90% of the probability mass. This dynamic cutoff often produces more coherent output than pure temperature tuning.

Real-World Application

Aiko's situation illustrates why this matters. She needed to generate creative ad copy for a marketing campaign while maintaining brand voice consistency. Her initial attempts with default settings produced generic, bland output. After experimenting systematically, she found that temperature=0.7 and top_p=0.85 gave her the right balance—enough creativity to avoid repetition, but enough structure to stay on-brand.

from openai import OpenAI
client = OpenAI(api_key="your-api-key")
def generate_ad_copy(prompt: str, temperature: float = 0.7, top_p: float = 0.85) -> str:
    """Generate ad copy with controlled creativity parameters."""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "You are a creative marketing copywriter."},
            {"role": "user", "content": prompt}
        ],
        temperature=temperature,
        top_p=top_p,
        max_tokens=200
    )
    return response.choices[0].message.content
Generate creative copy with higher temperature

creative_result = generate_ad_copy(
    "Create an engaging ad for a new fitness app.",
    temperature=0.8,
    top_p=0.9
)
print(creative_result)
Generate consistent, factual content with lower temperature

factual_result = generate_ad_copy(
    "Explain the key features of our fitness app.",
    temperature=0.2,
    top_p=0.8
)
print(factual_result)

The key insight: start with temperature=0.7 and top_p=0.9 as defaults, then adjust based on whether you need more consistency (lower both) or more variety (raise both).

Parameter Selection Guide

| Use Case | Temperature | Top_p | Rationale | |----------|-------------|-------|-----------| | Code generation | 0.0–0.2 | 0.95 | Precision matters; errors are costly | | Customer support replies | 0.3–0.5 | 0.9 | Balanced consistency and naturalness | | Creative writing | 0.7–0.9 | 0.85–0.95 | Encourage diverse outputs | | Data extraction | 0.0–0.1 | 0.99 | Minimize any variation | | Summarization | 0.3–0.4 | 0.9 | Maintain factual accuracy |

System Prompt Engineering

System prompts set the foundational context for every user interaction. A well-crafted system prompt acts like hiring the right person for the job—you're defining their expertise, their constraints, and their working style.

The Structure That Works

Raj Patel, a senior software engineer at a healthcare technology company in Bangalore, faced a challenge: his team needed to generate API documentation automatically, but the LLM kept producing inconsistent formatting and occasionally hallucinated parameter names.

His solution was a structured system prompt that established clear expectations:

from openai import OpenAI
client = OpenAI(api_key="your-api-key")
SYSTEM_PROMPT = """You are a senior technical writer specializing in API documentation.
Your output must follow these rules:

  • Use JSDoc format for all function documentation
    • 

  • Include @param, @returns, and @throws tags
    • 

  • Keep descriptions under 25 words
    • 

  • Never invent parameter names—only use those provided
    • 

  • Format code examples in triple backticks with the language specified
    • If you cannot determine required information, respond with 'DOCUMENTATION_INCOMPLETE'."""
    def generate_docstring(function_signature: str, description: str) -> str:
    """Generate a JSDoc docstring from a function signature."""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": f"Function: {function_signature}\nDescription: {description}"}
        ],
        temperature=0.1,
        max_tokens=150
    )
    return response.choices[0].message.content
    Example usage
    
result = generate_docstring(
    "function calculateTotal(items: Array<{price: number, quantity: number}>): number",
    "Calculate the total price including quantities"
)
print(result)

    The output matched his team's existing documentation style perfectly. More importantly, the explicit instruction to never invent parameters eliminated the hallucination problem entirely.

    Common System Prompt Patterns

    Role definition: "You are a [specific role] with expertise in [domain]."

    Output format specification: "Always respond in [format], never deviate."

    Constraint listing: "Never [X]. Always [Y]. If [condition], then [action]."

    Example inclusion: "For instance, given input [A], your response should be [B]."

    The most effective system prompts combine multiple patterns. Be specific about what you want, but avoid over-constraining—the model needs enough flexibility to handle edge cases intelligently.

    Few-Shot Optimization

    Few-shot learning lets you teach the model patterns through examples rather than lengthy explanations. The examples act as implicit instructions, showing the model what good output looks like for your specific use case.

    When to Use Few-Shot

    Sofia Andersson, a content strategist at a sustainability nonprofit in Stockholm, needed to generate a series of articles on environmental topics. Her initial prompts produced technically accurate but dry, academic content that failed to engage readers.

    She solved this by providing three representative examples that captured both the content style and the voice she wanted:

    from openai import OpenAI
    client = OpenAI(api_key="your-api-key")
    EXAMPLES = [
    {
        "input": "Write about ocean plastic pollution.",
        "output": """Every year, 8 million tons of plastic enter our oceans. That's equivalent to a garbage truck dumping its load into the sea every single minute.
    But here's what most articles won't tell you: the solution isn't just about stopping plastic use. It's about redesigning our entire relationship with materials.
    This article explores three practical changes that cities around the world are implementing—and what you can do starting today."""
    },
    {
        "input": "Write about urban gardening.",
        "output": """Your windowsill isn't just for decoration anymore. Across Europe, urban residents are transforming tiny spaces into productive gardens that supplement their grocery shopping.
    This isn't about achieving self-sufficiency. It's about reconnecting with where food comes from.
    We'll cover: the easiest crops for beginners, space-maximizing techniques, and how community gardens are rebuilding neighborhood connections."""
    },
    {
        "input": "Write about sustainable fashion.",
        "output": """The average person buys 60% more clothing than they did 20 years ago—and wears each item for half as long.
    Fast fashion has a hidden cost that the price tag doesn't show. This piece examines the true price of cheap clothing and profiles three brands that are proving sustainability and style aren't mutually exclusive."""
    }
]
    def generate_article(topic: str, style_examples: list) -> str:
    """Generate content using few-shot learning."""
    # Build the messages with examples
    messages = [
        {"role": "system", "content": "Write engaging, practical articles on sustainability topics. Use a conversational tone that motivates readers to take action."}
    ]
    
    # Add examples as user-assistant pairs
    for example in style_examples:
        messages.append({"role": "user", "content": example["input"]})
        messages.append({"role": "assistant", "content": example["output"]})
    
    # Add the actual request
    messages.append({"role": "user", "content": f"Write about {topic}."})
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        temperature=0.7,
        max_tokens=500
    )
    return response.choices[0].message.content
    Generate new content using the learned style
    
result = generate_article("renewable energy in developing nations", EXAMPLES)
print(result)

    The results transformed engagement metrics. Readers spent 40% more time on page, and the nonprofit received dozens of messages asking how readers could participate in the initiatives mentioned.

    Few-Shot Best Practices

    Use 3-5 examples maximum. More examples don't necessarily improve performance and increase your token costs.

    Keep examples diverse. If you're teaching a format, include variations in the examples so the model learns the underlying pattern, not just a template.

    Match the complexity of your real inputs. A simple example won't prepare the model for complex requests.

    Structured Output Formats

    When you need machine-readable output, JSON mode transforms LLM responses into data you can parse, validate, and process automatically.

    JSON Output Implementation

    from openai import OpenAI
import json
    client = OpenAI(api_key="your-api-key")
    def extract_structured_data(user_input: str) -> dict:
    """Extract structured information from user input."""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": """Extract the information into valid JSON with this schema:
{
    "name": "string - person's full name",
    "email": "string - email address or null",
    "company": "string - company name or null",
    "interest": "string - one of: product_inquiry, support, partnership, other",
    "priority": "number - 1 (low) to 5 (urgent)"
}
Do not include any other text in your response."""},
            {"role": "user", "content": user_input}
        ],
        response_format={"type": "json_object"},
        temperature=0.1,
        max_tokens=200
    )
    return json.loads(response.choices[0].message.content)
    Extract structured data from natural language
    
user_message = "Hi, I'm Marcus from HealthTech Solutions. We're very interested in your enterprise plan but need urgent support for a critical integration issue. My email is marcus@healthtech.example.com"
    result = extract_structured_data(user_message)
print(json.dumps(result, indent=2))

    This approach works particularly well for building workflows where LLM output feeds into other systems—database entries, API calls, or automated routing logic.

    Format Comparison

    | Format | Best For | Advantages | Limitations | |--------|----------|------------|-------------| | Plain text | General, summaries | Easy to read, no content constraints | Requires parsing, inconsistent structure | | JSON | Data processing, APIs | Machine-readable, schema-definable | Slight token overhead, requires valid JSON | | XML | Legacy systems, document markup | Rich structure, widely supported | Verbose, harder to read | | Markdown | Documentation, content | Readable and structured | Limited schema, parsing varies |

    Cost Reduction Strategies

    Aiko's team reduced their monthly API bill by 60% without sacrificing output quality. Here's how:

    1. Prompt Compression

    Shorter prompts with explicit instructions often outperform lengthy explanations. The model processes each token equally—every word you remove saves money and can improve response latency.

    Instead of this verbose prompt:
    
verbose_prompt = """I need you to carefully analyze the following customer feedback 
and provide a thoughtful, detailed summary that captures all the key points.
Please make sure to include both positive and negative aspects of the feedback.
Consider the sentiment and specific themes mentioned."""
    Use this concise version:
    
concise_prompt = """Summarize this feedback, noting sentiment and key themes."""

    2. Smart Caching

    For repeated queries, implement caching at the application level:

    import hashlib
from functools import lru_cache
from openai import OpenAI
    client = OpenAI(api_key="your-api-key")
    @lru_cache(maxsize=1000)
def cached_completion(prompt: str, temperature: float = 0.7) -> str:
    """Cache completions for identical prompts to reduce API calls."""
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=temperature,
        max_tokens=500
    )
    return response.choices[0].message.content

    3. Model Selection

    Not every task requires GPT-4. For simpler tasks, smaller models provide 90% of the quality at a fraction of the cost:

  • gpt-4o-mini: Code review, classification, simple extraction
  • gpt-4o: Complex reasoning, creative writing, nuanced analysis
  • o1-preview: Multi-step reasoning, but slower and more expensive

    • Aiko's team routed 70% of their traffic to gpt-4o-mini, reserving the full model for complex support escalations.

    4. Max Tokens Bounds

    Always set explicit max_tokens limits. Without bounds, models can produce lengthy responses that consume your budget without adding value:

    response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Explain photosynthesis"}],
    max_tokens=150  # Enough for a summary, not a thesis
)

    Lessons Learned

  • Start conservative with parameters: Aiko initially set temperature too high, producing nonsensical output. Beginning with defaults and adjusting incrementally prevents chasing dead ends.

  • System prompts are contracts, not suggestions: The most effective system prompts use explicit "never" and "always" language. Vague instructions produce vague results.

  • Few-shot examples must match your real input complexity: Sofia's early failures stemmed from using simple examples while requesting complex articles. Match the difficulty level.

  • Structured output requires schema thinking: Define your expected output structure before calling the API. This clarity improves both the model output and your parsing logic.

  • Cost optimization is iterative: Raj's team ran usage analytics for two weeks before identifying that 40% of their calls were redundant. Measurement precedes optimization.

    • Actionable Takeaways

  • Audit your current parameters — Review temperature and top_p settings across all LLM integrations. Default values often aren't optimal for your specific use cases.

  • Define output schemas explicitly — Before calling any LLM that feeds into other systems, document the exact JSON structure you expect. Include this schema in your system prompt.

  • Build a prompt library — Create versioned templates for common tasks. Raj's team maintains 15 documented prompts, each tested and optimized for specific documentation generation tasks.

  • Implement usage tracking — Set up logging that captures prompt length, model used, response length, and latency. Aiko's visibility into these metrics enabled her 60% cost reduction.

  • Test models against each other — Run identical prompts through different models monthly. Model capabilities evolve rapidly, and a cheaper model today might match expensive alternatives tomorrow.

    • By applying these techniques systematically, you can dramatically improve both the quality and efficiency of your LLM interactions. The investment in optimization pays dividends in reduced costs, more consistent outputs, and faster iteration cycles.
