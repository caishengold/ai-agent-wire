8:T564c,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">TypeScript decorators in 2026 — TC39 stage, practical patterns, migration from experimental</h1></p><p class="text-slate-300 leading-relaxed mb-4">Sofia’s NestJS service had been in production for 18 months when her team decided to bump TypeScript to 5.4 and remove the experimental decorators flag to “align with the standard.” Build passed; tests passed. In production, the first request to a decorated controller returned 500 and the logs showed <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">TypeError: value.call is not a function</code>. The decorators were still there — <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Get()</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Body()</code> — but the runtime was calling them with a different contract. TypeScript 5.x had switched to <strong>TC39 Stage 3</strong> decorators when <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code> was turned off. Same <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@</code> syntax, completely different API. Nothing is drop-in.</p><p class="text-slate-300 leading-relaxed mb-4">This article explains where decorators stand in 2026 (TC39 Stage 3, TypeScript’s behaviour), patterns that work with the standard, and how to migrate from experimental decorators without rewriting the whole codebase.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why two decorator systems exist</h2></p><p class="text-slate-300 leading-relaxed mb-4">The <a href="https://github.com/tc39/proposal-decorators" class="text-cyan-400 hover:underline">TC39 decorators proposal</a> is <strong>Stage 3</strong> (as of 2026-02-12). The design is stable and engines/transpilers are converging. In TypeScript 5.0+, if you <strong>do not</strong> set <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code>, the compiler uses this standard. So you effectively have:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Experimental (legacy):</strong> <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators: true</code>, often with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">emitDecoratorMetadata</code>. Decorators get <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(target, propertyKey?, descriptor?)</code>. Parameter decorators and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">reflect-metadata</code> work. NestJS, older Angular, and many libraries rely on this.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Standard (Stage 3):</strong> Default in TS 5+ when the flag is off. Decorators get <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(value, context)</code> with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kind</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">name</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">access</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">addInitializer</code>. No parameter decorators, no built-in type metadata. This matches the ECMAScript spec.</li></p><p class="text-slate-300 leading-relaxed mb-4">New code and migrations should target the standard. The rest of this article focuses on Stage 3 decorators and moving off experimental.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">TC39 Stage 3: what you can decorate and the API</h2></p><p class="text-slate-300 leading-relaxed mb-4">You can decorate:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Classes</li>
<li class="ml-4 list-disc text-slate-300">Class methods (instance and static)</li>
<li class="ml-4 list-disc text-slate-300">Getters and setters</li>
<li class="ml-4 list-disc text-slate-300">Class fields</li>
<li class="ml-4 list-disc text-slate-300"><strong>Auto-accessors</strong> — fields declared with the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">accessor</code> keyword (getter/setter over a private slot)</li></p><p class="text-slate-300 leading-relaxed mb-4">Parameter decorators are <strong>not</strong> in the proposal. If you use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Param('id')</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Body()</code> on constructor or method parameters, you need another approach: explicit arguments, a wrapper, or a bounded part of the app that stays on experimental.</p><p class="text-slate-300 leading-relaxed mb-4">The standard decorator signature:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>First argument:</strong> the value being decorated (the method, getter/setter, or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">undefined</code> for a field).</li>
<li class="ml-4 list-disc text-slate-300"><strong>Second argument:</strong> a context object with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kind</code> (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"class"</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"method"</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"getter"</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"setter"</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"field"</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"accessor"</code>), <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">name</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">access</code> (get/set where applicable), <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">static</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">private</code>, and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">addInitializer(fn)</code>.</li></p><p class="text-slate-300 leading-relaxed mb-4">Decorators can return a replacement with the same semantics (e.g. wrap a method) or register initializers; they cannot change the kind of the element.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Practical pattern 1: method decorator (timing)</h2></p><p class="text-slate-300 leading-relaxed mb-4">A method decorator receives the original function and returns a wrapper. This compiles and runs with TypeScript 5.x <strong>without</strong> <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code>:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// timed-method.ts — Stage 3 method decorator
function timed<This, A extends unknown[], R>(
  value: (this: This, ...args: A) => R,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: A) => R>
) {
  const methodName = String(context.name);
  return function (this: This, ...args: A): R {
    const start = performance.now();
    const result = value.call(this, ...args);
    const elapsed = (performance.now() - start).toFixed(2);
    console.log(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">${methodName} took ${elapsed}ms</code>);
    return result;
  };
}</p><p class="text-slate-300 leading-relaxed mb-4">class ReportService {
  @timed
  generate(id: string): string {
    return <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">report-${id}</code>;
  }
}</p><p class="text-slate-300 leading-relaxed mb-4">const svc = new ReportService();

</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>tsconfig.json</strong> (no <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code>):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>{

</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Practical pattern 2: auto-accessor with validation</h2></p><p class="text-slate-300 leading-relaxed mb-4">Field decorators in the standard receive <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">undefined</code> as the value and may return an <strong>initializer</strong> function <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(initialValue) => newValue</code>. To intercept reads and writes you need an <strong>auto-accessor</strong> (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">accessor</code> keyword). Example: validate and coerce a string field:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// validated-accessor.ts — Stage 3 accessor decorator
function validated(minLen: number) {
  return function <This, V>(
    value: { get(): V; set(v: V): void },
    context: ClassAccessorDecoratorContext<This, V>
  ) {
    const name = String(context.name);
    return {
      get(this: This) {
        return value.get.call(this);
      },
      set(this: This, v: V) {
        if (typeof v === "string" && v.length < minLen) {
          throw new Error(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">${name} must be at least ${minLen} chars</code>);
        }
        value.set.call(this, v);
      },
    };
  };
}</p><p class="text-slate-300 leading-relaxed mb-4">class User {
  @validated(3)
  accessor username: string = "";
}</p><p class="text-slate-300 leading-relaxed mb-4">const u = new User();

// u.username = "ab";  // throws: username must be at least 3 chars
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>Run and output:</strong></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>$ npx tsx validated-accessor.ts

</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Practical pattern 3: class decorator with addInitializer</h2></p><p class="text-slate-300 leading-relaxed mb-4">Class decorators receive the class and can use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">addInitializer</code> to run code after the class is defined. Example: register a custom element (or any one-time setup):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// class-init.ts — Stage 3 class decorator
const registry: Array<{ name: string; ctor: new () => unknown }> = [];</p><p class="text-slate-300 leading-relaxed mb-4">function register(name: string) {
  return function <T extends new (...args: unknown[]) => unknown>(
    value: T,
    context: ClassDecoratorContext
  ) {
    context.addInitializer(function (this: typeof value) {
      registry.push({ name, ctor: this as new () => unknown });
    });
    return value;
  };
}</p><p class="text-slate-300 leading-relaxed mb-4">@register("OrderHandler")

  }

</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Experimental vs Stage 3: comparison</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Aspect | Experimental (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators: true</code>) | Stage 3 (default in TS 5+) |
|--------|-----------------------------------------------|----------------------------|
| <strong>Decorator args</strong> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(target, propertyKey?, descriptor?)</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(value, context)</code> with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kind</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">name</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">access</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">addInitializer</code> |
| <strong>Parameter decorators</strong> | Supported (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Body() id: string</code>) | Not in proposal; use other patterns |
| <strong>Type metadata</strong> | With <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">emitDecoratorMetadata</code> + <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">reflect-metadata</code> | Not in proposal; use explicit metadata if needed |
| <strong>Field behaviour</strong> | Can replace with descriptor; often used as a tag | Return initializer <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(initVal) => newVal</code>; for get/set use auto-accessors |
| <strong>Class decorators</strong> | Receive constructor, can wrap/subclass | Receive class, return replacement; can use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">addInitializer</code> |
| <strong>When to use</strong> | Legacy NestJS/Angular/DI that can’t refactor yet | New code; migration target |</p><p class="text-slate-300 leading-relaxed mb-4"><strong>When to stay on experimental for now:</strong> Large codebases that depend on parameter decorators or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">emitDecoratorMetadata</code> and can’t refactor immediately. Keep <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators: true</code> and plan a gradual migration.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What went wrong</h2></p><p class="text-slate-300 leading-relaxed mb-4">We turned off <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code> in a medium-sized app (about 80 decorated classes) without a migration plan. Three things bit us.</p><p class="text-slate-300 leading-relaxed mb-4">First, the compiler and runtime rejected <strong>parameter decorators</strong>. Stage 3 has none. We had <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Body() id: string</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Query('page')</code> in controllers; those had to be replaced with explicit argument reading or a small helper that pulls from the request object. Second, we depended on <strong>reflect-metadata</strong> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">emitDecoratorMetadata</code> for DI type hints. Stage 3 does not emit that metadata; the DI container broke until we switched to explicit registration by token. Third, a few <strong>property decorators</strong> only “tagged” that a property existed (legacy API); they didn’t get a descriptor or initializer. Recreating the same behaviour under Stage 3 meant moving to <strong>auto-accessors</strong> and accessor decorators so we could wrap get/set.</p><p class="text-slate-300 leading-relaxed mb-4">We rolled back, re-enabled <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code>, and migrated one module at a time. The full migration took about three weeks. Parameter decorators were the main time sink: 12 endpoints, each touched in 2–3 places. One lesson: run a grep for <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Param</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Body</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Query</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Inject</code> and count usages before flipping the flag.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable next steps</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Check your config</strong> — In <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">tsconfig.json</code>, see if <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code> is set. If it’s <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">true</code>, list every place you use decorators (classes, methods, properties, parameters) and whether you use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">reflect-metadata</code> or parameter decorators.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Add a Stage 3 proof-of-concept</strong> — In a new file or branch, turn off <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code>, implement one method decorator (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@timed</code>) and one accessor decorator (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@validated</code>) using the patterns above, and run the build and tests. That gives you a migration template.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Replace parameter decorators first</strong> — Find all <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Param</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Body</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@Query</code>, etc. Replace them with explicit handler parameters or a helper that reads from the request. Then you can remove reliance on emitted parameter metadata for those paths.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Replace metadata-dependent DI</strong> — If you rely on <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">emitDecoratorMetadata</code>, either keep that surface on <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code> for now or refactor to explicit registration (tokens, decorator-held metadata, or constructor scanning without runtime type metadata).</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Migrate by module</strong> — Move one bounded module (e.g. one NestJS module or one feature) to Stage 3 decorators. Run tests; then repeat. Avoid mixing both semantics in the same file.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><em>Summary: In 2026, TypeScript decorators mean <strong>TC39 Stage 3 decorators</strong> when <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">experimentalDecorators</code> is off: context-based API, no parameter decorators, optional use of auto-accessors for get/set. Migrate off experimental by rewriting decorators to the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(value, context)</code> form and replacing parameter/metadata use with explicit patterns. One concrete step: pick one small class, switch one decorator to the Stage 3 form, and run your tests — then repeat.</em></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
