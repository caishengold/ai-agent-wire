Error Recovery and Resilience for AI Agents

In the realm of AI agents, the ability to recover from failures is paramount for ensuring uninterrupted operations. This document delves into various strategies and patterns for error recovery and resilience, providing a code-heavy guide for implementing these practices in TypeScript.

1. Retry Strategies

Retry strategies are essential for handling transient failures. Here are three common strategies:

Exponential Backoff

Exponential backoff reduces the frequency of retries over time, which prevents overwhelming the system.

function exponentialBackoff(retries: number, maxDelay: number): number {
  return Math.min(maxDelay, Math.pow(2, retries)  1000);
}

Jitter

Jitter adds randomness to the backoff period to avoid synchronized retries.

function jitteredBackoff(retries: number, baseDelay: number): number {
  const jitter = Math.random()  baseDelay;
  return baseDelay + jitter;
}

Circuit Breaker

The circuit breaker pattern prevents repeated attempts to call a failing service by opening the circuit after a certain number of failures.

class CircuitBreaker {
  private open: boolean = false;
  private failures: number = 0;
  private maxFailures: number = 5;
  private resetTimeout: number = 30000;
  public execute(): boolean {
    if (this.open) {
      return false;
    }
    try {
      // Call the service
      return true;
    } catch (error) {
      this.failures++;
      if (this.failures >= this.maxFailures) {
        this.open = true;
        setTimeout(() => this.open = false, this.resetTimeout);
      }
      return false;
    }
  }
}

2. Fallback Chains

Fallback chains provide alternative paths when the primary method fails.

Primary→Secondary Model

class FallbackChain {
  private primary: () => any;
  private secondary: () => any;
  constructor(primary: () => any, secondary: () => any) {
    this.primary = primary;
    this.secondary = secondary;
  }
  execute(): any {
    try {
      return this.primary();
    } catch (error) {
      return this.secondary();
    }
  }
}

Graceful Degradation

Graceful degradation provides reduced functionality rather than failing entirely.

class GracefulDegradation {
  private primary: () => any;
  private degraded: () => any;
  constructor(primary: () => any, degraded: () => any) {
    this.primary = primary;
    this.degraded = degraded;
  }
  execute(): any {
    try {
      return this.primary();
    } catch (error) {
      return this.degraded();
    }
  }
}

3. Idempotency Patterns

Idempotency ensures that multiple identical requests produce the same result, making retries safe.

Safe to Retry

function safeToRetry(operation: () => any): void {
  try {
    operation();
  } catch (error) {
    console.error('Operation failed, retrying...', error);
    setTimeout(() => safeToRetry(operation), 1000);
  }
}

Deduplication

const executedOperations = new Set();
function deduplicate(operation: () => any): void {
  if (executedOperations.has(operation.toString())) {
    return;
  }
  executedOperations.add(operation.toString());
  try {
    operation();
  } catch (error) {
    console.error('Operation failed, deduplication failed...', error);
  }
}

4. State Recovery

State recovery strategies help agents resume operations after a failure.

Checkpointing

class Checkpoint {
  private state: any;
  constructor(state: any) {
    this.state = state;
  }
  save(): void {
    // Save state to a persistent storage
  }
  load(): any {
    // Load state from persistent storage
    return this.state;
  }
}

Transaction Logs

class TransactionLog {
  private logs: any[] = [];
  log(operation: () => any): void {
    this.logs.push(operation);
  }
  revert(): void {
    for (let i = this.logs.length - 1; i >= 0; i--) {
      const operation = this.logs[i];
      try {
        operation();
      } catch (error) {
        console.error('Reverting transaction...', error);
      }
    }
  }
}

5. Error Classification

Error classification helps in determining whether a failure is transient or permanent.

Retryable vs Permanent

function isRetryableError(error: any): boolean {
  return error instanceof TimeoutError || error.message.includes('transient');
}

Auth vs Logic

function isErrorAuthRelated(error: any): boolean {
  return error instanceof AuthError;
}

Actionable Takeaways

  • Implement retry strategies to handle transient failures.
  • Use fallback chains to provide alternative paths when the primary method fails.
  • Ensure idempotency in operations to safely retry them.
  • Employ state recovery techniques to resume operations after a failure.
  • Classify errors to determine the appropriate recovery actions.
  • Learn from real-world patterns like OpenClaw's circuit breaker and checkpointing.

    • By following these practices, AI agents can achieve greater resilience and reliability in the face of failures.
