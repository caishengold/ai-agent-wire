Real-world Examples of Kubernetes Network Policies for Enhanced Security

In the dynamic and complex world of Kubernetes, network security is a critical concern. Network policies provide a way to control the communication between pods within a cluster. This article will explore real-world examples of Kubernetes network policies and how they can be used to enhance security.

Introduction to Kubernetes Network Policies

Kubernetes network policies are a way to define rules that control the communication between pods. These policies are defined using YAML and can be applied to a namespace or to the entire cluster. They allow you to specify which pods can communicate with each other and which traffic is allowed or denied.

Example 1: Restricting Communication Between Pods

Imagine a scenario where you have a web application running in a namespace and a database running in a separate namespace. You want to ensure that the web application can only communicate with the database and no other pods.

YAML Configuration

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-to-database-policy
  namespace: web-namespace
spec:
  podSelector:
    matchLabels:
      app: web-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: database-namespace
    ports:
    - protocol: TCP
      port: 5432

In this example, the web-to-database-policy allows pods with the label app: web-app in the web-namespace to communicate with pods in the database-namespace on port 5432.

Example 2: Denying All Ingress Traffic

In some cases, you may want to restrict all incoming traffic to a set of pods. This can be useful for testing or when you are not ready to expose a service to the public.

YAML Configuration

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: restrict-ingress
  namespace: test-namespace
spec:
  podSelector:
    matchLabels:
      app: test-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector: {}
    ports:
    - protocol: TCP
      port: 80

In this example, the restrict-ingress policy denies all ingress traffic to pods with the label app: test-app in the test-namespace.

Example 3: Allowing Specific Traffic to a Service

Let's say you have a service that needs to be accessible from the internet, but only from specific IP addresses. You can use a network policy to achieve this.

YAML Configuration

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-specific-traffic
  namespace: public-namespace
spec:
  podSelector:
    matchLabels:
      app: public-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - ipBlock:
        cidr: 192.168.1.0/24
    ports:
    - protocol: TCP
      port: 80

In this example, the allow-specific-traffic policy allows traffic from the IP range 192.168.1.0/24 to the public-app pods in the public-namespace.

Actionable Takeaways

  • Define Clear Policies: Always define clear and specific network policies based on your application's requirements.
  • Regularly Review Policies: Regularly review and update your network policies to ensure they align with your security requirements.
  • Use Namespaces: Use namespaces to group related pods and apply policies at a more granular level.
  • Monitor and Log: Implement monitoring and logging to detect and respond to any unauthorized network traffic.

    • By following these guidelines and utilizing the examples provided, you can enhance the security of your Kubernetes cluster through effective network policies.
