8:T1dd8,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Real-world Examples of Kubernetes Network Policies for Enhanced Security</h1></p><p class="text-slate-300 leading-relaxed mb-4">In the dynamic and complex world of Kubernetes, network security is a critical concern. Network policies provide a way to control the communication between pods within a cluster. This article will explore real-world examples of Kubernetes network policies and how they can be used to enhance security.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction to Kubernetes Network Policies</h2></p><p class="text-slate-300 leading-relaxed mb-4">Kubernetes network policies are a way to define rules that control the communication between pods. These policies are defined using YAML and can be applied to a namespace or to the entire cluster. They allow you to specify which pods can communicate with each other and which traffic is allowed or denied.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Example 1: Restricting Communication Between Pods</h2></p><p class="text-slate-300 leading-relaxed mb-4">Imagine a scenario where you have a web application running in a namespace and a database running in a separate namespace. You want to ensure that the web application can only communicate with the database and no other pods.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">YAML Configuration</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-to-database-policy
  namespace: web-namespace
spec:
  podSelector:
    matchLabels:
      app: web-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: database-namespace
    ports:
    - protocol: TCP
      port: 5432
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this example, the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">web-to-database-policy</code> allows pods with the label <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">app: web-app</code> in the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">web-namespace</code> to communicate with pods in the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">database-namespace</code> on port 5432.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Example 2: Denying All Ingress Traffic</h2></p><p class="text-slate-300 leading-relaxed mb-4">In some cases, you may want to restrict all incoming traffic to a set of pods. This can be useful for testing or when you are not ready to expose a service to the public.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">YAML Configuration</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: restrict-ingress
  namespace: test-namespace
spec:
  podSelector:
    matchLabels:
      app: test-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector: {}
    ports:
    - protocol: TCP
      port: 80
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this example, the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">restrict-ingress</code> policy denies all ingress traffic to pods with the label <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">app: test-app</code> in the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">test-namespace</code>.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Example 3: Allowing Specific Traffic to a Service</h2></p><p class="text-slate-300 leading-relaxed mb-4">Let's say you have a service that needs to be accessible from the internet, but only from specific IP addresses. You can use a network policy to achieve this.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">YAML Configuration</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-specific-traffic
  namespace: public-namespace
spec:
  podSelector:
    matchLabels:
      app: public-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - ipBlock:
        cidr: 192.168.1.0/24
    ports:
    - protocol: TCP
      port: 80
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this example, the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">allow-specific-traffic</code> policy allows traffic from the IP range <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">192.168.1.0/24</code> to the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">public-app</code> pods in the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">public-namespace</code>.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Policy Name | Policy Type | Description | Namespace | Pods Affected |
|-------------|-------------|-------------|-----------|---------------|
| web-to-database-policy | Ingress/Egress | Allows communication between web and database pods | web-namespace | Pods with label <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">app: web-app</code> |
