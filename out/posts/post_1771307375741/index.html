AgentWire: A Practical Guide to Developing MCP Servers

1. Introduction

Raj Patel had a problem. As the backend lead at a healthcare SaaS company, his team needed to integrate multiple AI assistants with their patient records system. Each AI tool—Claude, Cursor, and their custom in-house assistant—required separate API endpoints, different authentication flows, and unique response formats. The maintenance burden was becoming unmanageable.

In early 2025, Raj discovered the Model Context Protocol (MCP). Within two weeks, his team had built a unified MCP server that all three AI clients could communicate with. The result was a 60% reduction in integration code and a single point of control for security policies.

This guide shows you how to build MCP servers that work with Claude, Cursor, and any other MCP-compatible client. You'll set up the TypeScript SDK, implement working servers, and learn the patterns that make production deployments successful.

2. MCP Protocol Overview

The Model Context Protocol is a specification designed to facilitate the exchange of context information between AI agents and their environments. MCP defines three primary resource types:

Resources represent data that can be shared between clients and servers. These include documents, database queries, and API responses that provide context for AI operations.

Tools are executable functions that MCP clients can invoke. A tool might query a database, call an external API, or perform calculations. The protocol includes a validator to ensure tools follow the correct specification.

Prompts are templated messages that clients can request from servers. Servers can expose common prompt patterns that clients use to structure their requests.

The protocol operates over HTTP, typically on port 3000, using JSON-based request and response formats. Understanding these three components is essential before you start building.

3. TypeScript SDK Setup with @modelcontextprotocol/sdk

The official TypeScript SDK provides the foundation for building MCP servers. Install the package and its dependencies:

// First, initialize a new Node.js project
// npm init -y
// Install the SDK and TypeScript dependencies
// npm install @modelcontextprotocol/sdk
// npm install --save-dev typescript @types/node ts-node
// tsconfig.json configuration
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "lib": ["ES2020"],
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  },
  "include": ["src/*/"],
  "exclude": ["node_modules"]
}

Create a basic server entry point that initializes the MCP SDK:

// src/index.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { SSEServerTransport } from '@modelcontextprotocol/sdk/server/sse.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
const server = new Server(
  {
    name: 'example-mcp-server',
    version: '1.0.0',
  },
  {
    capabilities: {
      tools: {},
    },
  }
);
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: 'example_tool',
        description: 'An example tool that demonstrates MCP tool structure',
        inputSchema: {
          type: 'object',
          properties: {
            message: {
              type: 'string',
              description: 'Message to process',
            },
          },
          required: ['message'],
        },
      },
    ],
  };
});
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;
  if (name === 'example_tool') {
    return {
      content: [
        {
          type: 'text',
          text: Processed: ${args.message},
        },
      ],
    };
  }
  throw new Error(Unknown tool: ${name});
});
export { server };

This server defines a tool handler and registers a single example tool. The SDK handles the protocol complexity, letting you focus on your business logic.

4. Minimal Server Implementation

Three patterns cover most MCP server deployment scenarios. Choose based on your scaling requirements.

Example 1: Basic HTTP Server

For simple deployments or development, use the built-in HTTP server:

// src/server-basic.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { HttpServerServerTransport } from '@modelcontextprotocol/sdk/server/index.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
import  as http from 'http';
const server = new Server(
  { name: 'basic-mcp-server', version: '1.0.0' },
  { capabilities: { tools: {} } }
);
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: 'health_check',
      description: 'Returns server health status',
      inputSchema: { type: 'object', properties: {} },
    },
  ],
}));
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name } = request.params;
  
  if (name === 'health_check') {
    return {
      content: [{ type: 'text', text: 'OK' }],
    };
  }
  throw new Error(Unknown tool: ${name});
});
const transport = new HttpServerServerTransport('/mcp', server);
const serverInstance = http.createServer();
serverInstance.on('request', (req, res) => {
  if (req.url === '/mcp' && req.method === 'POST') {
    transport.handleRequest(req, res, req.body);
  } else {
    res.writeHead(404);
    res.end();
  }
});
serverInstance.listen(3000, () => {
  console.log('MCP server running on port 3000');
});

Example 2: Express Integration

For existing Express applications, integrate MCP within your routing:

// src/server-express.ts
import express from 'express';
import bodyParser from 'body-parser';
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { ExpressServerTransport } from '@modelcontextprotocol/sdk/server/index.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
const app = express();
app.use(bodyParser.json());
const server = new Server(
  { name: 'express-mcp-server', version: '1.0.0' },
  { capabilities: { tools: {} } }
);
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: 'query_database',
      description: 'Execute a read-only database query',
      inputSchema: {
        type: 'object',
        properties: {
          table: { type: 'string', description: 'Table name' },
          limit: { type: 'number', description: 'Maximum rows to return' },
        },
        required: ['table'],
      },
    },
  ],
}));
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;
  if (name === 'query_database') {
    // In production, replace with actual database query
    const mockData = [
      { id: 1, name: 'Sample Record 1' },
      { id: 2, name: 'Sample Record 2' },
    ];
    const result = mockData.slice(0, args.limit || 10);
    
    return {
      content: [{ type: 'text', text: JSON.stringify(result, null, 2) }],
    };
  }
  throw new Error(Unknown tool: ${name});
});
const transport = new ExpressServerTransport('/mcp', server);
app.post('/mcp', (req, res) => transport.handleRequest(req, res));
app.listen(3000, () => {
  console.log('Express MCP server running on port 3000');
});

Example 3: Clustered Server for Production

For production workloads requiring high availability, use clustering:

// src/server-cluster.ts
import cluster from 'cluster';
import os from 'os';
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { HttpServerServerTransport } from '@modelcontextprotocol/sdk/server/index.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
import  as http from 'http';
function createWorkerServer() {
  const server = new Server(
    { name: 'clustered-mcp-server', version: '1.0.0' },
    { capabilities: { tools: {} } }
  );
  server.setRequestHandler(ListToolsRequestSchema, async () => ({
    tools: [
      {
        name: 'process_data',
        description: 'Process data using worker thread',
        inputSchema: {
          type: 'object',
          properties: {
            data: { type: 'string', description: 'Data to process' },
          },
          required: ['data'],
        },
      },
    ],
  }));
  server.setRequestHandler(CallToolRequestSchema, async (request) => {
    const { name, arguments: args } = request.params;
    if (name === 'process_data') {
      // Simulate processing work
      const processed = args.data.toUpperCase();
      return {
        content: [{ type: 'text', text: Processed by worker ${process.pid}: ${processed} }],
      };
    }
    throw new Error(Unknown tool: ${name});
  });
  const transport = new HttpServerServerTransport('/mcp', server);
  const serverInstance = http.createServer();
  serverInstance.on('request', (req, res) => {
    if (req.url === '/mcp' && req.method === 'POST') {
      transport.handleRequest(req, res, req.body);
    } else {
      res.writeHead(404);
      res.end();
    }
  });
  serverInstance.listen(3000, () => {
    console.log(Worker ${process.pid} started on port 3000);
  });
}
if (cluster.isPrimary) {
  const numCPUs = os.cpus().length;
  console.log(Primary ${process.pid} starting ${numCPUs} workers);
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }
  cluster.on('exit', (worker, code, signal) => {
    console.log(Worker ${worker.process.pid} died. Restarting...);
    cluster.fork();
  });
} else {
  createWorkerServer();
}

6. Integration Patterns with Claude, Cursor, and Other MCP Clients

Different AI clients connect to MCP servers with varying authentication and session management approaches.

| Client | Authentication | Session Type | Reconnection Strategy | |--------|---------------|--------------|----------------------| | Claude Desktop | API key header | Persistent | Auto-reconnect on failure | | Cursor | OAuth 2.0 flow | Per-project | Manual restart required | | Claude Code | Token-based | Stateless | Retry with backoff | | Custom Client | Configurable | Configurable | Implement per client |

Claude Desktop Integration

Configure Claude Desktop to connect to your MCP server by adding it to your configuration file:

Cursor Integration

Cursor uses OAuth 2.0. Implement the authorization callback in your server:

// src/server-oauth.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { ExpressServerTransport } from '@modelcontextprotocol/sdk/server/index.js';
import express from 'express';
import crypto from 'crypto';
const app = express();
const clients = new Map();
const server = new Server(
  { name: 'oauth-mcp-server', version: '1.0.0' },
  { capabilities: { tools: {} } }
);
app.get('/oauth/authorize', (req, res) => {
  const { client_id, redirect_uri, response_type } = req.query;
  
  if (!clients.has(client_id as string)) {
    return res.status(400).json({ error: 'invalid_client' });
  }
  
  // In production, render an authorization page
  const authCode = crypto.randomBytes(32).toString('hex');
  res.redirect(${redirect_uri}?code=${authCode});
});
app.post('/oauth/token', express.json(), (req, res) => {
  const { grant_type, code, client_id } = req.body;
  
  if (grant_type !== 'authorization_code') {
    return res.status(400).json({ error: 'unsupported_grant_type' });
  }
  
  // Issue access token
  const accessToken = crypto.randomBytes(32).toString('hex');
  res.json({
    access_token: accessToken,
    token_type: 'Bearer',
    expires_in: 3600,
  });
});
const transport = new ExpressServerTransport('/mcp', server);
app.post('/mcp', (req, res) => transport.handleRequest(req, res));
app.listen(3000, () => {
  console.log('OAuth MCP server running on port 3000');
});

7. Common Pitfalls and Error Patterns

Understanding these issues before you encounter them will save hours of debugging.

Pitfalls

Request Validation — Always validate incoming requests before processing. Malformed requests should return clear error messages, not crash your server.

// Always validate tool arguments
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;
  
  // Validate required arguments
  if (!args || typeof args !== 'object') {
    throw new Error('Invalid arguments: expected object');
  }
  
  // ... proceed with tool execution
});

Asynchronous Operations — MCP requests must complete within reasonable timeframes. Use timeouts and proper async/await patterns.

Resource Management — Close database connections, release file handles, and clean up timers. Unmanaged resources cause memory leaks in long-running servers.

Error Patterns

| Error | Cause | Solution | |-------|-------|----------| | Error: Invalid Request | Malformed JSON or missing required fields | Validate request schema before processing | | Error: Internal Server Error | Uncaught exception in tool handler | Add try/catch and logging to all handlers | | Error: Connection Refused | Server not running or wrong port | Verify server is listening on correct port | | Error: Tool Not Found | Tool name mismatch | Check tool registration matches invocation | | Error: Timeout | Tool execution exceeded limit | Implement chunking or async processing |

8. Lessons Learned

  • Validate all incoming requests at the entry point — it's easier to catch malformed data before it reaches your business logic
  • Use clustering in production from the start — adding it later requires code changes that could break existing integrations
  • Implement comprehensive logging before deployment — when issues arise in production, you'll need detailed traces
  • Design tools with idempotency in mind — clients may retry requests, and duplicate processing causes data inconsistencies
  • Test with real network conditions — local testing doesn't reveal latency issues or connection failures that occur in production

    • 9. Actionable Takeaways

  • Set up the MCP TypeScript SDK — Run npm install @modelcontextprotocol/sdk in your project and configure TypeScript with the settings shown in Section 3
  • Start with the basic HTTP server — Deploy the minimal example from Section 4 to verify your environment before adding complexity
  • Add structured logging — Include request IDs, timestamps, and tool names in all log output for debugging production issues
  • Configure health check tools — Every production server should expose a health_check tool for monitoring systems
  • Plan your authentication strategy — Choose between API keys (simple), OAuth 2.0 (Cursor), or token-based (Claude Code) based on your client requirements
