title: "API Pagination Patterns: Offset, Cursor, and Keyset with SQLite Examples"
date: "2026-02-16"
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">Efficient pagination is crucial for API design, especially when dealing with large datasets. Different pagination patterns offer varying trade-offs in terms of performance, ease of use, and scalability. In this article, we'll compare three common pagination patterns: offset-based, cursor-based, and keyset-based. We'll explore their differences using real-world scenarios and SQLite examples.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Scenario: E-commerce Platform</h2></p><p class="text-slate-300 leading-relaxed mb-4">Let's consider an e-commerce platform where customers can browse and purchase products. Our API endpoint <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">GET /products</code> will return a list of products with pagination. For our examples, we'll assume a product table in an SQLite database.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Offset-based Pagination</h2></p><p class="text-slate-300 leading-relaxed mb-4">Offset-based pagination involves skipping a specified number of records before returning the next set of results. It's simple to implement but can be inefficient for large datasets.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example 1: Offset-based Pagination with SQLite</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- SQL for offset-based pagination
SELECT <em> FROM products ORDER BY id LIMIT 10 OFFSET 20;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this query, we're fetching the next 10 products, skipping the first 20.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example 2: Offset-based Pagination in Python</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import sqlite3</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Connect to the SQLite database</h1>
conn = sqlite3.connect('ecommerce.db')
cursor = conn.cursor()</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Offset-based pagination</h1>
offset = 20
limit = 10
query = f"SELECT </em> FROM products ORDER BY id LIMIT ? OFFSET ?"
cursor.execute(query, (limit, offset))</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Fetch the results</h1>
products = cursor.fetchall()
for product in products:
    print(product)</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Close the connection</h1>
cursor.close()
conn.close()
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Cursor-based Pagination</h2></p><p class="text-slate-300 leading-relaxed mb-4">Cursor-based pagination uses a unique value from the dataset (such as an ID) to determine the next set of results. It's more efficient than offset-based pagination for large datasets and is commonly used with primary keys.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example 1: Cursor-based Pagination with SQLite</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- SQL for cursor-based pagination using the last ID from the previous results
SELECT <em> FROM products WHERE id > 20 ORDER BY id LIMIT 10;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">This query fetches the next 10 products with IDs greater than 20.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example 2: Cursor-based Pagination in Python</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Assume we have a cursor value from the previous results</h1>
last_id = 21</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Cursor-based pagination</h1>
limit = 10
query = "SELECT </em> FROM products WHERE id > ? ORDER BY id LIMIT ?"
cursor.execute(query, (last_id, limit))</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Fetch the results</h1>
products = cursor.fetchall()
for product in products:
    print(product)
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Keyset-based Pagination</h2></p><p class="text-slate-300 leading-relaxed mb-4">Keyset-based pagination uses a combination of values from the dataset (such as a timestamp and a unique identifier) to determine the next set of results. It's highly efficient for large datasets and can also support sorting.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example 1: Keyset-based Pagination with SQLite</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- SQL for keyset-based pagination using a timestamp and ID
SELECT <em> FROM products WHERE (timestamp, id) > (?, ?) ORDER BY timestamp, id LIMIT 10;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this query, we're fetching the next 10 products after the last timestamp and ID from the previous results.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example 2: Keyset-based Pagination in Python</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Assume we have the last timestamp and ID from the previous results</h1>
last_timestamp = '2025-02-16'
last_id = 21</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Keyset-based pagination</h1>
limit = 10
query = "SELECT </em> FROM products WHERE (timestamp, id) > (?, ?) ORDER BY timestamp, id LIMIT ?"
cursor.execute(query, (last_timestamp, last_id, limit))</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Fetch the results</h1>
products = cursor.fetchall()
for product in products:
    print(product)
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Pagination Pattern | Query Complexity | Performance | Efficiency with Large Datasets |
|--------------------|------------------|------------|--------------------------------|
| Offset-based       | Low              | Moderate   | Low                            |
| Cursor-based       | Moderate         | High       | High                           |
| Keyset-based       | High             | Very High  | Very High                      |</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Offset-based pagination is simple but inefficient for large datasets.</li>
<li class="ml-4 list-disc text-slate-300">Cursor-based pagination is more efficient and can handle large datasets well.</li>
<li class="ml-4 list-disc text-slate-300">Keyset-based pagination offers the highest efficiency and performance, especially with sorting.</li>
<li class="ml-4 list-disc text-slate-300">When designing an API, consider the dataset size and whether sorting is required when choosing a pagination pattern.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Understand Use Cases</strong>: Different pagination patterns suit different scenarios. Evaluate your specific use case before selecting a pattern.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Prioritize Performance</strong>: For large datasets, prioritize performance by choosing cursor-based or keyset-based pagination.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Consider Sorting</strong>: If sorting is important for your dataset, use keyset-based pagination.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Test and Iterate</strong>: Test the performance and usability of your chosen pagination pattern under real-world conditions. Iterate based on feedback and data.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Document the Pagination</strong>: Clearly document the pagination pattern used in your API to help developers understand how to implement pagination correctly.</li></p><p class="text-slate-300 leading-relaxed mb-4">By considering these points and understanding the strengths and weaknesses of each pagination pattern, you can design an API that provides a great user experience with efficient pagination.
