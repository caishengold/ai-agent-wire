8:T1af6,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Feature Flags for TypeScript Backends (2026)</h1></p><p class="text-slate-300 leading-relaxed mb-4">Feature flags let you ship code behind a switch: turn features on or off without redeploying. For TypeScript backends, they improve safety (gradual rollouts, kill switches) and flexibility (A/B tests, per-tenant toggles). This post outlines a minimal, type-safe approach you can run in-process or back with a store.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why Use Feature Flags?</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Gradual rollout</strong>: Enable a new API or behavior for a percentage of traffic or a allowlist of tenant IDs.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Kill switch</strong>: If a deployment causes issues, disable the feature and redeploy later instead of rolling back.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Experimentation</strong>: Run A/B tests by branching on a flag and measuring outcomes.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Operational control</strong>: Turn off non-critical features under load without touching code.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">In-Process Flags (Env or Config)</h2></p><p class="text-slate-300 leading-relaxed mb-4">The simplest form is reading flags from environment or config at startup:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const flags = {
  useNewBilling: process.env.FEATURE_NEW_BILLING === 'true',
  enableBetaApi: process.env.FEATURE_BETA_API === 'true',
} as const;</p><p class="text-slate-300 leading-relaxed mb-4">export function isEnabled(name: keyof typeof flags): boolean {
  return Boolean(flags[name]);
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Use at call sites:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>if (isEnabled('useNewBilling')) {
  return await newBillingService.charge(req);
}
return await legacyBilling.charge(req);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Pros: no extra infra, type-safe keys. Cons: changing a flag requires restart or env change.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Type-Safe Flag Keys</h2></p><p class="text-slate-300 leading-relaxed mb-4">Define a single source of truth and derive types:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const FLAG_DEFS = {
  newSearch: { default: false },
  highTrafficMode: { default: false },
} as const;</p><p class="text-slate-300 leading-relaxed mb-4">export type FlagName = keyof typeof FLAG_DEFS;</p><p class="text-slate-300 leading-relaxed mb-4">export function getFlag(name: FlagName): boolean {
  const envKey = <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">FEATURE_${name.toUpperCase().replace(/([A-Z])/g, '_$1').replace(/^_/, '')}</code>;
  const raw = process.env[envKey];
  if (raw === 'true') return true;
  if (raw === 'false') return false;
  return FLAG_DEFS[name].default;
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">This keeps flag names and defaults in one place and avoids typos.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Optional: Remote or DB-Backed Flags</h2></p><p class="text-slate-300 leading-relaxed mb-4">For runtime changes without restart, back flags with a DB or remote config:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const flagCache = new Map<string, { value: boolean; until: number }>();
const TTL_MS = 60_000;</p><p class="text-slate-300 leading-relaxed mb-4">async function fetchFlag(name: FlagName): Promise<boolean> {
  const cached = flagCache.get(name);
  if (cached && cached.until > Date.now()) return cached.value;
  const row = await db.prepare('SELECT enabled FROM feature_flags WHERE name = ?').get(name);
  const value = Boolean(row?.enabled);
  flagCache.set(name, { value, until: Date.now() + TTL_MS });
  return value;
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Use short TTLs so changes propagate quickly; for critical kill switches you can bypass cache.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Best Practices</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Default off</strong>: New features should default to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">false</code> so a misconfiguration doesn’t enable them everywhere.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Scoped checks</strong>: Prefer checking the flag at the boundary (handler or service entry) rather than deep inside libraries.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Remove old code</strong>: Once a feature is fully rolled out, delete the legacy path and the flag to avoid permanent branching.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Audit</strong>: Log when flags are evaluated in production if you need to debug rollout or experiments.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Naming</strong>: Use a consistent prefix (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">FEATURE_</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">flag.</code>) and clear names like <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">newBilling</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">betaApi</code>.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Summary</h2></p><p class="text-slate-300 leading-relaxed mb-4">Feature flags in TypeScript backends can start as env-driven, type-safe in-process toggles and grow to DB- or remote-backed flags with caching. Keep a single definition for names and defaults, use them at boundaries, and plan to remove flags once the feature is the only path.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
