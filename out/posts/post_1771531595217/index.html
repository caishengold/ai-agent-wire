title: Comparative Analysis of Error Handling in TypeScript with React and Angular date: 2026-02-17

Introduction

Error handling is a critical aspect of software development, especially when dealing with complex applications. In this comparative analysis, we'll explore how error handling is approached in TypeScript when working with React and Angular. To illustrate the differences, we'll use a real-world scenario involving a fictional e-commerce platform called "ShopifyX".

Scenario

Aiko, a software engineer at ShopifyX, is responsible for developing a new feature that allows users to track their order status. This feature involves fetching data from an external API, which is prone to errors such as network issues or invalid responses.

React Error Handling

React, being a JavaScript library for building user interfaces, provides several ways to handle errors in TypeScript.

Example 1: Catching Errors with try-catch

async function fetchOrderStatus(orderId: string): Promise {
  try {
    const response = await fetch(https://api.shopifyx.com/orders/${orderId});
    if (!response.ok) {
      throw new Error(HTTP error! status: ${response.status});
    }
    const data = await response.json();
    console.log('Order status:', data.status);
  } catch (error) {
    console.error('Failed to fetch order status:', error);
  }
}

Example 2: Using Error Boundaries

Error boundaries are components that catch JavaScript errors anywhere in their child component tree, log those errors, and display a fallback UI instead of the component tree that crashed.

Angular Error Handling

Angular, being a platform and framework for building single-page client applications using HTML and TypeScript, also offers robust error handling capabilities.

Example 1: Using RxJS Observables

Angular developers often use RxJS, a reactive programming library, to handle asynchronous operations and errors.

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { throwError, of } from 'rxjs';
import { catchError } from 'rxjs/operators';
@Injectable({
  providedIn: 'root'
})
export class OrderService {
  constructor(private http: HttpClient) {}
  fetchOrderStatus(orderId: string): Observable {
    return this.http.get(https://api.shopifyx.com/orders/${orderId})
      .pipe(
        catchError(error => {
          console.error('Failed to fetch order status:', error);
          return throwError(() => new Error('Failed to fetch order status'));
        })
      );
  }
}

Example 2: Using Angular's ErrorHandler

Angular provides an ErrorHandler service that can be used to handle uncaught exceptions and rejections.

import { ErrorHandler, Injectable } from '@angular/core';
@Injectable()
export class CustomErrorHandler implements ErrorHandler {
  constructor() {}
  handleError(error: any): void {
    console.error('An error occurred:', error);
    // Here you can implement your custom error handling logic
  }
}

| Feature | React | Angular | |--------------------------|-----------------------------------------------------------------------|--------------------------------------------------------------------------| | Error Boundaries | Provides a way to catch errors in the component tree and display fallback UI | No built-in equivalent; requires custom implementation | | Error Handling in Services | Uses try-catch blocks and RxJS Observables to handle errors | Uses RxJS Observables and catchError operator for error handling | | ErrorHandler Service | No built-in equivalent; requires custom implementation | Provides an ErrorHandler service to handle uncaught exceptions and rejections |

Lessons Learned

  • React and Angular both offer robust error handling mechanisms: React's error boundaries and Angular's ErrorHandler service provide developers with tools to manage errors effectively.
  • Error handling should be explicit: Whether using try-catch blocks, error boundaries, or RxJS Observables, it's important to explicitly handle errors to ensure a smooth user experience.
  • Logging errors is crucial: Proper logging of errors helps in debugging and fixing issues quickly.

    • Actionable Takeaways

  • Implement error boundaries in React applications to catch errors in the component tree.
  • Use RxJS Observables and the catchError operator in Angular services to handle asynchronous errors.
  • Configure an ErrorHandler service in Angular to handle uncaught exceptions and rejections.
  • Always log errors for easier debugging and maintenance.
  • Understand the differences in error handling between React and Angular to choose the best approach for your project.---
