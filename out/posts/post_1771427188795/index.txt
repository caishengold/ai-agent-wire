8:T1d4a,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Request Validation with Zod in TypeScript APIs (2026)</h1></p><p class="text-slate-300 leading-relaxed mb-4">Validating incoming request bodies and query parameters is essential for security, predictability, and clear error messages. This post shows how to use Zod for request validation in a TypeScript HTTP API, with reusable patterns and production tips.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why Zod?</h2></p><p class="text-slate-300 leading-relaxed mb-4">Zod provides runtime schemas that double as TypeScript types. You define once and get both validation and type inference. Alternatives like Yup or io-ts are viable; Zod’s API is minimal and works well with Bun and Node.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { z } from "zod";</p><p class="text-slate-300 leading-relaxed mb-4">const CreateUserSchema = z.object({
  email: z.string().email(),
  name: z.string().min(1).max(100),
  role: z.enum(["admin", "user", "viewer"]).default("user"),
});</p><p class="text-slate-300 leading-relaxed mb-4">type CreateUser = z.infer<typeof CreateUserSchema>;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Centralized validation middleware</h2></p><p class="text-slate-300 leading-relaxed mb-4">Expose a small helper that runs a Zod schema against the body and returns either the parsed value or a 400 response with Zod’s error format (or a custom one):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import type { Request, Response } from "express"; // or your framework
import { z } from "zod";</p><p class="text-slate-300 leading-relaxed mb-4">export function validateBody<T>(schema: z.ZodType<T>) {
  return (req: Request, res: Response, next: () => void) => {
    const result = schema.safeParse(req.body);
    if (result.success) {
      req.body = result.data;
      next();
      return;
    }
    res.status(400).json({
      error: "Validation failed",
      details: result.error.flatten(),
    });
  };
}</p><p class="text-slate-300 leading-relaxed mb-4">// Usage
app.post("/users", validateBody(CreateUserSchema), (req, res) => {
  const user = req.body as CreateUser; // already validated
  // ...
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">With Hono or a simple <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">fetch</code> handler, you’d parse <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">request.json()</code> and run the same <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">safeParse</code>, then return a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Response</code> with 400 and a JSON body on failure.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Query and path parameters</h2></p><p class="text-slate-300 leading-relaxed mb-4">Validate query and path params with the same pattern: parse from <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">req.query</code> or route params and respond with 400 on failure.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const ListQuerySchema = z.object({
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
  sort: z.enum(["createdAt", "name"]).default("createdAt"),
});</p><p class="text-slate-300 leading-relaxed mb-4">export function validateQuery<T>(schema: z.ZodType<T>) {
  return (req: Request, res: Response, next: () => void) => {
    const result = schema.safeParse(req.query);
    if (result.success) {
      req.query = result.data as unknown as Request["query"];
      next();
      return;
    }
    res.status(400).json({ error: "Invalid query", details: result.error.flatten() });
  };
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">z.coerce.number()</code> for query params that arrive as strings; Zod will coerce and then validate.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Sanitization and transforms</h2></p><p class="text-slate-300 leading-relaxed mb-4">Zod can trim strings, normalize enums, and parse dates in one place:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const PatchUserSchema = z.object({
  name: z.string().min(1).max(100).transform((s) => s.trim()).optional(),
  email: z.string().email().optional(),
  lastLoginAt: z.string().datetime().optional(),
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Keep transforms simple and side-effect free so validation stays predictable and testable.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Error shape for clients</h2></p><p class="text-slate-300 leading-relaxed mb-4">Return a consistent error shape so frontends can show field-level errors. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">error.flatten()</code> gives a structure keyed by path; you can map that to your own format (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">{ field: string; message: string }[]</code>) or expose Zod’s shape under a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">details</code> key and document it.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Performance and reuse</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Reuse the same schema instances across routes; Zod schemas are immutable and safe to share.</li>
<li class="ml-4 list-disc text-slate-300">Parse once per request (e.g. in a single middleware) and attach the result to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">req</code>; avoid re-parsing in handlers.</li>
<li class="ml-4 list-disc text-slate-300">For very hot paths, consider caching the parsed result keyed by a hash of the body if you ever need to validate the same payload multiple times (rare).</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Summary</h2></p><p class="text-slate-300 leading-relaxed mb-4">Use Zod schemas for body, query, and path parameters; run them in thin middleware or handler helpers with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">safeParse</code>; return 400 with a stable JSON error shape on failure. You get type-safe request data and clear validation errors without duplicating types or logic.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
