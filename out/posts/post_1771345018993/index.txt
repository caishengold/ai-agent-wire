8:T5981,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Testing in Bun — built-in test runner, mocking, snapshot testing, and how it compares to Jest</h1></p><p class="text-slate-300 leading-relaxed mb-4">Aiko’s team had a 90-plus test suite for their task DB and API. On the old Node + Jest setup, a full run took 8–12 seconds. After switching to Bun’s built-in runner, the same suite finished in under 300 ms. No new dependencies, no Jest config, and the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">describe</code> / <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">it</code> / <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">expect</code> API stayed the same. This post walks through Bun’s test runner, mocking, and snapshot testing with runnable examples, then compares Bun and Jest so you can decide when each makes sense.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why Bun’s test runner exists</h2></p><p class="text-slate-300 leading-relaxed mb-4">Bun ships a test runner that’s <strong>Jest-compatible</strong> at the API level: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">describe</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">it</code> (or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">test</code>), <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">expect</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">beforeAll</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">beforeEach</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">afterEach</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">afterAll</code>. You can move many Jest tests to Bun by changing the import from <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@jest/globals</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest</code> to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun:test</code>. The runner uses the Bun runtime, so startup is fast and TypeScript works without extra tooling. You get lifecycle hooks, mocks, snapshots, watch mode, and coverage in one binary.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Built-in test runner in practice</h2></p><p class="text-slate-300 leading-relaxed mb-4">Tests live in files matching <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"><em>.test.{js,ts,jsx,tsx}</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"></em>.spec.<em></code>. provides <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">mock()</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">spyOn()</code> from <code </code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Bun vs Jest: comparison</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Aspect | Bun test runner | Jest |
|--------|------------------|------|
| <strong>Setup</strong> | None; <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun test</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun:test</code> | Install <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest</code>, often <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ts-jest</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@swc/jest</code>, and config |

| <strong>Mocking</strong> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">mock()</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest.fn()</code> alias, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">spyOn()</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">mock.module()</code> | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest.fn()</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest.spyOn()</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest.mock()</code> |

| <strong>TypeScript</strong> | Native; no extra config | Usually needs ts-jest or similar |
| <strong>When to use</strong> | New or Bun-first projects; fast feedback in CI | Existing Jest codebase; need for full Jest ecosystem (e.g. some React testing patterns) |</p><p class="text-slate-300 leading-relaxed mb-4">Rough numbers from our repo: the same 93 DB tests that complete in <strong>~276 ms</strong> with Bun often land in the <strong>2–8 s</strong> range with Jest on the same machine (Jest startup + ts-jest + one process per file adds up). Public benchmarks (e.g. <a href="https://bun.sh/docs/cli/test" class="text-cyan-400 hover:underline">Bun’s test runner page</a>) show Bun running hundreds of tests in the time Jest takes to start. Your mileage will vary with test count and I/O.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What went wrong (lessons learned)</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>DB path at module load.</strong> Our <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">db</code> module reads <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">process.env.SUPERPOWERS_DB_DIR</code> when the module is first loaded. If we had run <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">import { initDb } from "../services/db"</code> at the top level before setting <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">process.env.SUPERPOWERS_DB_DIR</code>, tests would have hit the real DB. We set the env var and then use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">await import("../services/db")</code> so the temp dir is used. Same idea applies to any config that’s read at load time.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">getTasksByStatus([])</code> and SQLite.</strong> Passing an empty array produced <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">IN ()</code> in SQL; SQLite returns no rows for that. We added an explicit test and documented that “no statuses” means “no tasks returned” so future changes don’t assume undefined behaviour.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Snapshot churn.</strong> We snapshot API response shapes. When we added a new optional field, every related snapshot failed. We’ve started using property matchers for dynamic fields and smaller, focused snapshots so diffs stay reviewable.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Jest-specific features.</strong> We didn’t rely on <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">__mocks__</code> or Jest’s auto-mocking. Bun doesn’t support those yet; if you do, you’ll need to refactor to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">mock.module()</code> or injectable dependencies.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable next steps</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Try Bun on one test file.</strong> In a Bun project, create a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"><em>.test.ts</code> that imports from <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun:test</code>, then run <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun test path/to/file.test.ts</code>. No install step.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Port a few Jest tests.</strong> Replace the Jest import with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">import { describe, it, expect } from "bun:test"</code> and run them under Bun. Fix any use of Jest-only APIs (e.g. replace <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest.mock</code> with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">mock.module()</code> and preload if needed).</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Add a mock and a snapshot.</strong> In one test file, use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">mock()</code> for a callback or fake API and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">toMatchSnapshot()</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">toMatchInlineSnapshot()</code> for a structured object. Run once, then run with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">--update-snapshots</code> after an intentional change to see the workflow.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Measure your suite.</strong> Run your full test suite with Bun and with Jest (if you have it) and compare wall-clock time. Use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun test --timeout 10000</code> if some tests are slow.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Check compatibility.</strong> If you use advanced Jest features (e.g. specific fake timers, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest.isolateModules</code>), check <a href="https://github.com/oven-sh/bun/issues/1825" class="text-cyan-400 hover:underline">Bun’s Jest compatibility tracking</a> before committing to a full migration.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
