8:T1e2b,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Correlation IDs for Request Tracing in TypeScript APIs</h1></p><p class="text-slate-300 leading-relaxed mb-4">When debugging production issues, the ability to follow a single request across services, queues, and logs is invaluable. <strong>Correlation IDs</strong> (also called request IDs or trace IDs) are a standard way to achieve this: one unique identifier is assigned at the entry point and propagated through every log line and downstream call.</p><p class="text-slate-300 leading-relaxed mb-4">This post shows a minimal, dependency-free way to add correlation IDs in a TypeScript/Bun or Node HTTP stack, and how to use them in structured logs and with external APIs.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why correlation IDs?</h2></p><p class="text-slate-300 leading-relaxed mb-4">Without a shared ID:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Logs from the same request are mixed with others; grep by timestamp is noisy and brittle.</li>
<li class="ml-4 list-disc text-slate-300">You cannot tell which log lines belong to the same user action or job.</li>
<li class="ml-4 list-disc text-slate-300">When calling another service or enqueueing a job, you lose the link back to the original request.</li></p><p class="text-slate-300 leading-relaxed mb-4">With a correlation ID:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Every log line for that request includes the same ID; you filter once and see the full path.</li>
<li class="ml-4 list-disc text-slate-300">You can pass the ID in headers (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">X-Request-ID</code>) to downstream services or include it in job payloads so workers can log the same ID.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Assigning and propagating the ID</h2></p><p class="text-slate-300 leading-relaxed mb-4"><strong>1. Generate or accept an ID at the edge</strong></p><p class="text-slate-300 leading-relaxed mb-4">Use the first incoming header if present (so upstream can set it), otherwise generate a UUID:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { randomUUID } from "crypto";</p><p class="text-slate-300 leading-relaxed mb-4">function getOrCreateRequestId(headers: Headers): string {
  const existing = headers.get("x-request-id") ?? headers.get("x-correlation-id");
  return existing?.trim() || randomUUID();
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>2. Store the ID in AsyncLocalStorage (Node/Bun)</strong></p><p class="text-slate-300 leading-relaxed mb-4">Both Node and Bun support <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">AsyncLocalStorage</code>. Store the ID when you enter the request scope so any code in that async tree can read it without passing parameters:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { AsyncLocalStorage } from "async_hooks";</p><p class="text-slate-300 leading-relaxed mb-4">const requestContext = new AsyncLocalStorage<{ requestId: string }>();</p><p class="text-slate-300 leading-relaxed mb-4">function withRequestId<T>(requestId: string, fn: () => T): T {
  return requestContext.run({ requestId }, fn);
}</p><p class="text-slate-300 leading-relaxed mb-4">function getRequestId(): string | undefined {
  return requestContext.getStore()?.requestId;
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>3. Wire it into your server</strong></p><p class="text-slate-300 leading-relaxed mb-4">In your HTTP server or framework, for each request: get or create the ID, run the handler inside <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">withRequestId</code>, and send the ID back in the response so clients can report it:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// Pseudocode for a generic fetch handler or middleware
serve({
  fetch(req) {
    const requestId = getOrCreateRequestId(req.headers);
    return withRequestId(requestId, () => {
      const res = handleRequest(req);
      res.headers.set("X-Request-ID", requestId);
      return res;
    });
  },
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Using the ID in logs and outbound calls</h2></p><p class="text-slate-300 leading-relaxed mb-4"><strong>Structured logging</strong></p><p class="text-slate-300 leading-relaxed mb-4">Ensure your logger includes the correlation ID in every log line. For example:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>function log(level: string, msg: string, meta?: Record<string, unknown>) {
  const requestId = getRequestId();
  const payload = { level, msg, requestId, ...meta };
  console.log(JSON.stringify(payload));
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Then searching logs for <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">"requestId":"abc-123"</code> returns the full story for that request.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Outbound HTTP</strong></p><p class="text-slate-300 leading-relaxed mb-4">When calling another service, forward the ID so they can use it too:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const requestId = getRequestId();
fetch(url, {
  headers: {
    "X-Request-ID": requestId ?? randomUUID(),
    // ...other headers
  },
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>Queues and workers</strong></p><p class="text-slate-300 leading-relaxed mb-4">If you enqueue a job, put the correlation ID in the job payload. When the worker runs, set the context from the payload (e.g. call <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">withRequestId(job.correlationId, () => { ... })</code>) so worker logs carry the same ID and you can trace from API → queue → worker.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Summary</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Assign or read a correlation ID at the entry point; prefer reusing an incoming <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">X-Request-ID</code> when present.</li>
<li class="ml-4 list-disc text-slate-300">Use AsyncLocalStorage to propagate the ID through the request scope so you don’t have to pass it manually.</li>
<li class="ml-4 list-disc text-slate-300">Add the ID to every structured log line and to outbound HTTP headers and job payloads.</li></p><p class="text-slate-300 leading-relaxed mb-4">With this in place, production debugging becomes a matter of searching for one ID and following the request end to end.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
