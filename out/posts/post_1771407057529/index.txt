When a customer reported “task T42 never finished,” they spent half an hour grepping log files and guessing which process had failed. They couldn’t afford Datadog (roughly 15–31 USD per host per month at list price), and they didn’t want to stand up Prometheus + Grafana for three services. So they built a minimal observability stack: <strong>structured logging</strong> for traceability, <strong>SQLite as a metrics store</strong> for counters and latencies, and a <strong>simple health dashboard</strong> that aggregates existing health endpoints and DB stats. Under load they saw "database is locked" errors (busy_timeout helped but didn’t remove them). They moved metrics to a separate <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">metrics.db</code> and used WAL and a 5-second busy timeout there too. Writes from two processes stayed below 100/sec, so one writer and one reader (dashboard script) were fine.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>3. Percentiles in SQL.</strong> Their first version computed p95 by selecting all samples in the last hour and doing the math in TypeScript. With 50k rows the script took 2–3 seconds. They added a simple time-bucketed aggregate table (e.g. per 5-minute window: count, sum, min, max) and computed approximate p95 from those buckets for the dashboard; raw samples are still there for ad-hoc analysis. That brought the dashboard load under 200 ms.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What you can do today</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Add a structured log helper</strong> in your scheduler or worker: one function that prints a single JSON line with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">time</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">level</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">msg</code>, and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">taskId</code>/<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">correlationId</code>. Use it for “task claimed” and “task completed/failed” at minimum.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Create a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">metrics</code> table</strong> (in a separate SQLite file if you prefer) with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ts</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">name</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">value</code>, and optional <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">tags</code>. From your task completion path, insert one row per task with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">task_duration_ms</code> and optionally <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">task_count</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">error_count</code>.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Run your existing health check from cron</strong> (e.g. every 5 minutes) and mail or notify on non-zero exit. If you don’t have <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">health-check.ts</code>, add a script that hits <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">/health</code> on your services and does <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">SELECT 1</code> on SQLite.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Add a 5-minute dashboard script</strong> that: runs the health checks, reads from <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">metrics</code> for the last hour, and prints or outputs JSON (p50/p95, error count, and OK/FAIL per service). Optionally serve it as a single HTML page from a small Bun HTTP server.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Set one alert:</strong> e.g. “if health check fails twice in a row, send an email or post to Slack.” That single rule catches most “something is down” incidents without needing Datadog.</li></p><p class="text-slate-300 leading-relaxed mb-4">Once this is in place, you have traceable logs, a place for metrics, and a minimal health view. You can grow into Prometheus or an APM when the team or service count justifies the cost and complexity.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
