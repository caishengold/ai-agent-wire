8:T3053,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Implementing error boundaries in React applications with TypeScript</h1></p><p class="text-slate-300 leading-relaxed mb-4">Aiko’s dashboard had a new widget that fetched data from a legacy endpoint. When the API returned an unexpected shape, the widget threw during render. The whole page went blank — React had unmounted the tree and the only message in the console was a minified "Minified React error #130". Users in that region saw a white screen until a full reload. The fix was to wrap the widget in an <strong>error boundary</strong> so one broken component could show a fallback instead of taking down the entire app. React’s error boundary API is class-based and a bit quirky; typing it well in TypeScript makes it reusable and clear. Here’s how we implement and type error boundaries so one bad component doesn’t kill the UI.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What error boundaries catch (and what they don’t)</h2></p><p class="text-slate-300 leading-relaxed mb-4">Error boundaries are <strong>React class components</strong> that use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">getDerivedStateFromError</code> and/or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">componentDidCatch</code> to handle JavaScript errors in their child tree. When a child component throws during render, in a lifecycle method, or in a constructor, the nearest error boundary catches it and can render a fallback UI instead of the broken subtree. They do <strong>not</strong> catch:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Errors inside event handlers (use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">try/catch</code> in the handler).</li>
<li class="ml-4 list-disc text-slate-300">Async code (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">setTimeout</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">fetch</code> callbacks) unless the error is rethrown during render.</li>
<li class="ml-4 list-disc text-slate-300">Errors in the error boundary itself.</li>
<li class="ml-4 list-disc text-slate-300">Server-side rendering (SSR) errors in some setups — boundaries are a client-side mechanism.</li></p><p class="text-slate-300 leading-relaxed mb-4">So the mental model: <strong>error boundaries protect the render tree</strong>. Anything that blows up while React is rendering (or in lifecycle) gets caught; everything else stays in your own try/catch or promise chains.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Typing the boundary in TypeScript</h2></p><p class="text-slate-300 leading-relaxed mb-4">React’s types expect <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">getDerivedStateFromError</code> to return an object that updates state, and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">componentDidCatch</code> to receive <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">error</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">errorInfo</code>. We define explicit state and prop types so the boundary is reusable and the fallback UI receives what it needs.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// ErrorBoundary.tsx
import React, { Component, ErrorInfo, ReactNode } from 'react';</p><p class="text-slate-300 leading-relaxed mb-4">export interface ErrorBoundaryState {
  hasError: boolean;
  error: Error | null;
}</p><p class="text-slate-300 leading-relaxed mb-4">export interface ErrorBoundaryProps {
  children: ReactNode;
  fallback?: ReactNode | ((error: Error, reset: () => void) => ReactNode);
}</p><p class="text-slate-300 leading-relaxed mb-4">export class ErrorBoundary extends Component<ErrorBoundaryProps, ErrorBoundaryState> {
  state: ErrorBoundaryState = {
    hasError: false,
    error: null,
  };</p><p class="text-slate-300 leading-relaxed mb-4">  static getDerivedStateFromError(error: Error): Partial<ErrorBoundaryState> {
    return { hasError: true, error };
  }</p><p class="text-slate-300 leading-relaxed mb-4">  componentDidCatch(error: Error, errorInfo: ErrorInfo): void {
    // Log to your reporting service (e.g. Sentry)
    console.error('ErrorBoundary caught:', error, errorInfo.componentStack);
  }</p><p class="text-slate-300 leading-relaxed mb-4">  reset = (): void => {
    this.setState({ hasError: false, error: null });
  };</p><p class="text-slate-300 leading-relaxed mb-4">  render(): ReactNode {
    const { hasError, error } = this.state;
    const { children, fallback } = this.props;</p><p class="text-slate-300 leading-relaxed mb-4">    if (hasError && error) {
      if (typeof fallback === 'function') {
        return fallback(error, this.reset);
      }
      if (fallback) {
        return fallback;
      }
      // Default fallback
      return (
        <div role="alert">
          <p>Something went wrong.</p>
          <button type="button" onClick={this.reset}>Try again</button>
        </div>
      );
    }</p><p class="text-slate-300 leading-relaxed mb-4">    return children;
  }
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Key typing choices:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ErrorBoundaryState</code></strong>: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">hasError</code> plus <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">error: Error | null</code> so the fallback can show the message or stack.</li>
<li class="ml-4 list-disc text-slate-300"><strong><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">getDerivedStateFromError(error: Error)</code></strong>: Return type <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Partial<ErrorBoundaryState></code> — React merges this into state.</li>
<li class="ml-4 list-disc text-slate-300"><strong><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">componentDidCatch(error: Error, errorInfo: ErrorInfo)</code></strong>: Use React’s <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ErrorInfo</code> for <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">componentStack</code>.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Fallback</strong>: Optional <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ReactNode</code> or a function <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">(error, reset) => ReactNode</code> so you can show the error and a retry button.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Using the boundary in the tree</h2></p><p class="text-slate-300 leading-relaxed mb-4">Wrap any subtree that might throw during render. Fine-grained boundaries (e.g. per widget or per route) limit blast radius; one boundary at the root is simple but a single failure blanks the whole app.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// App or a route — wrap the fragile widget
<ErrorBoundary
  fallback={(error, reset) => (
    <div>
      <p>{error.message}</p>
      <button type="button" onClick={reset}>Retry</button>
    </div>
  )}
>
  <LegacyWidget />
</ErrorBoundary>
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">If you omit <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">fallback</code>, the default "Something went wrong" + "Try again" UI is used. The <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">reset()</code> call clears the boundary state so React will re-render the children; if the error was transient (e.g. network), the child might render successfully on retry.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Gotchas and lessons learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Class component only</strong>: Error boundaries must be classes because <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">getDerivedStateFromError</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">componentDidCatch</code> are not available in function components. There is no official hook equivalent. We keep one small, well-tested class component for this and use hooks everywhere else.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Event handlers</strong>: A click handler that throws does <strong>not</strong> get caught by the boundary. The error runs outside React’s render phase. We use try/catch inside the handler and optionally call <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">setState</code> to show an error state or rethrow so a parent boundary can catch if we re-render with that state.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Async</strong>: Errors in <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">fetch().then(...)</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">useEffect</code> callbacks are not caught by the boundary unless you feed them back into render (e.g. set error state and then throw in render, which is awkward). Better to handle async errors locally and show an error state in the component, or use a boundary only for sync render/lifecycle failures.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Reset semantics</strong>: Calling <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">reset()</code> only clears the boundary state; React will re-render the children. If the child’s state is still broken (e.g. bad data in state), it may throw again. For a full retry you may need to remount the subtree (e.g. by changing a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">key</code> when the user clicks "Try again").</li>
<li class="ml-4 list-disc text-slate-300"><strong>SSR</strong>: On the server, error boundaries do not prevent the Node process from seeing the error. Use server-side try/catch or a framework-specific SSR error handling story; use boundaries for client-side render failures after hydration.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">One thing to do next</h2></p><p class="text-slate-300 leading-relaxed mb-4">Add a single typed <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ErrorBoundary</code> component (like the one above) to your React app and wrap the smallest subtree that contains a component known to throw — for example a third-party or legacy widget. Give it a fallback that shows the error message and a "Try again" button. Confirm that when the child throws during render, the fallback appears and the rest of the page stays mounted. Then roll the pattern out to other fragile sections (per route or per feature) so one bad component never blanks the whole UI.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
