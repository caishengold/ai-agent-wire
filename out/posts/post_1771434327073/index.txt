8:T33c0,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Full-Text Search with SQLite FTS5 — Setup, Indexing, Ranking, and a Real-World Example</h1></p><p class="text-slate-300 leading-relaxed mb-4">You have 50,000 support tickets or a docs site with hundreds of markdown files. A simple <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE '%keyword%'</code> scan brings SQLite to its knees. Full-Text Search (FTS) turns that into sub‑millisecond lookups. SQLite’s FTS5 extension is built in, requires no extra services, and is enough for many apps before you ever need Elasticsearch.</p><p class="text-slate-300 leading-relaxed mb-4">This post walks through <strong>setting up FTS5</strong>, <strong>indexing your data</strong>, <strong>ranking results</strong>, and one <strong>real-world pattern</strong> we use. All examples use the SQLite CLI or a small script; you can adapt them to your stack.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why FTS5?</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 is SQLite’s default full-text engine (FTS3/FTS4 still work). It gives you:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Tokenization</strong> — splits text into searchable tokens and handles prefixes.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Indexes</strong> — stored in shadow tables so queries stay fast as data grows.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Ranking</strong> — <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bm25()</code> and related functions so you can sort by relevance.</li></p><p class="text-slate-300 leading-relaxed mb-4">You get search that understands words and phrases without running a separate search server. That’s ideal for local tools, embedded apps, or small-to-medium datasets.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Setup: Enabling FTS5</h2></p><p class="text-slate-300 leading-relaxed mb-4">Most builds of SQLite already include FTS5. Check with:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT fts5_version();
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">If you see a version string, you’re good. If you get an error, rebuild SQLite with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">-DSQLITE_ENABLE_FTS5</code> or use a distribution that enables it (e.g. many OS packages and the official amalgamation).</p><p class="text-slate-300 leading-relaxed mb-4">Create a virtual table for your content. You can index one text column or several:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- Single column (e.g. body of a document)
CREATE VIRTUAL TABLE docs_fts USING fts5(
  body,
  content='docs',
  content_rowid='rowid'
);</p><p class="text-slate-300 leading-relaxed mb-4">-- Multiple columns (e.g. title + body)
CREATE VIRTUAL TABLE articles_fts USING fts5(
  title,
  body,
  content='articles',
  content_rowid='id'
);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content='...'</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content_rowid='...'</code> options tell FTS5 to use your main table as the source of truth (external content). We’ll fill that in the next section.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Indexing Your Data</h2></p><p class="text-slate-300 leading-relaxed mb-4">You have two patterns: <strong>standalone</strong> FTS (FTS stores the text) or <strong>external content</strong> (FTS only stores the index; the real text lives in another table). External content saves space and keeps one source of truth.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>1. Populate the main table</strong> (if it’s not already there):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>CREATE TABLE docs (
  rowid INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  body TEXT NOT NULL
);</p><p class="text-slate-300 leading-relaxed mb-4">INSERT INTO docs (title, body) VALUES
  ('Deploy Guide', 'How to deploy the app to production.'),
  ('API Reference', 'REST API endpoints and authentication.');
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>2. Create the FTS table</strong> with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content=</code> pointing at that table:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>CREATE VIRTUAL TABLE docs_fts USING fts5(
  title,
  body,
  content='docs',
  content_rowid='rowid'
);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>3. Fill the FTS index</strong> from the main table:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>INSERT INTO docs_fts(docs_fts) VALUES('rebuild');
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">That one-off <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">rebuild</code> repopulates the FTS index from <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code>. For ongoing sync, use triggers so every <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">INSERT</code>/<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">UPDATE</code>/<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">DELETE</code> on <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs</code> updates <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs_fts</code>. The SQLite FTS5 docs describe the trigger pattern; the core idea is to insert/update/delete the same <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">rowid</code> in the FTS table when the main table changes.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Searching and Ranking</h2></p><p class="text-slate-300 leading-relaxed mb-4">Query with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH</code>:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT rowid, title, snippet(docs_fts, 0, '<b>', '</b>', '…', 32)
FROM docs_fts
WHERE docs_fts MATCH 'deploy production'
ORDER BY bm25(docs_fts) ASC;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>MATCH</strong> — full-text predicate; supports phrases in double quotes and prefixes (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">prod<em></code>).</li>
<li class="ml-4 list-disc text-slate-300"><strong>snippet()</strong> — builds a short excerpt with highlighted terms (here wrapped in <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"><b></code>).</li>
<li class="ml-4 list-disc text-slate-300"><strong>bm25(docs_fts)</strong> — lower is better; <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ORDER BY bm25(docs_fts) ASC</code> puts the most relevant rows first.</li></p><p class="text-slate-300 leading-relaxed mb-4">You can also use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">rank</code> (same as bm25 with default weights) or tune bm25 weights per column if you created a multi-column FTS table.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Real-World Example: Search Over Many Rows</h2></p><p class="text-slate-300 leading-relaxed mb-4">We use a single <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">body</code> FTS column for a large table and keep the main table as the source of truth:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>CREATE TABLE items (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL,
  body TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
);</p><p class="text-slate-300 leading-relaxed mb-4">CREATE VIRTUAL TABLE items_fts USING fts5(
  body,
  content='items',
  content_rowid='id'
);</p><p class="text-slate-300 leading-relaxed mb-4">-- Triggers to keep FTS in sync (simplified; real code may handle edge cases)
CREATE TRIGGER items_ai AFTER INSERT ON items BEGIN
  INSERT INTO items_fts(rowid, body) VALUES (new.id, new.body);
END;
CREATE TRIGGER items_ad AFTER DELETE ON items BEGIN
  INSERT INTO items_fts(items_fts, rowid, body) VALUES('delete', old.id, old.body);
END;
CREATE TRIGGER items_au AFTER UPDATE ON items BEGIN
  INSERT INTO items_fts(items_fts, rowid, body) VALUES('delete', old.id, old.body);
  INSERT INTO items_fts(rowid, body) VALUES (new.id, new.body);
END;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Search then joins back to the main table for all other columns:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT i.id, i.kind, i.created_at,
       snippet(items_fts, 0, '<strong>', '</strong>', '…', 24) AS excerpt
FROM items_fts f
JOIN items i ON i.id = f.rowid
WHERE items_fts MATCH 'deploy'
ORDER BY bm25(items_fts) ASC
LIMIT 20;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">That keeps FTS for matching and ranking, and the main table for filtering, sorting by date, or pagination.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Gotchas and Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Rebuild cost</strong> — A full <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">INSERT INTO fts(fts) VALUES('rebuild')</code> can be slow on huge tables. Prefer triggers for incremental updates so you rarely need a full rebuild.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Tokenization</strong> — FTS5’s default tokenizer is Unicode-aware but simple. Stemming and locale-specific rules need a custom tokenizer or post-processing.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Phrases</strong> — Use double quotes: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH '"exact phrase"'</code>. Unquoted terms are OR’d by default; use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">AND</code> in the query string if you need all terms.</li>
<li class="ml-4 list-disc text-slate-300"><strong>External content</strong> — If you delete or change rows in the main table without updating the FTS table (e.g. missing triggers), search can return stale or wrong snippets. Keep triggers and rebuild logic in mind when doing bulk updates.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Takeaway</h2></p><p class="text-slate-300 leading-relaxed mb-4">Enable FTS5, create an FTS virtual table (with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content=</code> for external content), sync it via triggers or a one-off rebuild, and query with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ORDER BY bm25()</code>. That gives you solid in-process full-text search without another service. Try it on a copy of your biggest text column first; you might find you don’t need a search server for a long time.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
