Container Security: A Comprehensive Checklist
In the rapidly evolving world of containerization, ensuring the security of your containers is paramount. This article provides a detailed checklist for container security, focusing on key areas such as image scanning, rootless containers, seccomp profiles, and real-world Common Vulnerabilities and Exposures (CVE) examples. Let's dive into the essential steps to secure your containerized applications.
Image Scanning
Aiko Zhang, a software engineer at TechCorp, was recently tasked with deploying a new application using Docker containers. To ensure the application's security, she began by scanning the container images for vulnerabilities.
#### Step 1: Choose a Security Scanner
Aiko selected Docker Bench for Security, a tool that assesses the security of a Docker installation and Dockerfiles. It checks for common best practices and vulnerabilities.
sh docker run -v /var/run/docker.sock:/var/run/docker.sock --rm docker/docker-bench-for-security 

#### Step 2: Interpret the Results
After running the scan, Aiko reviewed the results and identified several vulnerabilities. One notable issue was an unpatched version of the container image, which had a CVE that could be exploited by an attacker.
Rootless Containers
To further enhance security, Aiko decided to use rootless containers, which run as a non-root user. This approach limits the potential damage that can be caused by a compromised container.
#### Step 3: Configure Rootless Containers
Aiko used podman to create rootless containers. She first added her user to the podman group and then ran the following command to start a rootless container:
sh sudo podman run -d --name my-container my-image 

#### Step 4: Verify Rootless Configuration
To confirm that the container is running in rootless mode, Aiko checked the container's user ID:
sh sudo podman ps -a 


Seccomp Profiles
To further restrict the capabilities of the container, Aiko configured seccomp profiles, which restrict system calls that a container can make.
#### Step 5: Create a Seccomp Profile
Aiko created a custom seccomp profile that blocked several system calls, including fork and execve. She used audit2allow to generate the necessary rules for the profile:
sh audit2allow -a 'alert ' -m 1 -M my-profile 

#### Step 6: Apply the Seccomp Profile
Aiko applied the seccomp profile to her container:
sh sudo podman run -d --name my-container --security-opt seccomp=my-profile my-image 


Real CVE Examples
To illustrate the importance of container security, let's look at some real-world CVE examples.
| CVE ID | Description | Affected Container | Potential Impact |
|--------|-------------|--------------------|------------------|
| CVE-2019-5736 | Docker Remote Code Execution | Docker 18.06.0-ce-3 | Remote attackers could execute arbitrary code on the host system |
| CVE-2020-8455 | Container Escape via Netlink | podman <= 2.1.1 | Attackers could escape from the container and gain elevated privileges |
| CVE-2020-3638 | Podman Local Privilege Escalation | podman <= 2.1.1 | Local attackers could escalate privileges within the container |
Lessons Learned
  • Regularly scan container images for vulnerabilities: Vulnerabilities can be introduced at any stage of the container lifecycle, so regular scanning is crucial.
    • 

  • Use rootless containers to reduce attack surface: Running containers as a non-root user limits the potential damage that can be caused by a compromised container.
    • 

  • Configure seccomp profiles to restrict capabilities: Seccomp profiles can help prevent containers from executing harmful system calls.
    • Actionable Takeaways
  • Implement regular container image scanning: Use tools like Docker Bench for Security to scan images for vulnerabilities.
    • 

  • Deploy rootless containers: Run containers as a non-root user to limit the potential damage of a compromise.
    • 

  • Configure seccomp profiles: Restrict the capabilities of containers to prevent unauthorized system calls.
    • 

  • Stay informed about CVEs: Regularly update your knowledge of CVEs and ensure that your containers are not vulnerable to known exploits.
    • 

  • Automate container security checks: Use CI/CD pipelines to automatically scan and enforce security policies during the container deployment process.
    • By following this checklist and implementing the recommended practices, you can significantly enhance the security of your containerized applications.
