title: Container Security Checklist: Ensuring Safety in the Container Age
date: 2026-02-13
author: Aiko Zhang
tags: container security, image scanning, rootless containers, seccomp profiles, CVE examples
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Container Security: A Comprehensive Checklist</h2></p><p class="text-slate-300 leading-relaxed mb-4">In the rapidly evolving world of containerization, ensuring the security of your containers is paramount. This article provides a detailed checklist for container security, focusing on key areas such as image scanning, rootless containers, seccomp profiles, and real-world Common Vulnerabilities and Exposures (CVE) examples. Let's dive into the essential steps to secure your containerized applications.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Image Scanning</h3></p><p class="text-slate-300 leading-relaxed mb-4">Aiko Zhang, a software engineer at TechCorp, was recently tasked with deploying a new application using Docker containers. To ensure the application's security, she began by scanning the container images for vulnerabilities.</p><p class="text-slate-300 leading-relaxed mb-4">#### Step 1: Choose a Security Scanner
Aiko selected Docker Bench for Security, a tool that assesses the security of a Docker installation and Dockerfiles. It checks for common best practices and vulnerabilities.</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>sh
docker run -v /var/run/docker.sock:/var/run/docker.sock --rm docker/docker-bench-for-security
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
#### Step 2: Interpret the Results
After running the scan, Aiko reviewed the results and identified several vulnerabilities. One notable issue was an unpatched version of the container image, which had a CVE that could be exploited by an attacker.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Rootless Containers</h3></p><p class="text-slate-300 leading-relaxed mb-4">To further enhance security, Aiko decided to use rootless containers, which run as a non-root user. This approach limits the potential damage that can be caused by a compromised container.</p><p class="text-slate-300 leading-relaxed mb-4">#### Step 3: Configure Rootless Containers
Aiko used <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">podman</code> to create rootless containers. She first added her user to the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">podman</code> group and then ran the following command to start a rootless container:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>sh
sudo podman run -d --name my-container my-image
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
#### Step 4: Verify Rootless Configuration
To confirm that the container is running in rootless mode, Aiko checked the container's user ID:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>sh
sudo podman ps -a
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
<h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Seccomp Profiles</h3></p><p class="text-slate-300 leading-relaxed mb-4">To further restrict the capabilities of the container, Aiko configured seccomp profiles, which restrict system calls that a container can make.</p><p class="text-slate-300 leading-relaxed mb-4">#### Step 5: Create a Seccomp Profile
Aiko created a custom seccomp profile that blocked several system calls, including <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">fork</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">execve</code>. She used <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">audit2allow</code> to generate the necessary rules for the profile:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>sh
audit2allow -a 'alert <em> </em> <em>' -m 1 -M my-profile
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
#### Step 6: Apply the Seccomp Profile
Aiko applied the seccomp profile to her container:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>sh
sudo podman run -d --name my-container --security-opt seccomp=my-profile my-image
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
<h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Real CVE Examples</h3></p><p class="text-slate-300 leading-relaxed mb-4">To illustrate the importance of container security, let's look at some real-world CVE examples.</p><p class="text-slate-300 leading-relaxed mb-4">| CVE ID | Description | Affected Container | Potential Impact |
|--------|-------------|--------------------|------------------|
| CVE-2019-5736 | Docker Remote Code Execution | Docker 18.06.0-ce-3 | Remote attackers could execute arbitrary code on the host system |
| CVE-2020-8455 | Container Escape via Netlink | podman <= 2.1.1 | Attackers could escape from the container and gain elevated privileges |
| CVE-2020-3638 | Podman Local Privilege Escalation | podman <= 2.1.1 | Local attackers could escalate privileges within the container |</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Lessons Learned</h3></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Regularly scan container images for vulnerabilities</strong>: Vulnerabilities can be introduced at any stage of the container lifecycle, so regular scanning is crucial.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Use rootless containers to reduce attack surface</strong>: Running containers as a non-root user limits the potential damage that can be caused by a compromised container.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Configure seccomp profiles to restrict capabilities</strong>: Seccomp profiles can help prevent containers from executing harmful system calls.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Actionable Takeaways</h3></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Implement regular container image scanning</strong>: Use tools like Docker Bench for Security to scan images for vulnerabilities.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Deploy rootless containers</strong>: Run containers as a non-root user to limit the potential damage of a compromise.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Configure seccomp profiles</strong>: Restrict the capabilities of containers to prevent unauthorized system calls.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Stay informed about CVEs</strong>: Regularly update your knowledge of CVEs and ensure that your containers are not vulnerable to known exploits.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Automate container security checks</strong>: Use CI/CD pipelines to automatically scan and enforce security policies during the container deployment process.</li></p><p class="text-slate-300 leading-relaxed mb-4">By following this checklist and implementing the recommended practices, you can significantly enhance the security of your containerized applications.
