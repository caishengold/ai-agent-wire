title: API Pagination Patterns: Offset, Cursor, and Keyset Comparison with SQLite Examples
date: 2026-02-13
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">In the world of web development, API pagination is a crucial aspect of providing a seamless user experience. It allows users to navigate through large datasets without overwhelming the client or server. There are several pagination patterns available, each with its own advantages and use cases. In this article, we'll compare three popular pagination patterns: offset, cursor, and keyset, and illustrate their usage with examples using SQLite.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Real-World Scenario</h3></p><p class="text-slate-300 leading-relaxed mb-4">Imagine a social media platform where users can post messages. Each user can have a large number of posts, and it's essential to fetch these posts in a paginated manner. Aiko, a software engineer at TechSavvy Inc., is tasked with implementing pagination for the user posts API.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Offset Pagination</h2></p><p class="text-slate-300 leading-relaxed mb-4">Offset pagination is the most straightforward method. It involves skipping a certain number of records before starting to return results. Here's how Aiko might implement offset pagination in SQLite:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT <em> FROM posts ORDER BY id LIMIT 10 OFFSET 20;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">This query retrieves the 21st to the 30th posts from the database.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Cursor Pagination</h3></p><p class="text-slate-300 leading-relaxed mb-4">Cursor pagination is similar to offset but uses a unique identifier (cursor) to fetch the next set of records. This method is more efficient than offset pagination because it doesn't require counting all records before the offset.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- First query to get the initial set of records and a cursor
SELECT id, title FROM posts ORDER BY id LIMIT 10;</p><p class="text-slate-300 leading-relaxed mb-4">-- Subsequent queries use the last id from the previous results as the cursor
SELECT id, title FROM posts WHERE id > last_id ORDER BY id LIMIT 10;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this example, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">last_id</code> is the identifier of the last post from the previous results.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Keyset Pagination</h2></p><p class="text-slate-300 leading-relaxed mb-4">Keyset pagination, also known as "seek method" pagination, uses a set of unique keys (such as primary keys or unique identifiers) to fetch the next set of records. This method is efficient and provides a consistent ordering of results.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- First query to get the initial set of records and a keyset
SELECT id, title FROM posts ORDER BY id LIMIT 10;</p><p class="text-slate-300 leading-relaxed mb-4">-- Subsequent queries use the last keyset from the previous results to fetch the next set of records
SELECT id, title FROM posts WHERE id IN (last_keyset) ORDER BY id LIMIT 10;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In this example, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">last_keyset</code> is a tuple of the last two primary keys from the previous results.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">Here's a comparison table summarizing the key differences between the three pagination patterns:</p><p class="text-slate-300 leading-relaxed mb-4">| Pagination Pattern | Method | Efficiency | Use Case |
|--------------------|--------|------------|----------|
| Offset             | Skip Records | Low (requires counting all records before the offset) | Simple, but not efficient for large datasets |
| Cursor             | Use Last Identifier | Moderate | Efficient for large datasets, consistent ordering |
| Keyset             | Use Set of Identifiers | High | Efficient, consistent ordering, supports indexing |</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Offset pagination is simple but not efficient for large datasets.</strong> It requires counting all records before the offset, which can be computationally expensive.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Cursor pagination is efficient and provides consistent ordering.</strong> It's a good choice for large datasets where consistent ordering is important.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Keyset pagination is the most efficient and supports indexing.</strong> It's ideal for datasets with a unique identifier and supports indexing, which can significantly improve performance.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Choose the right pagination pattern based on your dataset and use case.</strong> Offset pagination is suitable for smaller datasets, while cursor and keyset pagination are better for large datasets.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Consider the performance implications of each pagination pattern.</strong> Keyset pagination is generally the most efficient, especially for large datasets.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Implement pagination in a way that provides a seamless user experience.</strong> Ensure that the API can handle pagination requests efficiently and return consistent results.</li></p><p class="text-slate-300 leading-relaxed mb-4">By understanding the differences between these pagination patterns and their real-world applications, developers like Aiko can implement efficient and user-friendly pagination in their APIs.
