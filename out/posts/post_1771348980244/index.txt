8:T1a09,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Circuit Breaker for Agent API Calls</h1></p><p class="text-slate-300 leading-relaxed mb-4">> When an agent or task runner depends on external APIs (LLMs, third-party services, or your own backends), a failing or slow service can cause every request to hang or retry until timeouts. A circuit breaker stops calling the service after repeated failures and fails fast until the service is given a chance to recover.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">1. Why Use a Circuit Breaker?</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Fail fast</strong>: If the provider is down or severely degraded, retrying every task wastes time and resources. Failing quickly lets the scheduler move on or report clearly.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Give the service time to recover</strong>: After opening the circuit, you stop sending traffic for a period. That reduces load on the struggling service and allows it to stabilize.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Avoid cascading failures</strong>: One bad dependency can tie up all your workers. A circuit breaker isolates the failure so the rest of the system can keep working (e.g. skip that provider or use a fallback).</li></p><p class="text-slate-300 leading-relaxed mb-4">Use a circuit breaker in addition to retries and backoff: retries handle transient blips; the circuit breaker handles sustained outages.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">2. Three States</h2></p><p class="text-slate-300 leading-relaxed mb-4">A typical implementation has three states:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Closed</strong>: Requests go through. Failures are counted. If the failure count (or rate) exceeds a threshold within a time window, the circuit <strong>opens</strong>.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Open</strong>: Requests do not call the service; they fail immediately (or return a cached/fallback result). After a <strong>reset timeout</strong> (e.g. 30–60 seconds), the circuit moves to <strong>half-open</strong>.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Half-open</strong>: A limited number of requests (e.g. one or a few) are allowed through. If they succeed, the circuit <strong>closes</strong>; if they fail, the circuit <strong>opens</strong> again.</li></p><p class="text-slate-300 leading-relaxed mb-4">Thresholds (e.g. 5 failures in 10 seconds) and the reset timeout are configurable.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">3. Example in TypeScript</h2></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>type State = 'closed' | 'open' | 'half-open';</p><p class="text-slate-300 leading-relaxed mb-4">class CircuitBreaker {
  private state: State = 'closed';
  private failures = 0;
  private lastFailureAt = 0;
  private nextAttemptAt = 0;</p><p class="text-slate-300 leading-relaxed mb-4">  constructor(
    private readonly threshold: number,
    private readonly windowMs: number,
    private readonly resetMs: number
  ) {}</p><p class="text-slate-300 leading-relaxed mb-4">  async call<T>(fn: () => Promise<T>): Promise<T> {
    const now = Date.now();</p><p class="text-slate-300 leading-relaxed mb-4">    if (this.state === 'open') {
      if (now < this.nextAttemptAt) throw new Error('Circuit open');
      this.state = 'half-open';
    }</p><p class="text-slate-300 leading-relaxed mb-4">    if (this.state === 'closed' && this.lastFailureAt > 0 && now - this.lastFailureAt > this.windowMs) {
      this.failures = 0;
    }</p><p class="text-slate-300 leading-relaxed mb-4">    try {
      const result = await fn();
      if (this.state === 'half-open') {
        this.state = 'closed';
        this.failures = 0;
      }
      return result;
    } catch (e) {
      this.failures++;
      this.lastFailureAt = now;
      if (this.state === 'half-open' || this.failures >= this.threshold) {
        this.state = 'open';
        this.nextAttemptAt = now + this.resetMs;
      }
      throw e;
    }
  }
}</p><p class="text-slate-300 leading-relaxed mb-4">// Usage: wrap your API call
const breaker = new CircuitBreaker(5, 10_000, 30_000);
const response = await breaker.call(() => fetch('https://api.example.com/chat', { ... }));
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">4. Tuning and Integration</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Threshold and window</strong>: Lower threshold (e.g. 3) opens the circuit sooner; larger window (e.g. 60s) avoids reopening on short spikes. Choose based on how critical the dependency is and how noisy failures are.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Reset timeout</strong>: Too short and you keep hitting a service that is still recovering; too long and you delay recovery. Start with 30–60 seconds and adjust.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Half-open</strong>: Allowing a single request in half-open is common. If you have high concurrency, you might allow a small batch and close only if a majority succeed.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Observability</strong>: Log state transitions (closed → open, open → half-open, half-open → closed) and optionally expose them in metrics or health checks so you can see when and why the circuit opened.</li></p><p class="text-slate-300 leading-relaxed mb-4">Combined with backoff and jitter on retries, a circuit breaker keeps agent API calls resilient without overloading failing services or blocking the rest of your pipeline.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
