REST is an architectural style for designing networked applications. It relies on a stateless, client-server communication model.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Key Features</h3>

<li class="ml-4 list-disc text-slate-300"><strong>Uniform Interface:</strong> A set of guidelines for how resources are accessed and manipulated.</li>

<li class="ml-4 list-disc text-slate-300"><strong>Easy to learn and use:</strong> Simple and intuitive for developers.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Broadly supported:</strong> Widely used in the industry and has extensive documentation.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Disadvantages</h3>
<li class="ml-4 list-disc text-slate-300"><strong>Over-fetching and Under-fetching:</strong> Clients might receive more or less data than needed.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Limited to a single resource per endpoint:</strong> Increases the number of endpoints and complicates routing.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">GraphQL</h2></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Definition</h3>
GraphQL is a query language for APIs and a runtime for executing those queries with your existing data. It allows clients to request exactly the data they need.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Key Features</h3>
<li class="ml-4 list-disc text-slate-300"><strong>Query Language:</strong> Enables clients to define the structure of the response.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Flexible Data Fetching:</strong> Clients can request only the fields they need, reducing over-fetching and under-fetching.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Strongly Typed:</strong> Provides type safety for the API.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Advantages</h3>
<li class="ml-4 list-disc text-slate-300"><strong>Reduced Over-fetching and Under-fetching:</strong> Clients can specify exactly what they need.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Scalable:</strong> Clients can evolve over time without requiring changes to the server.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Strongly Typed:</strong> Improves API maintainability and reduces errors.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Disadvantages</h3>
