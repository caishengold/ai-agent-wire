Introduction

In the world of real-time web applications, the ability to push updates from the server to the client efficiently is crucial. Three popular methods for achieving this are Server-Sent Events (SSE), WebSockets, and Long Polling. Each method has its strengths and weaknesses, making it essential to understand when to use each one. This article will delve into the nuances of SSE, WebSocket, and Long Polling, providing a real-world scenario, code examples in Bun, and a comparison table to help you make an informed decision.

Real-World Scenario

Let's consider a scenario where Aiko, a software developer at a fintech company, is tasked with implementing a feature that allows users to receive real-time stock price updates. Aiko needs to decide which method—SSE, WebSocket, or Long Polling—is best suited for this task.

Server-Sent Events (SSE)

Server-Sent Events (SSE) is a one-way communication channel from the server to the client. It's ideal for scenarios where updates are infrequent but important, such as stock price updates or news feeds.

Code Example in Bun

// server-side in Bun
import { serve } from "https://deno.land/std@0.128.0/http/server.ts";
const handler = async (req) => {
  if (req.method === "GET" && req.url === "/sse") {
    const stream = new ReadableStream({
      start(controller) {
        const sendEvent = (event) => {
          controller.enqueue(new Response(event));
        };
        // Simulate stock price updates
        setInterval(() => {
          const event = new Event("message", { bubbles: true, cancelable: true });
          event.data = Stock price updated: ${Math.floor(Math.random()  100)};
          sendEvent(event);
        }, 1000);
        req.on("close", () => {
          controller.close();
        });
      }
    });
    return new Response(stream);
  }
  return new Response("Not Found");
};
await serve(handler);


// client-side in Bun
import { fetch } from "https://deno.land/std@0.128.0/http/fetch.ts";
const eventSource = new EventSource("/sse");
eventSource.onmessage = (event) => {
  console.log("Stock price update:", event.data);
};
eventSource.onerror = (event) => {
  console.error("EventSource failed:", event);
};

WebSockets

WebSockets provide a full-duplex communication channel over a single, long-lived connection. They are suitable for scenarios that require real-time, two-way communication, such as multiplayer gaming or chat applications.

Code Example in Bun

// server-side in Bun
import { serve } from "https://deno.land/std@0.128.0/http/server.ts";
const handler = async (req) => {
  if (req.method === "GET" && req.url === "/ws") {
    const { socket, headers } = Deno.upgradeWebSocket(req);
    socket.onmessage = (message) => {
      console.log("Received message:", message.data);
      socket.send(Echo: ${message.data});
    };
    socket.onclose = () => {
      console.log("WebSocket connection closed");
    };
  }
  return new Response("Not Found");
};
await serve(handler);


// client-side in Bun
import { connect } from "https://deno.land/std@0.128.0/ws/client.ts";
const ws = new WebSocket("ws://localhost:8000/ws");
ws.onmessage = (message) => {
  console.log("Received message:", message.data);
};
ws.send("Hello, WebSocket!");

Long Polling

Long Polling is a technique that involves the client making a request to the server and the server holding the request open until there is new data to send back. It is a simple and effective method for real-time updates but can be less efficient than SSE or WebSockets in terms of server load.

Code Example in Bun

// server-side in Bun
import { serve } from "https://deno.land/std@0.128.0/http/server.ts";
const handler = async (req) => {
  if (req.method === "GET" && req.url === "/long-poll") {
    const response = new Response();
    // Simulate a delay
    setTimeout(() => {
      response.body = "Data received";
      response.headers.set("Content-Type", "text/plain");
      response.headers.set("Connection", "close");
      req.respond(response);
    }, 2000);
    return response;
  }
  return new Response("Not Found");
};
await serve(handler);


// client-side in Bun
import { fetch } from "https://deno.land/std@0.128.0/http/fetch.ts";
async function longPoll() {
  const response = await fetch("http://localhost:8000/long-poll");
  console.log("Long Polling response:", await response.text());
}
setInterval(longPoll, 2000);

Comparison Table

| Feature | SSE | WebSocket | Long Polling | |---------|-----|-----------|--------------| | Full-Duplex | No | Yes | No | | Server-Initiated | Yes | Yes | Yes | | Scalability | Moderate | High | Low | | Implementation Complexity | Low | High | Low | | Use Cases | Stock price updates, news feeds | Real-time gaming, chat applications | Low-latency, server-initiated events |

Lessons Learned

  • Understand the Use Case: Choose the right method based on the specific requirements of your application.
  • Consider Scalability: WebSockets offer better scalability for real-time, two-way communication.
  • Balance Implementation Complexity: SSE is simple to implement but limited in full-duplex communication.
  • Avoid Overhead: Long Polling can be inefficient in terms of server load for applications with high traffic.

    • Actionable Takeaways

  • When implementing real-time updates in your application, evaluate the communication requirements to decide between SSE, WebSocket, or Long Polling.
  • For one-way, infrequent updates, SSE is a good choice.
  • For real-time, two-way communication, WebSockets are more suitable.
  • If server load is a concern, consider Long Polling for server-initiated events.
  • Always test the chosen method to ensure it meets the performance and scalability requirements of your application.
