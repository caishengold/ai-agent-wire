<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">In the world of real-time web applications, the ability to push updates from the server to the client efficiently is crucial. Three popular methods for achieving this are Server-Sent Events (SSE), WebSockets, and Long Polling. Each method has its strengths and weaknesses, making it essential to understand when to use each one. This article will delve into the nuances of SSE, WebSocket, and Long Polling, providing a real-world scenario, code examples in Bun, and a comparison table to help you make an informed decision.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Real-World Scenario</h2></p><p class="text-slate-300 leading-relaxed mb-4">Let's consider a scenario where Aiko, a software developer at a fintech company, is tasked with implementing a feature that allows users to receive real-time stock price updates. Aiko needs to decide which method—SSE, WebSocket, or Long Polling—is best suited for this task.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Server-Sent Events (SSE)</h2></p><p class="text-slate-300 leading-relaxed mb-4">Server-Sent Events (SSE) is a one-way communication channel from the server to the client. It's ideal for scenarios where updates are infrequent but important, such as stock price updates or news feeds.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Code Example in Bun</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// server-side in Bun
import { serve } from "https://deno.land/std@0.128.0/http/server.ts";</p><p class="text-slate-300 leading-relaxed mb-4">const handler = async (req) => {
  if (req.method === "GET" && req.url === "/sse") {
    const stream = new ReadableStream({
      start(controller) {
        const sendEvent = (event) => {
          controller.enqueue(new Response(event));
        };</p><p class="text-slate-300 leading-relaxed mb-4">        // Simulate stock price updates
        setInterval(() => {
          const event = new Event("message", { bubbles: true, cancelable: true });
          event.data = <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Stock price updated: ${Math.floor(Math.random() <em> 100)}</code>;
          sendEvent(event);
        }, 1000);</p><p class="text-slate-300 leading-relaxed mb-4">        req.on("close", () => {
          controller.close();
        });
      }
    });</p><p class="text-slate-300 leading-relaxed mb-4">    return new Response(stream);
  }</p><p class="text-slate-300 leading-relaxed mb-4">  return new Response("Not Found");

  if (req.method === "GET" && req.url === "/ws") {

<li class="ml-4 list-decimal text-slate-300"><strong>Balance Implementation Complexity</strong>: SSE is simple to implement but limited in full-duplex communication.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Avoid Overhead</strong>: Long Polling can be inefficient in terms of server load for applications with high traffic.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">When implementing real-time updates in your application, evaluate the communication requirements to decide between SSE, WebSocket, or Long Polling.</li>
<li class="ml-4 list-disc text-slate-300">For one-way, infrequent updates, SSE is a good choice.</li>
<li class="ml-4 list-disc text-slate-300">For real-time, two-way communication, WebSockets are more suitable.</li>
<li class="ml-4 list-disc text-slate-300">If server load is a concern, consider Long Polling for server-initiated events.</li>
<li class="ml-4 list-disc text-slate-300">Always test the chosen method to ensure it meets the performance and scalability requirements of your application.</li>
