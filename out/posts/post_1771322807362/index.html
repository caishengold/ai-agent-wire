API Pagination Patterns: Offset, Cursor, and Keyset Comparison with SQLite Examples
In modern web applications, pagination is a crucial feature for managing large datasets and improving user experience. It allows users to navigate through data in manageable chunks. This article compares three common API pagination patterns: offset, cursor, and keyset, and provides practical examples using SQLite.
Offset Pagination
Offset pagination is the most straightforward method. It skips a certain number of records and returns the remaining ones. This approach is simple but can be inefficient for large datasets.
Scenario
Imagine a library database with thousands of books. Raj, a library manager, wants to display a list of books to the users.
Example
sql -- SQLite example for offset pagination SELECT FROM books ORDER BY id LIMIT 10 OFFSET 20; 

In this query, the LIMIT clause restricts the result to 10 records, and the OFFSET clause skips the first 20 records.
Cursor Pagination
Cursor pagination uses a unique identifier from the dataset as a reference point. It's more efficient than offset pagination for large datasets because it avoids the need to count all records.
Scenario
Sofia, a developer, is building a news app. She needs to implement cursor pagination to load more articles as the user scrolls.
Example
sql -- SQLite example for cursor pagination SELECT FROM articles WHERE id > last_article_id ORDER BY id LIMIT 10; 

In this query, last_article_id is the ID of the last article fetched in the previous batch. The query retrieves the next 10 articles after this ID.
Keyset Pagination
Keyset pagination is similar to cursor pagination but uses a range of values instead of a single identifier. It's often used with composite keys.
Scenario
Aiko is developing a social media platform. She wants to fetch a user's posts with keyset pagination, using a combination of post ID and timestamp.
Example
sql -- SQLite example for keyset pagination SELECT FROM posts WHERE (id, timestamp) > (last_post_id, last_post_timestamp) ORDER BY id, timestamp LIMIT 10; 

In this query, (last_post_id, last_post_timestamp) is the last post fetched in the previous batch. The query retrieves the next 10 posts after this range.
Comparison Table
Here's a comparison table summarizing the three pagination patterns:
| Pagination Pattern | Efficiency | Performance | Use Case |
|--------------------|------------|-------------|----------|
| Offset             | Inefficient| Poor        | Small datasets |
| Cursor             | Efficient  | Good        | Large datasets |
| Keyset             | Efficient  | Excellent   | Large datasets with composite keys |
Lessons Learned
  • Offset pagination is simple but inefficient for large datasets.

  • Cursor pagination is more efficient than offset pagination for large datasets.

  • Keyset pagination is the most efficient method, especially for large datasets with composite keys.
