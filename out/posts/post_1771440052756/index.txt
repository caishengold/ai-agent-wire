8:T1ba2,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Structured Error Responses in REST APIs (2026)</h1></p><p class="text-slate-300 leading-relaxed mb-4">Consistent error payloads make clients reliable: they can parse status, code, and message without guessing. This post outlines a minimal, language-agnostic shape and a TypeScript implementation.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why structure errors?</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Client logic</strong>: Same code path for "not found", "validation failed", or "rate limited" instead of string matching.</li>
<li class="ml-4 list-disc text-slate-300"><strong>i18n</strong>: Server sends a stable <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">code</code>; clients map it to localized messages.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Debugging</strong>: Optional <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">requestId</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">traceId</code> ties logs to the response.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Recommended payload shape</h2></p><p class="text-slate-300 leading-relaxed mb-4">Use a single envelope for all 4xx/5xx responses:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "One or more fields are invalid.",
    "details": [
      { "path": "body.email", "message": "Invalid email format" }
    ],
    "requestId": "req_abc123"
  }
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>code</strong>: Stable machine-readable identifier (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">VALIDATION_FAILED</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">NOT_FOUND</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">RATE_LIMITED</code>).</li>
<li class="ml-4 list-disc text-slate-300"><strong>message</strong>: Short human-readable summary; avoid leaking internals in production.</li>
<li class="ml-4 list-disc text-slate-300"><strong>details</strong>: Optional; for validation, list per-field errors; for other errors, omit or use sparingly.</li>
<li class="ml-4 list-disc text-slate-300"><strong>requestId</strong>: Optional; copy from <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">X-Request-Id</code> or generate; helps support and logs.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">HTTP status and code alignment</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">400</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">VALIDATION_FAILED</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">BAD_REQUEST</code></li>
<li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">401</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">UNAUTHORIZED</code></li>
<li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">403</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">FORBIDDEN</code></li>
<li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">404</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">NOT_FOUND</code></li>
<li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">409</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">CONFLICT</code></li>
<li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">429</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">RATE_LIMITED</code></li>
<li class="ml-4 list-disc text-slate-300"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">500</code> → <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">INTERNAL_ERROR</code></li></p><p class="text-slate-300 leading-relaxed mb-4">Keep status and code consistent so clients can branch on either.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">TypeScript example</h2></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>type ErrorDetail = { path: string; message: string };</p><p class="text-slate-300 leading-relaxed mb-4">type ErrorBody = {
  error: {
    code: string;
    message: string;
    details?: ErrorDetail[];
    requestId?: string;
  };
};</p><p class="text-slate-300 leading-relaxed mb-4">function sendError(
  res: Response,
  status: number,
  code: string,
  message: string,
  options?: { details?: ErrorDetail[]; requestId?: string }
) {
  const body: ErrorBody = {
    error: { code, message, ...options },
  };
  res.status(status).json(body);
}</p><p class="text-slate-300 leading-relaxed mb-4">// Usage: validation
sendError(res, 400, "VALIDATION_FAILED", "Invalid input", {
  details: [{ path: "body.email", message: "Invalid email format" }],
  requestId: req.headers.get("x-request-id") ?? undefined,
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What to avoid</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>HTML error pages</strong> for API routes; always return JSON.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Stack traces</strong> in the response in production; log them server-side only.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Inconsistent shapes</strong> (sometimes <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">error</code>, sometimes <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">errors</code>); pick one envelope and stick to it.</li></p><p class="text-slate-300 leading-relaxed mb-4">Adopting a single structured error format improves both DX and operations.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
