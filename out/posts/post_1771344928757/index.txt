<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">Aiko Chen, lead developer at a mid-size fintech startup, faced a familiar problem in early 2024. Her team needed to deploy a lightweight analytics dashboard for internal use, but the infrastructure costs for PostgreSQL seemed excessive for a tool that would only handle a few thousand queries daily. The deployment needed to be simple, the database needed to start instantly without configuration, and the entire stack had to fit in a single Docker container.</p><p class="text-slate-300 leading-relaxed mb-4">After evaluating several options, Aiko chose Bun as her runtime and SQLite as the database. Three months later, the dashboard handles 50,000 daily operations with p99 latencies under 15ms. This article walks through exactly how she built it, the mistakes she made along the way, and the patterns that made the difference between a sluggish prototype and a production-ready system.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Setting Up the Project</h2></p><p class="text-slate-300 leading-relaxed mb-4">Aiko initialized the project using Bun's built-in package manager. The entire setup took less than two minutes.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>mkdir analytics-dashboard && cd analytics-dashboard
bun init -y
bun add sqlite better-sqlite3
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">She chose <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">better-sqlite3</code> over <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">sqlite3</code> for synchronous operations, which works better with Bun's event loop. For async-heavy workloads, the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">sqlite</code> package with the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">sqlite3</code> driver remains a solid choice.</p><p class="text-slate-300 leading-relaxed mb-4">The project structure looked like this:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>analytics-dashboard/
├── src/

</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Building the Database Layer</h2></p><p class="text-slate-300 leading-relaxed mb-4">Aiko created a dedicated database module that handles connection management and schema initialization. This pattern prevents connection leaks and ensures the database is ready before any queries execute.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// src/db.js
import Database from 'better-sqlite3';</p><p class="text-slate-300 leading-relaxed mb-4">let db = null;</p><p class="text-slate-300 leading-relaxed mb-4">export function getDb() {
  if (!db) {
    db = new Database('./analytics.db');
    db.pragma('journal_mode = WAL');
    db.pragma('synchronous = NORMAL');
    initializeSchema(db);
  }
  return db;
}</p><p class="text-slate-300 leading-relaxed mb-4">function initializeSchema(database) {
  database.exec(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">

      created_at DATETIME DEFAULT CURRENT_TIMESTAMP
    )
  </code>);</p><p class="text-slate-300 leading-relaxed mb-4">  database.exec(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
    CREATE TABLE IF NOT EXISTS users (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      username TEXT NOT NULL UNIQUE,
      password_hash TEXT NOT NULL,

  if (db) {

import { getDb } from './db.js';</p><p class="text-slate-300 leading-relaxed mb-4">export function createProduct(name, price, stock, category = 'general') {
  const db = getDb();
  const stmt = db.prepare(
    'INSERT INTO products (name, price, stock, category) VALUES (?, ?, ?, ?)'

  const result = stmt.run(name, price, stock, category);

  return stmt.get(id);
}</p><p class="text-slate-300 leading-relaxed mb-4">export function getAllProducts(category = null, limit = 100) {
  const db = getDb();
  if (category) {
    const stmt = db.prepare(
      'SELECT </em> FROM products WHERE category = ? ORDER BY created_at DESC LIMIT ?'
    );
    return stmt.all(category, limit);
  }
  const stmt = db.prepare(
    'SELECT <em> FROM products ORDER BY created_at DESC LIMIT ?'
  );
  return stmt.all(limit);
}</p><p class="text-slate-300 leading-relaxed mb-4">export function updateProduct(id, updates) {
  const db = getDb();
  const fields = [];
  const values = [];</p><p class="text-slate-300 leading-relaxed mb-4">  if (updates.name !== undefined) {
    fields.push('name = ?');
    values.push(updates.name);
  }
  if (updates.price !== undefined) {
    fields.push('price = ?');
    values.push(updates.price);
  }
  if (updates.stock !== undefined) {
    fields.push('stock = ?');
    values.push(updates.stock);
  }</p><p class="text-slate-300 leading-relaxed mb-4">  if (fields.length === 0) return false;</p><p class="text-slate-300 leading-relaxed mb-4">  values.push(id);
  const stmt = db.prepare(
    <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">UPDATE products SET ${fields.join(', ')} WHERE id = ?</code>
  );
  const result = stmt.run(...values);
  return result.changes > 0;
}</p><p class="text-slate-300 leading-relaxed mb-4">export function deleteProduct(id) {
  const db = getDb();
  const stmt = db.prepare('DELETE FROM products WHERE id = ?');
  const result = stmt.run(id);
  return result.changes > 0;
}</p><p class="text-slate-300 leading-relaxed mb-4">export function getLowStockProducts(threshold = 10) {
  const db = getDb();
  const stmt = db.prepare(
    'SELECT </em> FROM products WHERE stock < ? ORDER BY stock ASC'
  );
  return stmt.all(threshold);

</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">updateProduct</code> function uses a dynamic query builder pattern. This approach handles partial updates gracefully—if you only want to update the price, you don't need to specify name or stock.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">User Authentication</h2></p><p class="text-slate-300 leading-relaxed mb-4">For authentication, Aiko implemented password hashing using bcrypt. Never store plain-text passwords, even in internal tools.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// src/auth.js
import { getDb } from './db.js';
import bcrypt from 'bcryptjs';</p><p class="text-slate-300 leading-relaxed mb-4">const SALT_ROUNDS = 10;</p><p class="text-slate-300 leading-relaxed mb-4">export function createUser(username, password, role = 'user') {
  const db = getDb();
  const passwordHash = bcrypt.hashSync(password, SALT_ROUNDS);</p><p class="text-slate-300 leading-relaxed mb-4">  try {
    const stmt = db.prepare(
      'INSERT INTO users (username, password_hash, role) VALUES (?, ?, ?)'
    );
    const result = stmt.run(username, passwordHash, role);
    return { success: true, userId: result.lastInsertRowid };
  } catch (error) {
    if (error.code === 'SQLITE_CONSTRAINT_UNIQUE') {
      return { success: false, error: 'Username already exists' };
    }
    throw error;
  }
}</p><p class="text-slate-300 leading-relaxed mb-4">export function verifyCredentials(username, password) {
  const db = getDb();
  const stmt = db.prepare('SELECT <em> FROM users WHERE username = ?');
  const user = stmt.get(username);</p><p class="text-slate-300 leading-relaxed mb-4">  if (!user) {
    return { valid: false, user: null };
  }</p><p class="text-slate-300 leading-relaxed mb-4">  const valid = bcrypt.compareSync(password, user.password_hash);
  return { valid, user: valid ? user : null };
}</p><p class="text-slate-300 leading-relaxed mb-4">export function getUserById(id) {
  const db = getDb();
  const stmt = db.prepare('SELECT id, username, role FROM users WHERE id = ?');
  return stmt.get(id);
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The authentication module returns structured results rather than throwing exceptions for invalid credentials. This pattern makes it easier to handle different failure modes in the API layer.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Performance Comparisons</h2></p><p class="text-slate-300 leading-relaxed mb-4">Aiko ran benchmarks to understand the impact of indexing on query performance. She tested four common operations against a table with 10,000 products.</p><p class="text-slate-300 leading-relaxed mb-4">| Operation | Without Index (ms) | With Index (ms) | Improvement |
|-----------|-------------------|-----------------|-------------|
| Insert Product | 0.8 | 0.9 | -12% |
| Find by ID | 4.2 | 0.3 | 93% |
| Find by Category | 6.1 | 2.8 | 54% |
| Delete by ID | 3.8 | 0.4 | 89% |</p><p class="text-slate-300 leading-relaxed mb-4">The results showed that indexing dramatically improves read and delete operations, with a small overhead on inserts. For read-heavy workloads like Aiko's analytics dashboard, the trade-off clearly favors indexing.</p><p class="text-slate-300 leading-relaxed mb-4">She added indexes for the most common query patterns:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// Add these after table creation in db.js
db.exec('CREATE INDEX IF NOT EXISTS idx_products_category ON products(category)');

db.exec('CREATE INDEX IF NOT EXISTS idx_events_timestamp ON events(timestamp)');
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Transactions and Data Integrity</h2></p><p class="text-slate-300 leading-relaxed mb-4">When Aiko needed to record an event and update user statistics atomically, she discovered the importance of transactions:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// src/events.js
import { getDb } from './db.js';</p><p class="text-slate-300 leading-relaxed mb-4">export function recordEventWithUserUpdate(userId, eventType, payload) {
  const db = getDb();
  
  const transaction = db.transaction(() => {
    const insertStmt = db.prepare(
      'INSERT INTO events (user_id, event_type, payload) VALUES (?, ?, ?)'
    );
    const eventResult = insertStmt.run(userId, eventType, JSON.stringify(payload));</p><p class="text-slate-300 leading-relaxed mb-4">    const updateStmt = db.prepare(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
      UPDATE users 
      SET events_count = COALESCE(events_count, 0) + 1 
      WHERE id = ?
    </code>);
    updateStmt.run(userId);</p><p class="text-slate-300 leading-relaxed mb-4">    return eventResult.lastInsertRowid;
  });</p><p class="text-slate-300 leading-relaxed mb-4">  return transaction();
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Using <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">db.transaction()</code> ensures that either both operations succeed or both fail. Without this wrapper, a failure after the first operation would leave the database in an inconsistent state.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Common Pitfalls</h2></p><p class="text-slate-300 leading-relaxed mb-4">Aiko encountered several issues that cost her debug time. Here's what to avoid:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Forgetting to close the database</strong> — In long-running Bun processes, unclosed connections accumulate. Always call <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">closeDb()</code> during shutdown.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Using async/await with better-sqlite3</strong> — This library is synchronous by design. Wrapping it in async functions adds overhead without benefit.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Ignoring WAL checkpointing</strong> — The WAL file grows indefinitely without periodic checkpoints. Add <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">db.pragma('wal_checkpoint(TRUNCATE)')</code> during maintenance windows.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Storing large objects as JSON strings</strong> — Querying within JSON fields is slow. Use separate tables for data you need to filter.</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Assuming single-file means single-user</strong> — SQLite handles concurrent reads well, but write locking is table-level. Design for write patterns accordingly.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">WAL mode and proper pragmas improved throughput by 3x compared to default settings</li>
<li class="ml-4 list-disc text-slate-300">Dynamic query building for partial updates saved code duplication and reduced bugs</li>
<li class="ml-4 list-disc text-slate-300">Transactions prevented data inconsistency during multi-step operations</li>
<li class="ml-4 list-disc text-slate-300">Indexing provided 90%+ improvement on read queries with minimal insert overhead</li>
<li class="ml-4 list-disc text-slate-300">Password hashing with bcrypt is non-negotiable, even for internal tools</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Enable WAL mode immediately</strong> — Add <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">db.pragma('journal_mode = WAL')</code> before any other configuration</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Profile before optimizing</strong> — Use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">EXPLAIN QUERY PLAN</code> to understand SQLite's query strategy before adding indexes</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Use transactions for multi-statement operations</strong> — The <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">transaction()</code> wrapper in better-sqlite3 makes this trivial</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Implement graceful shutdown</strong> — Call database close handlers when your Bun process receives SIGTERM</li></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Hash all passwords</strong> — Never store plain-text credentials, and use sufficient salt rounds (10+)</li></p><p class="text-slate-300 leading-relaxed mb-4">Aiko's analytics dashboard has been running stably for three months with zero maintenance incidents.
