8:T4999,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Exploring Modular Architecture Patterns with Bun CLI for Scalable Web Applications</h1></p><p class="text-slate-300 leading-relaxed mb-4">As applications grow, monolithic codebases become difficult to maintain. Developers find themselves wading through thousands of lines of tightly coupled code to make simple changes. Modular architecture provides a solution by breaking applications into independent, replaceable modules.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Bun</strong>, the all-in-one JavaScript runtime, ships with a built-in package manager and bundler. These tools make modular development practical without the overhead of traditional toolchains.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">The Case for Modular Design</h2></p><p class="text-slate-300 leading-relaxed mb-4">Raj Patel, a senior engineer at a Singapore-based logistics platform, faced this challenge during 2025-Q2. His team was building a multi-tenant API serving 200+ enterprise clients. Each client needed custom integrations with varying data formats, authentication schemes, and notification preferences.</p><p class="text-slate-300 leading-relaxed mb-4">The initial codebase was a single Express application with 15,000 lines. Adding a new integration required touching authentication, database models, and webhook handlers. Deployments became risky. A change in one area could cascade into unrelated features.</p><p class="text-slate-300 leading-relaxed mb-4">Raj's team restructured the application into modules:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Authentication module</strong>: OAuth2, API keys, and session management</li>
<li class="ml-4 list-disc text-slate-300"><strong>Data transformation module</strong>: Format converters for client-specific schemas</li>
<li class="ml-4 list-disc text-slate-300"><strong>Notification module</strong>: Email, SMS, and webhook dispatchers</li>
<li class="ml-4 list-disc text-slate-300"><strong>Audit module</strong>: Logging and compliance tracking</li></p><p class="text-slate-300 leading-relaxed mb-4">Each module exposed a clean interface. Modules communicated through events, not direct imports. The codebase became testable. Teams could work in parallel without merge conflicts.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Bun's Built-in Module Management</h2></p><p class="text-slate-300 leading-relaxed mb-4">Traditional Node.js workflows require separate tools: npm or yarn for package management, webpack or esbuild for bundling, Jest for testing. Bun consolidates these into a single binary.</p><p class="text-slate-300 leading-relaxed mb-4">| Feature | Traditional Stack | Bun |
|---------|------------------|-----|
| Package manager | npm/yarn/pnpm | Built-in |
| Bundler | webpack/esbuild/rollup | Built-in |
| Test runner | Jest/Vitest | Built-in |
| TypeScript | ts-node or transpile | Native |
| Cold start | 2-5 seconds | <200ms |
| Workspace support | Lerna/Rush/pnpm | Native <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun workspaces</code> |</p><p class="text-slate-300 leading-relaxed mb-4">Bun's workspace support simplifies modular monorepos. You define workspaces in a root <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">package.json</code>:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>{
  "name": "logistics-platform",
  "workspaces": [
    "packages/<em>",
    "integrations/</em>"
  ],
  "scripts": {
    "dev": "bun run --filter '<em>' dev",
    "test": "bun test",
    "build": "bun run --filter '</em>' build"
  }
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Each module lives as an independent package with its own <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">package.json</code>, dependencies, and build configuration. Bun resolves workspace dependencies automatically.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Pattern 1: Plugin Architecture</h2></p><p class="text-slate-300 leading-relaxed mb-4">A plugin architecture loads modules dynamically at runtime. This pattern works well when you have optional features or need third-party extensibility.</p><p class="text-slate-300 leading-relaxed mb-4">Sofia Kim, building a document processing pipeline for a legal tech startup in 2025-09, needed to support multiple file formats. New formats emerged quarterly. Hardcoding converters would require frequent deployments.</p><p class="text-slate-300 leading-relaxed mb-4">She implemented a plugin system using Bun's dynamic imports:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// packages/core/src/plugin-manager.ts
import { readdir } from 'node:fs/promises';
import { join } from 'node:path';</p><p class="text-slate-300 leading-relaxed mb-4">export interface FileConverter {
  name: string;
  supportedExtensions: string[];
  convert(input: Buffer): Promise<Buffer>;
}</p><p class="text-slate-300 leading-relaxed mb-4">export class PluginManager {
  private converters = new Map<string, FileConverter>();</p><p class="text-slate-300 leading-relaxed mb-4">  async loadPlugins(pluginsDir: string): Promise<void> {
    const entries = await readdir(pluginsDir, { withFileTypes: true });
    
    for (const entry of entries) {
      if (entry.isDirectory()) {
        const pluginPath = join(pluginsDir, entry.name, 'index.ts');
        
        try {
          const module = await import(pluginPath);
          const converter: FileConverter = module.default;
          
          for (const ext of converter.supportedExtensions) {
            this.converters.set(ext.toLowerCase(), converter);
          }
          
          console.log(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Loaded converter: ${converter.name}</code>);
        } catch (error) {
          console.error(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Failed to load plugin ${entry.name}:</code>, error);
        }
      }
    }
  }</p><p class="text-slate-300 leading-relaxed mb-4">  getConverter(extension: string): FileConverter | undefined {
    return this.converters.get(extension.toLowerCase());
  }
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Individual plugins implement the interface:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// integrations/pdf-converter/index.ts
import type { FileConverter } from '@legaltech/core';
import { pdfToText } from 'pdf-parse';</p><p class="text-slate-300 leading-relaxed mb-4">const pdfConverter: FileConverter = {
  name: 'PDF Text Extractor',
  supportedExtensions: ['.pdf'],
  
  async convert(input: Buffer): Promise<Buffer> {
    const text = await pdfToText(input);
    return Buffer.from(text, 'utf-8');
  }
};</p><p class="text-slate-300 leading-relaxed mb-4">export default pdfConverter;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Adding a new format requires dropping a folder into the integrations directory. No core code changes. No redeployment.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Pattern 2: Domain-Driven Modules</h2></p><p class="text-slate-300 leading-relaxed mb-4">Domain-driven design organizes code around business capabilities. Each module owns its data, logic, and interfaces.</p><p class="text-slate-300 leading-relaxed mb-4">Chen Wang's healthcare data platform on 2026-01-12 served hospitals, insurance providers, and researchers. Each user type accessed patient data differently:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Clinical module</strong>: Real-time vitals and medication tracking</li>
<li class="ml-4 list-disc text-slate-300"><strong>Billing module</strong>: Insurance claims and payment processing  </li>
<li class="ml-4 list-disc text-slate-300"><strong>Research module</strong>: Anonymised aggregate datasets</li></p><p class="text-slate-300 leading-relaxed mb-4">Chen structured the codebase with clear boundaries:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>packages/
├── clinical/
│   ├── src/
│   │   ├── domain/
│   │   │   ├── patient.ts
│   │   │   ├── vitals.ts
│   │   │   └── medication.ts
│   │   ├── api/
│   │   │   └── routes.ts
│   │   └── persistence/
│   │       └── repository.ts
│   ├── package.json
│   └── tsconfig.json
├── billing/
│   └── ...
└── research/
    └── ...
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Each module has internal structure invisible to others. The clinical module exports only what external code needs:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// packages/clinical/src/index.ts
export { Patient } from './domain/patient';
export { VitalsService } from './services/vitals';
export { createClinicalRoutes } from './api/routes';</p><p class="text-slate-300 leading-relaxed mb-4">// Internal types stay hidden
// export { InternalCache } from './cache';
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Bun's bundler creates optimised builds per module:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>{
  "scripts": {
    "build": "bun build ./src/index.ts --outdir ./dist --target node"
  }
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Pattern 3: Event-Driven Communication</h2></p><p class="text-slate-300 leading-relaxed mb-4">Direct function calls create tight coupling. Events let modules react to changes without knowing the source.</p><p class="text-slate-300 leading-relaxed mb-4">Priya Sharma's e-commerce platform on 2025-11-03 processed orders through multiple services. When a customer placed an order:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300">Inventory module checked stock</li>
<li class="ml-4 list-decimal text-slate-300">Payment module processed the charge</li>
<li class="ml-4 list-decimal text-slate-300">Shipping module created a label</li>
<li class="ml-4 list-decimal text-slate-300">Notification module sent confirmations</li></p><p class="text-slate-300 leading-relaxed mb-4">Direct API calls between services created a fragile dependency chain. If the shipping service was down, the entire order failed.</p><p class="text-slate-300 leading-relaxed mb-4">She replaced synchronous calls with an event bus:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// packages/event-bus/src/index.ts
type EventHandler<T> = (payload: T) => void | Promise<void>;</p><p class="text-slate-300 leading-relaxed mb-4">export class EventBus {
  private handlers = new Map<string, Set<EventHandler<any>>>();</p><p class="text-slate-300 leading-relaxed mb-4">  on<T>(event: string, handler: EventHandler<T>): () => void {
    if (!this.handlers.has(event)) {
      this.handlers.set(event, new Set());
    }
    this.handlers.get(event)!.add(handler);
    
    return () => this.handlers.get(event)?.delete(handler);
  }</p><p class="text-slate-300 leading-relaxed mb-4">  async emit<T>(event: string, payload: T): Promise<void> {
    const handlers = this.handlers.get(event);
    if (!handlers) return;
    
    await Promise.all(
      Array.from(handlers).map(handler => 
        Promise.resolve(handler(payload)).catch(err => {
          console.error(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Handler error for ${event}:</code>, err);
        })
      )
    );
  }
}</p><p class="text-slate-300 leading-relaxed mb-4">export const eventBus = new EventBus();
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Modules publish events without knowing subscribers:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// packages/orders/src/service.ts
import { eventBus } from '@platform/event-bus';</p><p class="text-slate-300 leading-relaxed mb-4">export async function createOrder(customerId: string, items: LineItem[]) {
  const order = await db.insert('orders', { customerId, items });
  
  await eventBus.emit('order.created', {
    orderId: order.id,
    customerId,
    items,
    timestamp: new Date().toISOString()
  });
  
  return order;
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Other modules subscribe independently:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// packages/shipping/src/index.ts
import { eventBus } from '@platform/event-bus';</p><p class="text-slate-300 leading-relaxed mb-4">eventBus.on('order.created', async ({ orderId, items }) => {
  const label = await generateShippingLabel(items);
  await saveLabel(orderId, label);
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">If the shipping module is offline, the event persists in a queue (using Redis or similar) and processes when available.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Testing Modular Code</h2></p><p class="text-slate-300 leading-relaxed mb-4">Bun's test runner works across workspaces. You run tests from the root:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>bun test
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Or filter to specific modules:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>bun test packages/clinical
bun test --filter "<em>converter</em>"
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Mock external modules in tests:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// packages/orders/src/service.test.ts
import { test, expect, mock } from 'bun:test';
import { createOrder } from './service';</p><p class="text-slate-300 leading-relaxed mb-4">mock.module('@platform/event-bus', () => ({
  eventBus: {
    emit: mock(() => Promise.resolve())
  }
}));</p><p class="text-slate-300 leading-relaxed mb-4">test('createOrder emits event', async () => {
  const order = await createOrder('cust-123', [{ sku: 'ABC', qty: 2 }]);
  expect(order.id).toBeDefined();
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Performance Considerations</h2></p><p class="text-slate-300 leading-relaxed mb-4">Modular architectures add overhead. Multiple node_modules directories increase disk usage. Dynamic imports add runtime cost.</p><p class="text-slate-300 leading-relaxed mb-4">Bun mitigates this through:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Global module cache</strong>: Workspace dependencies are deduplicated</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Fast startup</strong>: Cold starts under 200ms make dynamic loading practical</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Tree shaking</strong>: Dead code is eliminated during bundling</li></p><p class="text-slate-300 leading-relaxed mb-4">Monitor bundle sizes:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>bun build ./src/index.ts --outdir ./dist --analyze
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">Start with 2-3 modules and extract more as patterns emerge — premature modularisation wastes time</li>
<li class="ml-4 list-disc text-slate-300">Define module boundaries around business capabilities, not technical layers</li>
<li class="ml-4 list-disc text-slate-300">Document the public API of each module — other developers depend on these contracts</li>
<li class="ml-4 list-disc text-slate-300">Implement health checks per module — failures should be isolated</li>
<li class="ml-4 list-disc text-slate-300">Use workspace scripts for cross-module operations — <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun run --filter '<em>' build</code> runs all builds in dependency order</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Audit your current architecture</strong> — Identify the top 3 business capabilities that would benefit from independent modules</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Set up a Bun workspace</strong> — Move one existing feature into its own package as an experiment</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Implement an event bus</strong> — Replace one direct service call with event-driven communication</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Measure module coupling</strong> — Track which modules import from each other; reduce cross-module dependencies</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Document module APIs</strong> — Create a README in each package folder explaining what it exports and why</li>
