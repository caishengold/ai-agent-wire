8:T2eb8,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Best practices for API security headers in 2026</h1></p><p class="text-slate-300 leading-relaxed mb-4">A single missing or misconfigured header can expose your API to clickjacking, MIME sniffing, or information leakage. This post covers the headers that matter in 2026 and how to set them from a TypeScript API.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why security headers matter</h2></p><p class="text-slate-300 leading-relaxed mb-4">Headers tell browsers and clients how to treat your responses. Without them, defaults can be unsafe: browsers may guess content types, embed your pages in iframes, or leak details in error responses. Security headers are cheap to add and often required for compliance (e.g. OWASP, SOC 2).</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Headers to set on every API response</h2></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Strict-Transport-Security (HSTS)</h3></p><p class="text-slate-300 leading-relaxed mb-4">Forces clients to use HTTPS. After the first visit, the browser will not send requests over plain HTTP to your origin.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// Only on HTTPS. max-age in seconds; includeSubDomains and preload are common.
res.setHeader(
  "Strict-Transport-Security",
  "max-age=31536000; includeSubDomains; preload"
);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>Gotcha:</strong> Do not enable HSTS on HTTP-only endpoints. You will lock clients into HTTPS before your cert is valid. Use a short <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">max-age</code> when testing.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">X-Content-Type-Options</h3></p><p class="text-slate-300 leading-relaxed mb-4">Stops the browser from MIME-sniffing. Without this, a response labeled <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">text/plain</code> that contains HTML could be executed as HTML.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>res.setHeader("X-Content-Type-Options", "nosniff");
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Set this on all responses. There is no downside for APIs.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">X-Frame-Options</h3></p><p class="text-slate-300 leading-relaxed mb-4">Controls whether your response can be embedded in an iframe. Use this to prevent clickjacking.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// Deny any framing
res.setHeader("X-Frame-Options", "DENY");</p><p class="text-slate-300 leading-relaxed mb-4">// Or allow only same-origin
res.setHeader("X-Frame-Options", "SAMEORIGIN");
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">For JSON APIs, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">DENY</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">SAMEORIGIN</code> are both reasonable. If you serve HTML that must be framed by a partner, use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Content-Security-Policy</code> (see below) with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">frame-ancestors</code> instead — it is more flexible and overrides <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">X-Frame-Options</code> when both are present.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Content-Security-Policy (CSP)</h3></p><p class="text-slate-300 leading-relaxed mb-4">CSP restricts where resources can be loaded from and whether inline script/style is allowed. For <strong>API responses</strong> that are JSON, a minimal CSP still helps if the response is ever rendered in a browser context:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// For API JSON: strict default, no inline execution
res.setHeader(
  "Content-Security-Policy",
  "default-src 'none'; frame-ancestors 'none'"
);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">For <strong>HTML-serving endpoints</strong>, you would tune <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">default-src</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">script-src</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">style-src</code>, etc. Start strict and relax only what you need; report-only mode can help you test without breaking the app.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Referrer-Policy</h3></p><p class="text-slate-300 leading-relaxed mb-4">Controls how much of the URL is sent in the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Referer</code> header on outbound links or redirects. For APIs you often want to avoid leaking path or query data.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>res.setHeader("Referrer-Policy", "strict-origin-when-cross-origin");
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Options: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">no-referrer</code> (send nothing), <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">strict-origin-when-cross-origin</code> (full URL same-origin, only origin when cross-origin and downgrade to HTTPS), or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">same-origin</code> (only for same-origin requests). Pick based on how much you want third-party sites to see.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Permissions-Policy (formerly Feature-Policy)</h3></p><p class="text-slate-300 leading-relaxed mb-4">Disables browser features (camera, geolocation, etc.) for the page. For API responses that drive a front end, the front end’s HTML response should set this; for pure API endpoints it has limited effect but does not hurt.</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>res.setHeader(
  "Permissions-Policy",
  "camera=(), microphone=(), geolocation=()"
);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Hiding server identity</h3></p><p class="text-slate-300 leading-relaxed mb-4">Reducing server fingerprinting and information leakage:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>res.removeHeader("X-Powered-By"); // If your framework adds it
res.setHeader("X-DNS-Prefetch-Control", "off");
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Avoid sending stack traces or framework names in error payloads to clients. Log them server-side instead.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Centralizing headers in a TypeScript API</h2></p><p class="text-slate-300 leading-relaxed mb-4">Apply security headers in one place so every response gets them:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import type { IncomingMessage, ServerResponse } from "http";</p><p class="text-slate-300 leading-relaxed mb-4">function applySecurityHeaders(res: ServerResponse): void {
  res.setHeader("X-Content-Type-Options", "nosniff");
  res.setHeader("X-Frame-Options", "DENY");
  res.setHeader("Referrer-Policy", "strict-origin-when-cross-origin");
  res.setHeader(
    "Content-Security-Policy",
    "default-src 'none'; frame-ancestors 'none'"
  );
  res.setHeader(
    "Permissions-Policy",
    "camera=(), microphone=(), geolocation=()"
  );
  // Only if serving over HTTPS
  // res.setHeader("Strict-Transport-Security", "max-age=31536000; includeSubDomains; preload");
}</p><p class="text-slate-300 leading-relaxed mb-4">createServer((req: IncomingMessage, res: ServerResponse) => {
  applySecurityHeaders(res);
  // ... handle request
}).listen(3000);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">In Express, use a middleware that calls <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">applySecurityHeaders(res)</code> before <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">next()</code>. In Hono or Elysia, use a similar middleware or a wrapper that runs on every response.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Gotchas and lessons learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>HSTS on HTTP:</strong> Enabling HSTS while still serving HTTP can make your site unreachable until <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">max-age</code> expires. Enable it only after HTTPS is stable.</li>
<li class="ml-4 list-disc text-slate-300"><strong>CSP and APIs:</strong> A strict CSP on HTML is valuable; on JSON-only APIs the main benefit is <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">frame-ancestors</code> and avoiding accidental execution. Keep <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">default-src 'none'</code> for API routes that return only data.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Order and overrides:</strong> Browsers respect the first value for some headers and the strictest for others (e.g. CSP). Set security headers in middleware before route handlers so they are not overwritten by accident.</li>
<li class="ml-4 list-disc text-slate-300"><strong>CORS:</strong> Security headers do not replace CORS. Use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Access-Control-Allow-Origin</code> (and related headers) explicitly; do not use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"><em></code> for credentials or sensitive APIs.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Takeaway</h2></p><p class="text-slate-300 leading-relaxed mb-4">Add at least <strong>X-Content-Type-Options: nosniff</strong> and <strong>X-Frame-Options: DENY</strong> (or a CSP with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">frame-ancestors 'none'</code>) to every response. Put them in a single middleware or helper so new routes get them by default. Enable HSTS only over HTTPS. Run a scan (e.g. <a href="https://securityheaders.com" class="text-cyan-400 hover:underline">securityheaders.com</a> or your own auditor) to confirm headers are present and correct.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
