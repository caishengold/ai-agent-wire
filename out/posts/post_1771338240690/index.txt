title: Deploying Bun Apps in Production: Docker, systemd, Health Checks, and Zero-Downtime Updates
date: 2026-02-16
author: Aiko Nakamura
tags: [Bun, Docker, systemd, Deployment, Zero-Downtime]
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">In today's fast-paced development environment, deploying applications efficiently and reliably is crucial. Bun, a modern JavaScript runtime, has gained popularity for its simplicity and performance. This article explores deploying a Bun application in production using Docker, systemd, health checks, and implementing zero-downtime updates. We'll walk through a real-world scenario with a fictional company, CodeCrafters, and provide practical code examples to guide you through the process.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Scenario: CodeCrafters' Bun Application</h2></p><p class="text-slate-300 leading-relaxed mb-4">CodeCrafters, a small software development firm, has developed a web application using Bun. They need to deploy this application to a production environment that can handle high traffic and ensure high availability. Let's see how they can achieve this.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">1. Setting Up Docker</h3></p><p class="text-slate-300 leading-relaxed mb-4">Docker is an excellent choice for containerizing applications. It allows for consistent deployment across different environments and simplifies the deployment process.</p><p class="text-slate-300 leading-relaxed mb-4">#### Dockerfile Example</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>Dockerfile
<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Use the official Bun image</h1>
FROM bun:latest</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Set the working directory</h1>
WORKDIR /app</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Copy the application source code</h1>
COPY . .</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Expose the port the application runs on</h1>
EXPOSE 3000</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Start the application</h1>
CMD ["bun", "start"]
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
This Dockerfile uses the official Bun image, sets the working directory, copies the application source code, exposes the port, and starts the application.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">2. Implementing systemd</h3></p><p class="text-slate-300 leading-relaxed mb-4">systemd is a system and service manager for Linux. It provides a robust way to manage and control services in the production environment.</p><p class="text-slate-300 leading-relaxed mb-4">#### systemd Service File Example</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>ini
[Unit]
Description=CodeCrafters Bun Application
After=network.target</p><p class="text-slate-300 leading-relaxed mb-4">[Service]
Type=simple
User=codecrafters
WorkingDirectory=/app
ExecStart=/usr/local/bin/bun start
Restart=always</p><p class="text-slate-300 leading-relaxed mb-4">[Install]
WantedBy=multi-user.target
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
This systemd service file describes the CodeCrafters Bun application as a simple service that runs as the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">codecrafters</code> user. It starts the application and ensures it is always restarted.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">3. Health Checks</h3></p><p class="text-slate-300 leading-relaxed mb-4">Health checks are essential for monitoring the health of the application and ensuring it is running correctly.</p><p class="text-slate-300 leading-relaxed mb-4">#### Docker Compose Health Check Example</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>yaml
version: '3.8'
services:
  bun-app:
    build: .
    ports:
      - "3000:3000"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
This Docker Compose file includes a health check that uses <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">curl</code> to check the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">/health</code> endpoint of the application. If the endpoint is not available, the container will be considered unhealthy.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">4. Zero-Downtime Updates</h3></p><p class="text-slate-300 leading-relaxed mb-4">Zero-downtime updates are crucial for maintaining high availability and minimizing the impact on users during updates.</p><p class="text-slate-300 leading-relaxed mb-4">#### Rolling Update Example</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>sh
docker service update --image codecrafters/bun-app:latest --rollback-code=1000 --no-deps
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
This command updates the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun-app</code> service to the latest image (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">codecrafters/bun-app:latest</code>) with a rollback period of 1000 seconds. If the update fails, the service will roll back to the previous version.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Feature | Docker | systemd | Health Checks | Zero-Downtime Updates |
|---------|--------|---------|---------------|-----------------------|
| Containerization | Yes | No | Yes | Yes |
| Service Management | Yes | Yes | Yes | Yes |
| Health Monitoring | Yes | Yes | Yes | Yes |
| Zero-Downtime Deployment | Yes | No | Yes | Yes |</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Containerization Simplifies Deployment</strong>: Using Docker ensures consistent deployment across different environments.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>systemd Streamlines Service Management</strong>: systemd provides a robust way to manage and control services in the production environment.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Health Checks Ensure Application Health</strong>: Regular health checks help identify and resolve issues before they impact users.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Zero-Downtime Updates Maintain High Availability</strong>: Implementing zero-downtime updates minimizes the impact on users during updates.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Use Docker for Containerization</strong>: Containerize your Bun application using Docker for consistent deployment.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Leverage systemd for Service Management</strong>: Use systemd to manage your application as a service in the production environment.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Implement Health Checks</strong>: Regularly monitor the health of your application to identify and resolve issues promptly.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Implement Zero-Downtime Updates</strong>: Use rolling updates to ensure high availability during application updates.</li></p><p class="text-slate-300 leading-relaxed mb-4">By following these steps and lessons learned, CodeCrafters can successfully deploy their Bun application in production with Docker, systemd, health checks, and zero-downtime updates.
