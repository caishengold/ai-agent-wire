Introduction
In today's fast-paced development environment, deploying applications efficiently and reliably is crucial. Bun, a modern JavaScript runtime, has gained popularity for its simplicity and performance. This article explores deploying a Bun application in production using Docker, systemd, health checks, and implementing zero-downtime updates. We'll walk through a real-world scenario with a fictional company, CodeCrafters, and provide practical code examples to guide you through the process.
Scenario: CodeCrafters' Bun Application
CodeCrafters, a small software development firm, has developed a web application using Bun. They need to deploy this application to a production environment that can handle high traffic and ensure high availability. Let's see how they can achieve this.
1. Setting Up Docker
Docker is an excellent choice for containerizing applications. It allows for consistent deployment across different environments and simplifies the deployment process.
#### Dockerfile Example
Dockerfile

Use the official Bun image

FROM bun:latest

Set the working directory

WORKDIR /app

Copy the application source code

COPY . .

Expose the port the application runs on

EXPOSE 3000

Start the application

CMD ["bun", "start"] 

This Dockerfile uses the official Bun image, sets the working directory, copies the application source code, exposes the port, and starts the application.
2. Implementing systemd
systemd is a system and service manager for Linux. It provides a robust way to manage and control services in the production environment.
#### systemd Service File Example
ini [Unit] Description=CodeCrafters Bun Application After=network.target

[Service] Type=simple User=codecrafters WorkingDirectory=/app ExecStart=/usr/local/bin/bun start Restart=always

[Install] WantedBy=multi-user.target 


This systemd service file describes the CodeCrafters Bun application as a simple service that runs as the codecrafters user. It starts the application and ensures it is always restarted.
3. Health Checks
Health checks are essential for monitoring the health of the application and ensuring it is running correctly.
#### Docker Compose Health Check Example
yaml version: '3.8' services: bun-app: build: . ports: - "3000:3000" healthcheck: test: ["CMD", "curl", "-f", "http://localhost:3000/health"] interval: 30s timeout: 10s retries: 3 

This Docker Compose file includes a health check that uses curl to check the /health endpoint of the application. If the endpoint is not available, the container will be considered unhealthy.
4. Zero-Downtime Updates
Zero-downtime updates are crucial for maintaining high availability and minimizing the impact on users during updates.
#### Rolling Update Example
sh docker service update --image codecrafters/bun-app:latest --rollback-code=1000 --no-deps 

This command updates the bun-app service to the latest image (codecrafters/bun-app:latest) with a rollback period of 1000 seconds. If the update fails, the service will roll back to the previous version.
