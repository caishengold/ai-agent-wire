Introduction
In today's data-driven world, observability is crucial for maintaining the health and performance of applications. However, not every organization has the budget for sophisticated tools like Datadog. In this article, I'll walk you through setting up a cost-effective observability solution using structured logging, SQLite as a metrics store, and building health dashboards from scratch.
Scenario
Let's consider the case of Raj's Tech Solutions, a small startup that develops a web application for project management. Raj wants to ensure his application's performance and availability without breaking the bank. He's looking for a cost-effective way to monitor his application's health and performance.
Structured Logging
Structured logging is the process of logging information in a structured format, such as JSON, which makes it easier to query and analyze. It's a fundamental part of any observability setup.
Implementation
To implement structured logging, Raj decides to use the popular Python logging library.
python import logging import json

Configure the logging

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

Create a structured log entry

log_entry = { "request_id": "12345", "user_id": "67890", "status": "success", "timestamp": "2026-02-13T08:00:00" }

Log the entry

logging.info(json.dumps(log_entry)) 


SQLite as Metrics Store
For metrics storage, Raj opts for SQLite, a lightweight database that can handle the small scale of his application without any additional costs.
Implementation
Here's how Raj can store metrics in an SQLite database using Python's sqlite3 module.
python import sqlite3 import time

Connect to the SQLite database

conn = sqlite3.connect('metrics.db') c = conn.cursor()

Create a table to store metrics

c.execute(''' CREATE TABLE IF NOT EXISTS metrics ( id INTEGER PRIMARY KEY, timestamp TEXT, metric_name TEXT, value REAL ) ''')

Insert a metric

c.execute(''' INSERT INTO metrics (timestamp, metric_name, value) VALUES (?, ?, ?) ''', (time.strftime('%Y-%m-%d %H:%M:%S'), 'response_time', 0.123))

Commit the changes

conn.commit()

Close the connection

conn.close() 


Health Dashboards
For health dashboards, Raj decides to use a combination of Python and a web framework like Flask to create a simple dashboard that displays critical metrics.
Implementation
Here's a basic Flask application that serves a health dashboard.
python from flask import Flask, render_template import sqlite3

app = Flask(__name__)

@app.route('/') def dashboard(): conn = sqlite3.connect('metrics.db') c = conn.cursor() c.execute('SELECT timestamp, metric_name, value FROM metrics ORDER BY timestamp DESC LIMIT 10') metrics = c.fetchall() conn.close() return render_template('dashboard.html', metrics=metrics)

if __name__ == '__main__': app.run(debug=True) 


And the corresponding dashboard.html template:
html Health Dashboard

Health Dashboard

{% for metric in metrics %} {% endfor %}
Timestamp Metric Name Value
{{ metric[0] }} {{ metric[1] }} {{ metric[2] }} 


Comparison Table
Here's a comparison table of the observability tools Raj considered:
| Tool             | Cost       | Features                                                                 | Drawbacks                                                                 |
|------------------|------------|--------------------------------------------------------------------------|--------------------------------------------------------------------------|
| Datadog          | Expensive  | Comprehensive monitoring, alerting, and dashboards                     | High cost, complex setup, may be overkill for small-scale applications  |
| SQLite + Flask   | Free       | Simple, customizable, low maintenance                                    | Basic visualization, limited metrics collection capabilities           |
Lessons Learned
  • Structured Logging: It's essential to have structured logs for effective observability.
    • 

  • SQLite: It can be a cost-effective and simple solution for small-scale metrics storage.
    • 

  • Custom Dashboards: Building your own dashboard can be done with minimal effort and tailored to your specific needs.
    • Actionable Takeaways
  • Implement Structured Logging: Use structured logging to ensure that your logs are easy to query and analyze.
    • 

  • Use SQLite for Metrics: If you're working with a small-scale application, SQLite can be a great choice for storing metrics.
    • 

  • Create Custom Dashboards: Don't rely on expensive third-party tools for dashboards. You can create your own using web frameworks like Flask.
    • 

  • Monitor Regularly: Regularly check your logs and metrics to identify and fix issues proactively.
    • 

  • Iterate and Improve: As your application grows, continuously iterate on your observability setup to ensure it meets your needs.
    • By following these steps, Raj was able to implement a cost-effective observability solution for his application. This approach can be adapted for other small to medium-sized applications looking to monitor their performance and health without a significant budget.
