8:T3132,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Full-Text Search with SQLite FTS5</h1></p><p class="text-slate-300 leading-relaxed mb-4">You have a SQLite database with thousands of rows — logs, notes, or product descriptions. A simple <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE '%keyword%'</code> scan works for tiny tables but locks up on real data. You need search that feels instant and ranks results by relevance. SQLite’s FTS5 extension does exactly that, and you can ship it without adding Elasticsearch or another service.</p><p class="text-slate-300 leading-relaxed mb-4">This post walks through FTS5 setup, indexing, ranking, and a small end-to-end example so you can drop full-text search into an existing app.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why FTS5?</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 is SQLite’s built-in full-text search engine. It tokenizes text, builds an inverted index, and supports ranking and phrase queries. No extra process, no network hop — same file, same process. For single-node apps or embedded use cases, that’s a big win. If your data fits in SQLite, FTS5 often fits too.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Setup: enable and create a virtual table</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 is compiled into most SQLite builds. Check with:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT fts5_version();
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">If that works, create a <strong>virtual table</strong> for full-text search. You don’t store rows in a normal table and “sync” to FTS; the FTS table is the index. A common pattern is to keep your main table and use an FTS5 table that either mirrors the searchable columns or references the main table by rowid.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Option A — FTS5 table as the primary store (simple, good for “documents”):</strong></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>CREATE VIRTUAL TABLE docs_fts USING fts5(
  title,
  body,
  content='',
  content_rowid='rowid'
);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><strong>Option B — FTS5 table synced from a regular table (good when you already have a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">documents</code> table):</strong></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>-- Your existing table
CREATE TABLE documents (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  created_at TEXT
);</p><p class="text-slate-300 leading-relaxed mb-4">-- FTS5 shadow table for search only
CREATE VIRTUAL TABLE documents_fts USING fts5(
  title,
  body,
  content='documents',
  content_rowid='id'
);</p><p class="text-slate-300 leading-relaxed mb-4">-- Triggers to keep FTS in sync (SQLite 3.35+)
CREATE TRIGGER documents_ai AFTER INSERT ON documents BEGIN
  INSERT INTO documents_fts(rowid, title, body) VALUES (new.id, new.title, new.body);
END;
CREATE TRIGGER documents_ad AFTER DELETE ON documents BEGIN
  INSERT INTO documents_fts(documents_fts, rowid, title, body) VALUES ('delete', old.id, old.title, old.body);
END;
CREATE TRIGGER documents_au AFTER UPDATE ON documents BEGIN
  INSERT INTO documents_fts(documents_fts, rowid, title, body) VALUES ('delete', old.id, old.title, old.body);
  INSERT INTO documents_fts(rowid, title, body) VALUES (new.id, new.title, new.body);
END;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Once the FTS table exists, you <strong>insert into it</strong> (option A) or rely on triggers (option B). Queries go to the FTS table.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Indexing: what gets tokenized</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 tokenizes the text you insert. By default it splits on whitespace and lowercases. So “Full-Text Search” becomes two tokens: “full-text” and “search”. You can use the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">porter</code> tokenizer for simple stemming (e.g. “running” → “run”) if you want:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>CREATE VIRTUAL TABLE docs_fts USING fts5(title, body, tokenize='porter');
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Insert your content as usual. For option A, insert into <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs_fts</code>. For option B, insert into <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">documents</code> and let the triggers update <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">documents_fts</code>.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Querying and ranking</h2></p><p class="text-slate-300 leading-relaxed mb-4">Search with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH</code>:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT rowid, title, snippet(docs_fts, 2, '<b>', '</b>', '…', 32)
FROM docs_fts
WHERE docs_fts MATCH 'keyword'
ORDER BY rank
LIMIT 20;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">rank</code> is a special column that reflects relevance (lower is better in FTS5). So <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ORDER BY rank</code> gives you best matches first. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bm25()</code> is another ranking function you can use for finer control:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>SELECT rowid, title, bm25(docs_fts) AS score
FROM docs_fts
WHERE docs_fts MATCH 'sqlite search'
ORDER BY score
LIMIT 20;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Phrase search uses double quotes: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH '"full text"'</code>. Prefix search uses <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"><em></code>: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH 'key</em>'</code>. Combine as needed: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH 'sqlite AND fts5'</code>.</p><p class="text-slate-300 leading-relaxed mb-4"><code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">snippet()</code> is useful for UI: it returns a short fragment with the match wrapped in your chosen markers (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"><b>…</b></code>).</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Real-world example: search over task titles and descriptions</h2></p><p class="text-slate-300 leading-relaxed mb-4">Assume a <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">tasks</code> table with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">id</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">title</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">description</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">status</code>. We add an FTS5 table and keep it in sync:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>CREATE VIRTUAL TABLE tasks_fts USING fts5(
  title,
  description,
  content='tasks',
  content_rowid='id'
);</p><p class="text-slate-300 leading-relaxed mb-4">CREATE TRIGGER tasks_fts_ai AFTER INSERT ON tasks BEGIN
  INSERT INTO tasks_fts(rowid, title, description) VALUES (new.id, new.title, new.description);
END;
CREATE TRIGGER tasks_fts_ad AFTER DELETE ON tasks BEGIN
  INSERT INTO tasks_fts(tasks_fts, rowid, title, description) VALUES ('delete', old.id, old.title, old.description);
END;
CREATE TRIGGER tasks_fts_au AFTER UPDATE ON tasks BEGIN
  INSERT INTO tasks_fts(tasks_fts, rowid, title, description) VALUES ('delete', old.id, old.title, old.description);
  INSERT INTO tasks_fts(rowid, title, description) VALUES (new.id, new.title, new.description);
END;
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Application code (e.g. Node/Bun with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">better-sqlite3</code>):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>const db = require('better-sqlite3')('app.db');
const query = process.argv[2] || 'deploy';
const stmt = db.prepare(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">
  SELECT t.id, t.title, t.status,
         snippet(tasks_fts, 2, '<b>', '</b>', '…', 24) AS snippet
  FROM tasks_fts f
  JOIN tasks t ON t.id = f.rowid
  WHERE tasks_fts MATCH ?
  ORDER BY bm25(tasks_fts)
  LIMIT 10
</code>);
console.log(stmt.all(query));
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Users get ranked results and a snippet without maintaining a separate search service.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Gotchas and lessons learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Schema changes</strong>: Adding or removing columns from the content table means recreating the FTS table and triggers and re-populating. Plan the schema up front if you can.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Rank direction</strong>: FTS5’s <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">rank</code> is “lower is better”. So <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ORDER BY rank</code> is correct for “best first”; don’t expect a higher number to mean more relevant.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Empty or NULL</strong>: If you use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content='table'</code>, the content table must already exist and the FTS table is populated from it (or via triggers). Inserting into the FTS table when using external content can be confusing — prefer triggers for sync.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Rebuilds</strong>: If you corrupt or change tokenizer options, you typically rebuild the FTS table from the source table. So keep the source of truth in a regular table if you might need to rebuild.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Takeaway</h2></p><p class="text-slate-300 leading-relaxed mb-4">Enable FTS5, create a virtual table (standalone or synced via triggers), insert or sync your text, then query with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">MATCH</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">ORDER BY rank</code> or <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bm25()</code>. Use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">snippet()</code> for result previews. That’s enough to add fast, ranked full-text search to a SQLite-backed app without new infrastructure.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
