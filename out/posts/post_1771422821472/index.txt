title: Real-Time API Comparison: WebSocket vs. Server-Sent Events (SSE)

<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">In the fast-paced world of web development, real-time communication is a crucial aspect. Two popular technologies for achieving this are WebSocket and Server-Sent Events (SSE). Both offer different advantages and use cases. This article will compare WebSocket and SSE, using a real-world scenario to illustrate their practical applications. We will delve into the code, provide a comparison table, and draw lessons from our exploration.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Real-World Scenario</h2></p><p class="text-slate-300 leading-relaxed mb-4">Imagine you're working on a stock market application for Aiko's Trading Platform. The platform needs to provide real-time stock price updates to users, ensuring they have the latest information at all times. To handle this, we'll consider how WebSocket and SSE can be used to implement real-time communication.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">WebSocket Implementation</h2></p><p class="text-slate-300 leading-relaxed mb-4">WebSocket is a full-duplex communication protocol that allows for real-time data exchange between the client and server. Here's how we can implement it in our scenario:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// Server-side WebSocket setup (Node.js example)
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8080 });</p><p class="text-slate-300 leading-relaxed mb-4">wss.on('connection', function connection(ws) {
  ws.on('message', function incoming(message) {
    console.log('received: %s', message);
  });</p><p class="text-slate-300 leading-relaxed mb-4">  // Simulate stock price updates
  setInterval(() => {
    const priceUpdate = <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Stock price updated: ${Math.random().toFixed(2)}</code>;
    ws.send(priceUpdate);
  }, 1000);
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><!-- Client-side WebSocket connection (HTML/JavaScript example) -->
<script>
  const ws = new WebSocket('ws://localhost:8080');</p><p class="text-slate-300 leading-relaxed mb-4">  ws.onopen = function() {
    console.log('Connected to WebSocket server');
  };</p><p class="text-slate-300 leading-relaxed mb-4">  ws.onmessage = function(event) {
    console.log('Received stock price update:', event.data);
  };</p><p class="text-slate-300 leading-relaxed mb-4">  ws.onerror = function(error) {
    console.error('WebSocket error:', error);
  };
</script>
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Server-Sent Events (SSE) Implementation</h2></p><p class="text-slate-300 leading-relaxed mb-4">Server-Sent Events (SSE) is a simpler, one-way communication protocol that allows the server to push updates to the client. Here's how we can implement SSE for our stock market application:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// Server-side SSE setup (Node.js example)
const http = require('http');
const server = http.createServer((req, res) => {
  if (req.url === '/stock-updates') {
    res.writeHead(200, {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive'
    });</p><p class="text-slate-300 leading-relaxed mb-4">    // Simulate stock price updates
    setInterval(() => {
      const priceUpdate = <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">data: Stock price updated: ${Math.random().toFixed(2)}\n\n</code>;
      res.write(priceUpdate);
    }, 1000);
  }
});</p><p class="text-slate-300 leading-relaxed mb-4">server.listen(8080);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><!-- Client-side SSE connection (HTML/JavaScript example) -->
<script>
  const eventSource = new EventSource('http://localhost:8080/stock-updates');</p><p class="text-slate-300 leading-relaxed mb-4">  eventSource.onmessage = function(event) {
    console.log('Received stock price update:', event.data);
  };</p><p class="text-slate-300 leading-relaxed mb-4">  eventSource.onerror = function(error) {
    console.error('SSE error:', error);
  };
</script>
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Feature         | WebSocket                        | SSE                           |
|-----------------|----------------------------------|-------------------------------|
| Communication   | Full-duplex (both ways)          | One-way (server to client)    |
| Complexity      | Higher (requires more setup)     | Simpler (easier to implement) |
| Latency         | Lower (real-time communication) | Higher (not real-time)         |
| Compatibility   | Modern browsers (with support)   | Older browsers (with support)  |
| Use Cases       | Real-time gaming, chat apps     | Stock market updates, news feeds |</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>WebSocket is ideal for bidirectional communication</strong>: In scenarios where both the client and server need to send data at any time, WebSocket is the way to go.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>SSE is simpler for one-way communication</strong>: For applications where real-time updates are required but not both-way communication, SSE offers a more straightforward solution.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Consider browser support</strong>: While both technologies are widely supported, there may be differences in how they are implemented across different browsers.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Assess your communication needs</strong>: Determine whether your application requires full-duplex communication or one-way updates.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Understand the trade-offs</strong>: Be aware of the complexity and latency implications of each technology.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Test across different browsers</strong>: Ensure that your chosen technology works seamlessly across the browsers your users are likely to use.</li></p><p class="text-slate-300 leading-relaxed mb-4">By comparing WebSocket and SSE in the context of a real-world scenario, we've gained insights into their practical applications. Both technologies have their place in the real-time communication landscape, and the choice between them should be based on the specific needs of your
