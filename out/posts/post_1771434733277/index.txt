8:T4393,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Full-Text Search with SQLite FTS5 — setup, indexing, ranking, real-world example</h1></p><p class="text-slate-300 leading-relaxed mb-4">Relational databases handle exact matches well. When users need to find documents containing specific words, phrases, or partial terms, the standard SQL <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE</code> operator quickly becomes a bottleneck. SQLite addresses this gap with its <strong>FTS5</strong> (Full-Text Search version 5) extension — a lightweight, zero-configuration search engine built directly into the database.</p><p class="text-slate-300 leading-relaxed mb-4">This guide walks you through setting up FTS5, understanding how it indexes content, and implementing relevance ranking in a real application.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">How FTS5 Works</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 creates an inverted index that maps terms to the documents containing them. Instead of scanning every row like a traditional <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE '%query%'</code> search, FTS5 locates matching documents in near-constant time.</p><p class="text-slate-300 leading-relaxed mb-4">Consider a simple example: a table with 100,000 articles. A <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">LIKE</code> query searching for "machine learning" scans all 100,000 rows. The same query against an FTS5 virtual table identifies matching documents directly from the index, typically completing in milliseconds regardless of table size.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">FTS5 vs Standard LIKE</h3></p><p class="text-slate-300 leading-relaxed mb-4">| Aspect | LIKE '%pattern%' | FTS5 |
|--------|-----------------|------|
| Query performance | O(n) full table scan | O(1) index lookup |
| Wildcard support | Limited (trailing only) | Full prefix, suffix matching |
| Ranking | None | BM25 relevance scoring |
| Phrase matching | Requires complex queries | Native phrase operators |
| Index maintenance | None | Automatic with writes |
| Storage overhead | None | 20-50% additional |</p><p class="text-slate-300 leading-relaxed mb-4">The trade-off is straightforward: FTS5 uses more storage and slightly slows write operations, but delivers search performance that scales.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Setting Up FTS5</h2></p><p class="text-slate-300 leading-relaxed mb-4">Creating an FTS5 virtual table follows a familiar pattern. Suppose Raj Patel, a backend engineer at a growing SaaS company, needs to add search to his application's knowledge base. His team stores help articles in a regular table and needs fast, relevant search.</p><p class="text-slate-300 leading-relaxed mb-4">First, the base table holds the source data:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import sqlite3</p><p class="text-slate-300 leading-relaxed mb-4">conn = sqlite3.connect("knowledge_base.db")
cursor = conn.cursor()</p><p class="text-slate-300 leading-relaxed mb-4">cursor.execute("""
    CREATE TABLE IF NOT EXISTS articles (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        content TEXT NOT NULL,
        category TEXT,
        created_at TEXT DEFAULT (datetime('now'))
    )
""")
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Next, the FTS5 virtual table stores the searchable content:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>cursor.execute("""
    CREATE VIRTUAL TABLE IF NOT EXISTS articles_fts USING fts5(
        title,
        content,
        category,
        content='articles',
        content_rowid='id'
    )
""")
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content_rowid</code> parameters link the FTS5 table to the base table, enabling synchronized updates.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Synchronizing Data</h3></p><p class="text-slate-300 leading-relaxed mb-4">Keeping the FTS5 index current requires triggers. When rows are inserted, updated, or deleted in the base table, the triggers maintain the search index:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>cursor.execute("""

    END
""")</p><p class="text-slate-300 leading-relaxed mb-4">cursor.execute("""

        INSERT INTO articles_fts(rowid, title, content, category)

""")</p><p class="text-slate-300 leading-relaxed mb-4">conn.commit()

The simplest is a single term:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>def search_articles(query: str, limit: int = 10):
    cursor.execute("""
        SELECT a.id, a.title, a.category,
               bm25(articles_fts) as rank
        FROM articles_fts
        JOIN articles a ON articles_fts.rowid = a.id
        WHERE articles_fts MATCH ?
        ORDER BY rank
        LIMIT ?
    """, (query, limit))
    
    return cursor.fetchall()</p><p class="text-slate-300 leading-relaxed mb-4">results = search_articles("machine learning")
for row in results:
    print(f"{row[1]} ({row[2]}) - Score: {row[3]:.2f}")
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bm25()</code> function returns relevance scores using the BM25 ranking algorithm. Lower (more negative) scores indicate better matches.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Query Operators</h3></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 supports powerful query syntax:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">AND operator: both terms must appear</h1>
results = search_articles("api AND authentication")</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">OR operator: either term appears</h1>
results = search_articles("database OR migration")</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Phrase matching: exact phrase</h1>
results = search_articles('"machine learning"')</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Prefix matching: terms starting with prefix</h1>
results = search_articles("data<em>")</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">NOT operator: exclude term</h1>
results = search_articles("api NOT rate")
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Building a Search Interface</h3></p><p class="text-slate-300 leading-relaxed mb-4">Aiko Tanaka, the frontend developer on Raj's team, builds a search endpoint. <li class="ml-4 list-decimal text-slate-300"><strong>Inverse document frequency (IDF)</strong> — How rare is the term across the corpus?</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Document length</strong> — Are matches in shorter or longer documents?</li></p><p class="text-slate-300 leading-relaxed mb-4">This combination rewards documents with multiple occurrences of rare terms while penalizing matches in lengthy documents where the term appears infrequently.</p><p class="text-slate-300 leading-relaxed mb-4">FTS5 exposes ranking through the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bm25()</code> function. For custom ranking, you can modify the query:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>cursor.execute("""

    FROM articles_fts
    WHERE articles_fts MATCH ?
    ORDER BY rank
""", ("query",))
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The parameters adjust term frequency saturation (default 1.2), document length normalization (default 0.75), and a constant term weight.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Performance Considerations</h2></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 performs well out of the box, but a few configurations help:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Rebuild the index after bulk inserts for optimal performance</h1>

<li class="ml-4 list-disc text-slate-300"><strong>Prefix searches have a cost</strong> — trailing wildcards (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">data<em></code>) work well, but leading wildcards (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm"></em>data</code>) require more processing</li>
<li class="ml-4 list-disc text-slate-300"><strong>BM25 scoring is query-dependent</strong> — the same document scores differently for different queries, which is the intended behavior</li>
<li class="ml-4 list-disc text-slate-300"><strong>Combine FTS5 with regular columns</strong> in queries when you need to filter by category, date, or other attributes alongside text search</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Create your FTS5 table with content linking</strong> — Use the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content</code> and <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">content_rowid</code> parameters to enable automatic index maintenance via triggers</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Index content and title separately</strong> — Weight title matches higher by including them as a separate column or adjusting BM25 parameters</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Add category filters in the WHERE clause</strong> — FTS5 handles text matching while regular SQL filters narrow results by other attributes</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Test with realistic query volumes</strong> — Small datasets mask performance issues that appear at scale</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Consider custom tokenizers for non-English content</strong> — The porter stemmer and unicode61 tokenizer handle most international text</li></p><p class="text-slate-300 leading-relaxed mb-4">FTS5 provides production-ready full-text search without external services or complex infrastructure. For applications where Elasticsearch or Algolia would be overkill, SQLite FTS5 delivers excellent results with minimal operational overhead.
