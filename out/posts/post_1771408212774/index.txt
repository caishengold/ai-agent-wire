8:T1e66,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">OpenTelemetry Tracing in TypeScript Services</h1></p><p class="text-slate-300 leading-relaxed mb-4">Distributed tracing is essential for understanding request flow across services, finding bottlenecks, and debugging production issues. OpenTelemetry (OTel) provides a vendor-neutral standard for traces, metrics, and logs. This post shows how to add tracing to TypeScript backends (Node.js or Bun) with minimal boilerplate.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why OpenTelemetry?</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Vendor-neutral</strong>: Export to Jaeger, Zipkin, Datadog, Honeycomb, or OTLP collectors without changing application code.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Context propagation</strong>: Trace IDs flow across HTTP headers, message queues, and async boundaries so you see a single trace per user request.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Low overhead</strong>: Sampling and async batching keep production impact small.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Basic Setup (Node.js)</h2></p><p class="text-slate-300 leading-relaxed mb-4">Install the core SDK and HTTP instrumentation:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>npm install @opentelemetry/api @opentelemetry/sdk-node @opentelemetry/auto-instrumentations-node
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Bootstrap tracing <strong>before</strong> any other imports (e.g. in <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">instrumentation.ts</code> or the top of your entry file):</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { NodeSDK } from "@opentelemetry/sdk-node";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";</p><p class="text-slate-300 leading-relaxed mb-4">const sdk = new NodeSDK({
  serviceName: "my-api",
  traceExporter: /<em> your exporter, e.g. OTLP or Console </em>/,
  instrumentations: [getNodeAutoInstrumentations()],
});
sdk.start();
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Auto-instrumentation will create spans for <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">http</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">pg</code>, <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">redis</code>, and other popular libraries. You can then run your app with <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">node --import ./instrumentation.js dist/index.js</code> (or register the file so it runs first).</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Manual Spans</h2></p><p class="text-slate-300 leading-relaxed mb-4">For custom business logic, create spans explicitly:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { trace } from "@opentelemetry/api";</p><p class="text-slate-300 leading-relaxed mb-4">const tracer = trace.getTracer("my-api", "1.0.0");</p><p class="text-slate-300 leading-relaxed mb-4">function processOrder(orderId: string) {
  return tracer.startActiveSpan("processOrder", { attributes: { "order.id": orderId } }, (span) => {
    try {
      // ... work ...
      span.setStatus({ code: SpanStatusCode.OK });
      return result;
    } catch (err) {
      span.setStatus({ code: SpanStatusCode.ERROR, message: (err as Error).message });
      span.recordException(err as Error);
      throw err;
    } finally {
      span.end();
    }
  });
}
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Always call <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">span.end()</code> (or use the callback pattern above) and set status and record exceptions so failures show up in the trace.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Bun Compatibility</h2></p><p class="text-slate-300 leading-relaxed mb-4">Bun is compatible with the same OpenTelemetry API. Use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@opentelemetry/sdk-node</code> and the same <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">NodeSDK</code>; auto-instrumentations may partially work. For full coverage on Bun, prefer manual spans and the OTLP exporter. Ensure your instrumentation file runs before any other code (e.g. via <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">bun --preload ./instrumentation.ts run src/index.ts</code>).</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Context Propagation</h2></p><p class="text-slate-300 leading-relaxed mb-4">For outbound HTTP calls, inject the current context into headers so the next service continues the trace:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { propagation } from "@opentelemetry/api";</p><p class="text-slate-300 leading-relaxed mb-4">propagation.inject(context.active(), headers);
// then use headers in fetch() or your HTTP client
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">The receiving service should use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">propagation.extract()</code> and set the extracted context as active so new spans attach to the same trace.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Sampling in Production</h2></p><p class="text-slate-300 leading-relaxed mb-4">Use a probabilistic or rate-based sampler to avoid overwhelming your backend:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>import { TraceIdRatioBasedSampler } from "@opentelemetry/sdk-trace-node";</p><p class="text-slate-300 leading-relaxed mb-4">// e.g. 10% of traces
const sampler = new TraceIdRatioBasedSampler(0.1);
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">Configure this in the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">NodeSDK</code> via <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">traceOptions</code> so high-throughput services stay within budget while still giving representative traces.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Summary</h2></p><p class="text-slate-300 leading-relaxed mb-4">Adding OpenTelemetry tracing to TypeScript services involves: (1) installing the SDK and auto-instrumentations, (2) starting the SDK before other imports, (3) using manual spans for critical business operations, and (4) enabling context propagation and sampling. With this in place, you get vendor-neutral, end-to-end visibility into request flow and failures.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
