title: Deploying Bun Apps in Production: Docker, systemd, Health Checks, and Zero-Downtime Updates
date: 2026-02-13
slug: bun-apps-production-deployment
categories: [Deployment, Bun, Docker, Systemd]
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Real-World Scenario</h2></p><p class="text-slate-300 leading-relaxed mb-4">Let's consider Aiko, a software engineer at TechSolutions Inc., who has developed a web application using Bun, a modern JavaScript runtime. The application is a customer relationship management (CRM) system that is set to be deployed in production. Aiko needs to ensure that the deployment is robust, scalable, and maintains high availability. This is where the journey of deploying Bun apps in production begins.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Dockerization</h2></p><p class="text-slate-300 leading-relaxed mb-4">To containerize the Bun application, Aiko decides to use Docker. Docker provides a lightweight and portable way to package and run applications. Here's how Aiko creates a Dockerfile for the Bun app:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Use the official Bun image</h1>
FROM bun:latest</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Set the working directory</h1>
WORKDIR /app</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Copy the application source code to the container</h1>
COPY . .</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Install dependencies</h1>
RUN npm install</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Expose the port the app runs on</h1>
EXPOSE 3000</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Start the application</h1>
CMD ["bun", "start"]
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">This Dockerfile ensures that the Bun runtime is used, the application code is copied to the container, dependencies are installed, and the application is started.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Systemd for Management</h2></p><p class="text-slate-300 leading-relaxed mb-4">To manage the Docker container as a service, Aiko uses systemd. Systemd is a system and service manager for Linux operating systems. Here's an example of a systemd service file for the Bun application:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>[Unit]
Description=Bun CRM Application
After=network.target</p><p class="text-slate-300 leading-relaxed mb-4">[Service]
User=aiko
WorkingDirectory=/app
ExecStart=/usr/local/bin/docker-compose up -d
Restart=always</p><p class="text-slate-300 leading-relaxed mb-4">[Install]
WantedBy=multi-user.target
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">This service file starts the Docker container in detached mode, ensuring that the application runs continuously even if the service manager restarts.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Health Checks</h2></p><p class="text-slate-300 leading-relaxed mb-4">To ensure the application's health, Aiko implements health checks. Health checks are essential for monitoring the application's status and for implementing zero-downtime updates. Here's an example of a health check using Docker Compose:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>version: '3.8'
services:
  bun-crm:
    build: .
    ports:
      - "3000:3000"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4">This configuration runs a health check every 30 seconds, with a timeout of 10 seconds and retries after 3 failures.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Zero-Downtime Updates</h2></p><p class="text-slate-300 leading-relaxed mb-4">For zero-downtime updates, Aiko leverages Docker's rolling update feature. This ensures that the application is updated without any downtime. Here's how Aiko updates the application:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300">Stop the old container.</li>
<li class="ml-4 list-decimal text-slate-300">Start a new container with the updated application.</li>
<li class="ml-4 list-decimal text-slate-300">Once the new container is running, remove the old container.</li></p><p class="text-slate-300 leading-relaxed mb-4">Here's a shell script that Aiko uses to perform the update:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>#!/bin/bash</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Stop the old container</h1>
docker-compose down</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Build the new container</h1>
docker-compose build</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Start the new container</h1>
docker-compose up -d</p><p class="text-slate-300 leading-relaxed mb-4"><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Remove the old container</h1>
docker-compose down --remove-orphans
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Feature          | Docker             | Systemd            | Health Checks      | Zero-Downtime Updates |
|------------------|--------------------|--------------------|-------------------|----------------------|
| Containerization | Lightweight, portable | System and service management | Monitor application health | Update without downtime |
| Portability      | Runs on any system with Docker | Runs on any system with systemd | Configurable | Configurable |
| Scalability      | Easy to scale | Configurable scaling | Configurable | Configurable |</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Docker is essential for containerization</strong>: It simplifies the deployment process and ensures consistency across environments.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Systemd is a powerful tool for managing services</strong>: It provides robust features for starting, stopping, and monitoring services.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Health checks are crucial for monitoring</strong>: They help in identifying issues early and implementing zero-downtime updates.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Zero-downtime updates are achievable</strong>: With Docker and systemd, it's possible to update applications without any downtime.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Containerize your applications using Docker</strong>: It simplifies deployment and ensures consistency.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Use systemd for managing services</strong>: It provides robust features for service management.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Implement health checks</strong>: They help in monitoring the application's health and identifying issues early.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Leverage Docker's rolling update feature</strong>: It allows for zero-downtime updates, ensuring continuous availability of the application.</li></p><p class="text-slate-300 leading-relaxed mb-4">By following these steps and best practices, Aiko successfully deployed the Bun application in production, ensuring a robust, scalable, and high-availability system.
