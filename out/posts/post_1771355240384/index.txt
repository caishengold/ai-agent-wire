title: Comprehensive DevOps audit templates for cloud-native environments
date: 2026-02-13
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4">Audit season hits. Someone asks for a security and compliance snapshot of your Kubernetes clusters, container registries, and CI pipelines. You open five tabs, grep through configs, and hand over a mix of screenshots and "we think we're good" — not a repeatable checklist. We've been there. This post gives you copy-paste audit templates you can run quarterly (or before a big release) so the next ask is a single report, not a scramble.</p><p class="text-slate-300 leading-relaxed mb-4"><strong>Who this is for:</strong> Platform and DevOps engineers running cloud-native stacks (Kubernetes, containers, serverless, CI/CD) who need consistent audit trails for security, cost, and compliance without reinventing the wheel each time.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why audit templates matter in cloud-native</h2></p><p class="text-slate-300 leading-relaxed mb-4">Cloud-native systems change fast: new workloads, updated policies, drift between what's documented and what's running. Ad-hoc audits take days and rarely cover the same dimensions twice. Templates fix that:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Consistency</strong> — Same questions and checks every run, so you can compare "last quarter vs this quarter."</li>
<li class="ml-4 list-disc text-slate-300"><strong>Coverage</strong> — Security, cost, compliance, and reliability in one place so nothing falls through the cracks.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Handoff</strong> — New team members (or auditors) can run the same checklist without tribal knowledge.</li></p><p class="text-slate-300 leading-relaxed mb-4">We focus on <strong>actionable checklists and minimal runnable commands</strong> you can adapt to your environment (AWS EKS, GKE, AKS, or self-hosted K8s).</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Template 1: Cluster and workload security</h2></p><p class="text-slate-300 leading-relaxed mb-4">Use this when auditing who can do what in the cluster and whether workloads follow baseline hardening.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Checklist (mark Pass / Fail / N/A)</h3></p><p class="text-slate-300 leading-relaxed mb-4">| # | Check | How to verify | Notes |
|---|--------|----------------|--------|
| 1 | RBAC least privilege | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get clusterrolebindings -o wide</code>; review subjects and roles | Prefer namespaced Roles over ClusterRoles where possible |
| 2 | No anonymous auth | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get --raw /api/v1 | grep -i anonymous</code> or check API server flags | Disable if not explicitly required |
| 3 | Pod security (restricted) | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get ns -o jsonpath='{range .items[<em>]}{.metadata.name}{"\t"}{.metadata.labels}{"\n"}{end}'</code> | Ensure prod namespaces have <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">pod-security.kubernetes.io/enforce=restricted</code> (or equivalent) |
| 4 | Non-root containers | Check Dockerfile / image: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">USER</code> not root; or use PSS | Scan Dockerfiles or image metadata |
| 5 | Read-only root filesystem where possible | Deployment spec: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">securityContext.readOnlyRootFilesystem: true</code> | Some apps need writable dirs; mount emptyDir for those |
| 6 | No privileged containers in prod | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get pods -A -o json \| jq '.items[].spec.containers[]? \| select(.securityContext.privileged==true)'</code> | Should return empty |
| 7 | Image pull policy and digest pinning | Deployments use <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">imagePullPolicy: Always</code> and digest (<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">@sha256:...</code>) or pinned tag | Avoid <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">latest</code> in prod |
| 8 | Network policies present | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get networkpolicies -A \| wc -l</code> | At least default-deny or per-workload policies in critical namespaces |</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example: quick RBAC dump for review</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Export ClusterRoleBindings and RoleBindings for offline review</h1>
kubectl get clusterrolebindings -o yaml > crb-audit-$(date +%Y%m%d).yaml
kubectl get rolebindings -A -o yaml > rb-audit-$(date +%Y%m%d).yaml
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Template 2: Container registry and image hygiene</h2></p><p class="text-slate-300 leading-relaxed mb-4">Focus: what's in the registry, who can pull/push, and whether images are scanned and signed.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Checklist</h3></p><p class="text-slate-300 leading-relaxed mb-4">| # | Check | How to verify | Notes |
|---|--------|----------------|--------|
| 1 | Registry access is IAM/role-based | Review registry IAM policies (ECR, GCR, ACR, etc.) | No long-lived global pull credentials in CI |
| 2 | Image scanning in pipeline | CI job runs Trivy, Clair, or vendor scanner on build | Fail build on HIGH/CRITICAL |
| 3 | Base images from trusted sources | Inspect Dockerfile <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">FROM</code>; prefer distro LTS or vendor images | Document exceptions |
| 4 | No secrets in images | Scan with TruffleHog or similar; no env vars with "secret" in CI | Use secret managers at runtime |
| 5 | Image retention / lifecycle | Configure retention (e.g. keep last N tags per repo) | Reduces blast radius and cost |
| 6 | Signing (optional but recommended) | Cosign or Notary; verify in admission controller | Enforce "signed only" in prod |</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example: Trivy in CI (GitHub Actions)</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>- name: Run Trivy image scanner
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: 'myregistry/myapp:${{ github.sha }}'
    format: 'sarif'
    output: 'trivy-results.sarif'
    severity: 'CRITICAL,HIGH'
  env:
    TRIVY_EXIT_CODE: '1'
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Template 3: CI/CD and pipeline security</h2></p><p class="text-slate-300 leading-relaxed mb-4">Audit how code gets built, tested, and deployed — and where secrets and permissions live.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Checklist</h3></p><p class="text-slate-300 leading-relaxed mb-4">| # | Check | How to verify | Notes |
|---|--------|----------------|--------|
| 1 | Pipelines use short-lived credentials | No long-lived API keys in env; use OIDC or workload identity where possible | GitHub OIDC, GitLab ID tokens, etc. |
| 2 | Secrets in vault or secret manager | Scan pipeline YAML for literal secrets; use secret store references | e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">${{ secrets.DEPLOY_KEY }}</code> not hardcoded |
| 3 | Build from committed Dockerfile only | Pipeline builds image from repo, not ad-hoc <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docker run</code> | Reproducible builds |
| 4 | Deploy only from main/protected branch or tag | Branch protection + pipeline rules | No deploy from random forks |
| 5 | Approval gate for prod | Manual approval or change-management integration | Document who can approve |
| 6 | Pipeline logs and artifacts retention | Configure retention; no secrets in logs | Mask secrets in log output |</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example: branch rule (GitHub Actions)</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  deploy:
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    runs-on: ubuntu-latest
    # ... deploy steps
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Template 4: Cost and resource efficiency</h2></p><p class="text-slate-300 leading-relaxed mb-4">Cloud-native sprawl burns budget if nobody looks at requests/limits and idle resources.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Checklist</h3></p><p class="text-slate-300 leading-relaxed mb-4">| # | Check | How to verify | Notes |
|---|--------|----------------|--------|
| 1 | CPU/memory requests and limits set | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get pods -A -o custom-columns=...</code> or use Kubecost / OpenCost | Avoid "no limits" in prod |
| 2 | Right-sizing | Compare requests vs actual usage (metrics server or cloud billing) | Downsize over-provisioned workloads |
| 3 | HPA/VPA in place for variable load | <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">kubectl get hpa,vpa -A</code> | Scale to zero or min replicas for batch where possible |
| 4 | Unused volumes and snapshots | List PVs, PVCs, and cloud snapshots; delete detached | Schedule recurring review |
| 5 | Idle or low-utilization nodes | Cluster autoscaler logs; remove single-replica dev namespaces from prod cluster | Consider separate dev cluster |</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Example: list pods without limits</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>kubectl get pods -A -o json | jq -r '
  .items[] | select(.spec.containers[]? | .resources.limits == null) |
  "\(.metadata.namespace)/\(.metadata.name)"
'
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Template 5: Observability and incident readiness</h2></p><p class="text-slate-300 leading-relaxed mb-4">Can you detect and debug issues quickly? This template checks the basics.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Checklist</h3></p><p class="text-slate-300 leading-relaxed mb-4">| # | Check | How to verify | Notes |
|---|--------|----------------|--------|
| 1 | Centralized logging | Logs from pods/clusters flow to one place (e.g. Loki, Elastic, cloud log) | Retention and access controls documented |
| 2 | Metrics and dashboards | Prometheus/Grafana or cloud equivalent; key SLOs on dashboard | Latency, error rate, throughput |
| 3 | Alerts on SLO breach and critical failures | Alertmanager or PagerDuty/Opsgenie; no alert storms | Run a game day to test |
| 4 | Tracing for request flows | Sampling or full trace for critical paths | Trace ID in logs for correlation |
| 5 | Runbooks for top alerts | Each alert has a runbook link or embedded steps | Kept in repo or wiki |</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">How to run these audits</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Schedule</strong> — Run full audit quarterly; security subset (Templates 1–3) after major infra or tooling changes.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Owner</strong> — Assign one person per template (or rotate) so someone owns the outcome.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Store results</strong> — Save checklist results (Pass/Fail/N/A) and command outputs in a dated doc or wiki. Example: <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">audit-2026-02-cluster-security.md</code>.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Track remediation</strong> — Open tickets for every Fail; close only after verification.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Minimal runbook snippet</h3></p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Audit runbook (quarterly)</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300">[ ] Template 1: Cluster security — assignee: ___</li>
<li class="ml-4 list-disc text-slate-300">[ ] Template 2: Registry & images — assignee: ___</li>
<li class="ml-4 list-disc text-slate-300">[ ] Template 3: CI/CD — assignee: ___</li>
<li class="ml-4 list-disc text-slate-300">[ ] Template 4: Cost — assignee: ___</li>
<li class="ml-4 list-disc text-slate-300">[ ] Template 5: Observability — assignee: ___</li>
<li class="ml-4 list-disc text-slate-300">[ ] Consolidate report and share with ___ by ___</li>
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Gotchas we ran into</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>RBAC dumps are huge.</strong> Filter by namespace or use a script to list only bindings that reference human users or broad service accounts; otherwise the YAML is unreadable.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Image scanning in CI is slow.</strong> Run scan in parallel with tests or use a separate "scan" job that doesn't block merge but must pass before deploy. Cache the scanner DB.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Cost tools need permissions.</strong> Give a read-only, scoped account to Kubecost/OpenCost (or cloud billing) so you don't grant more than needed.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Audit fatigue.</strong> If the checklist has 50 items, teams skip. Start with 5–10 must-haves per template and add more as they become habit.</li></p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Takeaway</h2></p><p class="text-slate-300 leading-relaxed mb-4">Pick one template (we suggest Template 1: cluster security) and run it this week. Export your RBAC and pod security context for one namespace, and fix one clear gap. Next quarter, run the full set and compare — you'll have a baseline instead of a one-off scramble.</p><p class="text-slate-300 leading-relaxed mb-4">If you want a single file to share with your team, copy the checklists and runbook snippet above into a repo (e.g. <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">docs/audits/</code>) and version it so improvements stay in one place.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
