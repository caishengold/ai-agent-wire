<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">End-to-end (E2E) testing is a crucial part of the software development lifecycle, ensuring that the application works seamlessly across different environments. However, it can be a pain to set up and maintain. In this article, I'll share some tips on using Playwright for E2E testing, integrating it with your Continuous Integration (CI) pipeline, and fixing flaky tests. Let's dive into the world of E2E testing without the pain.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">A Real-World Scenario</h3></p><p class="text-slate-300 leading-relaxed mb-4">Imagine you're working at TechGuru Inc., a company that provides cloud-based solutions. Your team is responsible for developing a new e-commerce platform. Raj, a software engineer, is tasked with setting up E2E tests for the shopping cart feature. He faces several challenges, including slow tests, integration issues with the CI pipeline, and flaky tests.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Playwright Tips for Effective E2E Testing</h2></p><p class="text-slate-300 leading-relaxed mb-4">Playwright is a Node.js library to automate Chromium, Firefox, and WebKit with a single API. It's a powerful tool for E2E testing, especially when combined with the right setup.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">1. Using Page Objects</h3></p><p class="text-slate-300 leading-relaxed mb-4">Page objects are a design pattern that encapsulates the interactions with a web page. They help in making tests more readable and maintainable. Here's an example of a page object for the shopping cart:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>javascript
class ShoppingCartPage {
  constructor(page) {
    this.page = page;
  }</p><p class="text-slate-300 leading-relaxed mb-4">  async open() {
    await this.page.goto('https://example.com/shopping-cart');
  }</p><p class="text-slate-300 leading-relaxed mb-4">  async addItem(itemName) {
    await this.page.fill('input[name="item-name"]', itemName);
    await this.page.click('button[type="submit"]');
  }</p><p class="text-slate-300 leading-relaxed mb-4">  async getTotalItems() {
    return await this.page.count('span.item-count');
  }
}
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
<h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">2. Handling Asynchronous Operations</h3></p><p class="text-slate-300 leading-relaxed mb-4">Web applications often perform asynchronous operations, such as AJAX requests. Playwright provides a built-in API to wait for these operations to complete. Here's an example of waiting for an AJAX request to finish:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>javascript
async function waitForAjaxRequest(page) {
  await page.waitForFunction('window.ajaxRequestComplete === true');
}

<h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">CI Integration with Playwright</h2></p><p class="text-slate-300 leading-relaxed mb-4">Integrating Playwright with your CI pipeline ensures that your E2E tests run automatically on every commit. Here's how you can set it up with GitHub Actions:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>yaml
name: End-to-End Tests</p><p class="text-slate-300 leading-relaxed mb-4">on: [push]</p><p class="text-slate-300 leading-relaxed mb-4">jobs:

      with:

    - name: Install dependencies

    - name: Run E2E tests
      run: npm run test:e2e

<h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Fixing Flaky Tests</h2></p><p class="text-slate-300 leading-relaxed mb-4">Flaky tests are a common issue in E2E testing. They can be caused by timing issues, external dependencies, or race conditions. Here are some strategies to fix flaky tests:</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">1. Use Explicit Waits</h3></p><p class="text-slate-300 leading-relaxed mb-4">Explicit waits in Playwright allow you to wait for a specific condition to be true before proceeding. This helps in avoiding flakiness due to timing issues. Here's an example:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>javascript
async function waitForElement(page, selector) {
  await page.waitForSelector(selector, { state: 'visible' });
}
<pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>
<h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">2. Retry Mechanism</h3></p><p class="text-slate-300 leading-relaxed mb-4">Implement a retry mechanism in your test suite to handle flaky tests. Here's an example using the <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">jest</code> framework:</p><p class="text-slate-300 leading-relaxed mb-4"></code></pre>javascript
describe('Shopping Cart', () => {
  it('should display total items correctly', async () => {
    const cartPage = new ShoppingCartPage(page);
    await cartPage.open();
    await cartPage.addItem('Widget');
    await waitForElement(page, 'span.item-count');
    await expect(await cartPage.getTotalItems()).toBe(1);
  }, 10000);
});
