Graceful Shutdown for TypeScript HTTP Servers

Handling process signals and draining connections before exit keeps deployments safe and avoids dropped requests. This post outlines how to implement graceful shutdown for HTTP servers in TypeScript (Node.js or Bun).

Why Graceful Shutdown Matters

When you deploy or scale down, the process receives SIGTERM (or SIGINT on Ctrl+C). If the server exits immediately, in-flight requests are cut off and clients see errors. Graceful shutdown means:

  • Stop accepting new connections so load balancers can route traffic elsewhere.
  • Finish existing requests within a timeout.
  • Close the server and exit cleanly.

    • Without this, rolling deployments and autoscaling can cause user-facing 502s or connection resets.

    Basic Pattern

    The idea is the same in Node and Bun:

  • Create your HTTP server as usual.
  • Listen for SIGTERM and SIGINT.
  • On signal: call server.close() to stop accepting new connections, then give in-flight requests time to complete, then exit (or run any other cleanup).

    • Example skeleton:

    const server = createServer(requestHandler);
    server.listen(port, () => {
  console.log(Listening on ${port});
});
    function shutdown(signal: string) {
  console.log(${signal} received, draining...);
  server.close(() => {
    console.log("Server closed");
    process.exit(0);
  });
  setTimeout(() => {
    console.error("Drain timeout, forcing exit");
    process.exit(1);
  }, 30_000);
}
    process.on("SIGTERM", () => shutdown("SIGTERM"));
process.on("SIGINT", () => shutdown("SIGINT"));

    server.close() only stops new connections; it does not abort active requests. The setTimeout is a safety net: if the server does not close within 30 seconds (e.g. a stuck request), you force exit.

    Tracking In-Flight Requests

    For more control, track open requests and wait for them to finish (or hit a timeout):

    let inFlight = 0;
const server = createServer((req, res) => {
  inFlight++;
  res.on("finish", () => inFlight--);
  requestHandler(req, res);
});
    function drain(): Promise {
  return new Promise((resolve) => {
    const check = () => (inFlight === 0 ? resolve() : setTimeout(check, 50));
    check();
  });
}
    async function shutdown(signal: string) {
  server.close();
  await Promise.race([drain(), sleep(25_000)]);
  process.exit(0);
}

    This way you can log "waiting for N requests" and tune the timeout to your SLA.

    Bun and Node Compatibility

    In Bun, Bun.serve() returns a server object with a .stop() method. You still listen for SIGTERM/SIGINT, then call server.stop(true) (the boolean can control whether to wait for connections). The same idea applies: stop accepting new work, wait for a bounded time, then exit.

    Health Checks During Shutdown

    If you expose a readiness probe (e.g. /ready), flip it to "not ready" as soon as you receive the signal. That way the orchestrator stops sending new traffic before you call server.close(). Combined with a short drain window, you get minimal dropped requests during rolling updates.

    Summary

    Implement graceful shutdown by: (1) handling SIGTERM/SIGINT, (2) stopping the server from accepting new connections, (3) optionally waiting for in-flight requests with a timeout, and (4) exiting. Use a drain timeout to avoid hanging on stuck requests. Doing this in TypeScript (Node or Bun) keeps deployments and scaling events safe for users.
