8:T197f,<h1 class="text-2xl font-bold text-slate-100 mt-8 mb-4">Comparing Bun and Node.js performance for microservices</h1></p><p class="text-slate-300 leading-relaxed mb-4">You spin up dozens of small services—health checks, webhooks, workers—and every extra millisecond of cold start or CPU-bound work adds up. We ran a focused benchmark to see where Bun and Node.js actually differ for typical microservice workloads.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Why this comparison matters</h2></p><p class="text-slate-300 leading-relaxed mb-4">Microservices often do a mix of: starting fast (serverless or frequent restarts), parsing JSON (APIs, config), doing light CPU work, and reading files. Picking a runtime based on marketing claims is risky; real numbers on your own machine help. We measured cold start, JSON round-trip, a tight loop, and repeated file reads so you can map results to your own patterns.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What we measured</h2></p><p class="text-slate-300 leading-relaxed mb-4">We used a small runner script that spawns the same worker under Bun and Node and reports median times over five runs. Workloads:</p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Cold start</strong> — time to spawn a process that runs <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">console.log(1)</code> and exits (no heavy bootstrap).</li>
<li class="ml-4 list-disc text-slate-300"><strong>JSON parse/stringify</strong> — 50,000 rounds of <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">JSON.parse(JSON.stringify(obj))</code> on a small object.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Tight loop</strong> — 5 million iterations of a trivial loop (sum of indices).</li>
<li class="ml-4 list-disc text-slate-300"><strong>File read</strong> — 100 synchronous reads of <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">package.json</code> (same file path for both runtimes).</li></p><p class="text-slate-300 leading-relaxed mb-4">The worker is plain JavaScript (CommonJS) so both runtimes execute the same code. The runner lives at <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">scripts/bun-nodejs-benchmark-2026-02-13-00-50.ts</code>; you can re-run it with:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>bun run scripts/bun-nodejs-benchmark-2026-02-13-00-50.ts
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Results (median of 5 runs)</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Workload              | Bun    | Node   | Winner      |
|-----------------------|--------|--------|-------------|
| Cold start (spawn)    | 86.6 ms | 135.3 ms | Bun 1.6× faster |
| JSON (50k rounds)     | 147.5 ms | 145.1 ms | ~tie (Node 1.0×) |
| Tight loop (5M iter)  | 68.6 ms | 21.5 ms | Node 3.2× faster |
| File read (100×)      | 4.7 ms | 5.7 ms | Bun 1.2× faster |</p><p class="text-slate-300 leading-relaxed mb-4">So: <strong>Bun wins on cold start and file I/O</strong> in this setup; <strong>Node wins clearly on the tight numeric loop</strong>. JSON is effectively a tie.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">What this means for microservices</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>Serverless or frequent restarts</strong> — Bun’s faster cold start (1.6× here) can shave tens of milliseconds per invocation. That matters when you have many short-lived processes.</li>
<li class="ml-4 list-disc text-slate-300"><strong>JSON-heavy APIs</strong> — Neither runtime has a strong advantage in this test; choose based on ecosystem and tooling.</li>
<li class="ml-4 list-disc text-slate-300"><strong>CPU-bound helpers</strong> — Our tight-loop result is one data point: Node was 3.2× faster. If you have hot numeric or algorithmic code, benchmark it yourself; V8’s optimisations can dominate.</li>
<li class="ml-4 list-disc text-slate-300"><strong>File-heavy or I/O-bound</strong> — Bun was a bit faster on repeated sync file reads. For async I/O and real network or DB work, both are capable; again, measure your own workload.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Gotchas and lessons learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-disc text-slate-300"><strong>One machine, one point in time.</strong> Results were from a single run (2026-02-13); your OS, CPU, and Node/Bun versions will differ. The script writes results to <code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">scripts/bun-nodejs-benchmark-2026-02-13-00-50.result.txt</code> so you can compare.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Tight loops are not “typical” microservice code.</strong> Most services spend time in I/O and JSON. The loop test is there to show that <strong>Bun is not always faster</strong>—Node’s V8 can win on pure CPU. So avoid extrapolating “Bun is faster” to every workload.</li>
<li class="ml-4 list-disc text-slate-300"><strong>Cold start is process spawn only.</strong> We did not measure full framework bootstrap (e.g. Fastify or Hono). For real cold start, run your actual app under both runtimes.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Takeaway</h2></p><p class="text-slate-300 leading-relaxed mb-4">For microservices, <strong>Bun gives you quicker cold start and slightly faster sync file reads in our test</strong>; <strong>Node can be much faster on tight numeric loops</strong>. Run the benchmark script on your own box and, if possible, add a workload that matches your hottest path (e.g. a real handler or a DB round-trip). Use those numbers, not generic claims, to decide.</p><p class="text-slate-300 leading-relaxed mb-4"><hr class="border-slate-700 my-6" />
