title: SSE vs WebSocket vs Long Polling: When to Use Each, Scalability, and Code Examples in Bun
date: 2026-02-16
slug: sse-vs-websocket-vs-long-polling
tags: [SSE, WebSocket, Long Polling, Bun, Real-time Communication]
<hr class="border-slate-700 my-6" /></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Introduction</h2></p><p class="text-slate-300 leading-relaxed mb-4">In the world of web development, real-time communication is crucial for enhancing user experience. Three popular methods for achieving this are Server-Sent Events (SSE), WebSocket, and Long Polling. Each has its strengths and weaknesses, and choosing the right one for your application can significantly impact performance and scalability. This article will explore the differences between SSE, WebSocket, and Long Polling, provide real-world scenarios, and include code examples using Bun, a modern JavaScript runtime.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Real-World Scenario</h3></p><p class="text-slate-300 leading-relaxed mb-4">Imagine you're developing a weather application. Users want to receive real-time updates on weather conditions as they travel. To implement this, you need a method that can push updates from the server to the client without the client having to constantly poll the server.</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Server-Sent Events (SSE)</h2></p><p class="text-slate-300 leading-relaxed mb-4">SSE is a simple and lightweight technology that allows a server to push updates to a client over a single HTTP connection. It's ideal for one-way communication from server to client.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Code Example</h3></p><p class="text-slate-300 leading-relaxed mb-4">Here's a simple example of how to set up SSE in Bun:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// server.js
import { createServer } from 'http';
import { readFileSync } from 'fs';</p><p class="text-slate-300 leading-relaxed mb-4">const server = createServer((req, res) => {
  if (req.url === '/weather-updates') {
    res.writeHead(200, {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive'
    });</p><p class="text-slate-300 leading-relaxed mb-4">    const weatherData = readFileSync('/path/to/weather/data.json');
    res.write(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">data: ${weatherData}\n\n</code>);
  }
});</p><p class="text-slate-300 leading-relaxed mb-4">server.listen(3000, () => {
  console.log('Server running on port 3000');
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">WebSocket</h2></p><p class="text-slate-300 leading-relaxed mb-4">WebSocket is a full-duplex communication protocol that allows for real-time data exchange between the client and server. It's more complex than SSE but offers bidirectional communication.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Code Example</h3></p><p class="text-slate-300 leading-relaxed mb-4">Here's how to set up a WebSocket server in Bun:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// server.js
import { createServer } from 'ws';</p><p class="text-slate-300 leading-relaxed mb-4">const wss = new WebSocket.Server({ port: 3000 });</p><p class="text-slate-300 leading-relaxed mb-4">wss.on('connection', (ws) => {
  console.log('Client connected');</p><p class="text-slate-300 leading-relaxed mb-4">  ws.on('message', (message) => {
    console.log(<code class="bg-slate-700/50 px-1.5 py-0.5 rounded text-cyan-300 text-sm">Received message: ${message}</code>);
  });</p><p class="text-slate-300 leading-relaxed mb-4">  ws.send('Connected to WebSocket server');
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Long Polling</h2></p><p class="text-slate-300 leading-relaxed mb-4">Long Polling is a technique where the client sends a request to the server and the server holds the request open until new data is available. Once the data is available, the server sends a response, and the client immediately sends another request.</p><p class="text-slate-300 leading-relaxed mb-4"><h3 class="text-lg font-semibold text-slate-100 mt-6 mb-2">Code Example</h3></p><p class="text-slate-300 leading-relaxed mb-4">Here's an example of how to implement Long Polling in Bun:</p><p class="text-slate-300 leading-relaxed mb-4"><pre class="bg-slate-950 border border-slate-700 rounded-lg p-4 my-4 overflow-x-auto text-sm"><code>// server.js
import { createServer } from 'http';</p><p class="text-slate-300 leading-relaxed mb-4">const server = createServer((req, res) => {
  if (req.url === '/long-polling') {
    setTimeout(() => {
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({ message: 'New data available' }));
    }, 5000); // Wait for 5 seconds before sending a response
  }
});</p><p class="text-slate-300 leading-relaxed mb-4">server.listen(3000, () => {
  console.log('Server running on port 3000');
});
</code></pre></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Comparison Table</h2></p><p class="text-slate-300 leading-relaxed mb-4">| Feature            | SSE               | WebSocket         | Long Polling      |
|--------------------|-------------------|-------------------|-------------------|
| Communication      | One-way (server to client) | Bidirectional     | One-way (server to client) |
| Connection         | Persistent HTTP connection | Persistent WebSocket connection | Persistent HTTP connection |
| Latency            | Low               | Low               | High              |
| Implementation     | Simple            | Complex           | Simple            |
| Use Cases          | Live updates, stock tickers | Chat, gaming, real-time collaboration | Polling for new data |
| Scalability        | Moderate          | High              | Moderate          |</p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Lessons Learned</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Understand Use Cases</strong>: SSE is best for one-way communication with low latency, WebSocket for bidirectional communication, and Long Polling for simple polling scenarios.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Consider Scalability</strong>: WebSocket offers better scalability for real-time applications compared to SSE and Long Polling.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Use the Right Tool for the Job</strong>: Choose the communication method based on the specific requirements of your application.</li></p><p class="text-slate-300 leading-relaxed mb-4"><h2 class="text-xl font-bold text-slate-100 mt-8 mb-3">Actionable Takeaways</h2></p><p class="text-slate-300 leading-relaxed mb-4"><li class="ml-4 list-decimal text-slate-300"><strong>Evaluate Your Application's Needs</strong>: Determine whether your application requires one-way or bidirectional communication.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Test for Performance</strong>: Before deploying, test each method to ensure it meets your application's performance requirements.</li>
<li class="ml-4 list-decimal text-slate-300"><strong>Stay Updated</strong>: Keep abreast of new developments in real-time communication technologies to make informed decisions.</li></p><p class="text-slate-300 leading-relaxed mb-4">By understanding the differences between SSE, WebSocket, and Long Polling, you can make informed decisions about which technology to use for your web application's real-time communication needs.
