AgentWire: Patterns for Inter-Agent Communication (A2A)

As AI agent ecosystems evolve from monolithic entities to multi-agent systems (MAS), the "wire protocol"—how agents talk to each other—becomes the critical bottleneck for reliability and scalability. This guide outlines five fundamental communication patterns for agent-to-agent (A2A) coordination.

1. Request/Response (Synchronous)

The most common pattern, where an agent sends a specific query and waits for a direct answer. Best for simple lookups or linear task chains.

JSON Schema

{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "requestId": { "type": "string" },
    "method": { "type": "string" },
    "params": { "type": "object" }
  },
  "required": ["requestId", "method", "params"]
}

TypeScript Interface

interface AgentRequest {
  requestId: string;
  method: string;
  params: T;
}
interface AgentResponse {
  requestId: string;
  status: 'success' | 'error';
  data?: R;
  error?: string;
}

Example Implementation

async function callAgent(targetUrl: string, request: AgentRequest): Promise {
  const response = await fetch(targetUrl, {
    method: 'POST',
    body: JSON.stringify(request),
    headers: { 'Content-Type': 'application/json' }
  });
  return response.json();
}

2. Event-Driven (Pub/Sub)

Agents emit events to a message broker (e.g., Redis, RabbitMQ) without knowing who consumes them. Ideal for decoupling and high-throughput monitoring.

JSON Schema

{
  "type": "object",
  "properties": {
    "eventId": { "type": "string" },
    "topic": { "type": "string" },
    "payload": { "type": "object" },
    "timestamp": { "type": "string", "format": "date-time" }
  },
  "required": ["eventId", "topic", "payload"]
}

TypeScript Interface

interface AgentEvent
 {
  eventId: string;
  topic: string;
  payload: P;
  timestamp: string;
}

Example Implementation

import { EventEmitter } from 'events';
const bus = new EventEmitter();
// Subscriber
bus.on('task.completed', (event: AgentEvent) => {
  console.log(Agent ${event.payload.agentId} finished ${event.payload.taskId});
});
// Publisher
bus.emit('task.completed', {
  eventId: 'evt_123',
  topic: 'task.completed',
  payload: { agentId: 'worker-1', taskId: 'job-99' },
  timestamp: new Date().toISOString()
});

3. Shared State (Blackboard)

Agents read from and write to a common data store (Database, S3, or shared memory). This allows for indirect communication and long-lived context.

JSON Schema

{
  "type": "object",
  "properties": {
    "key": { "type": "string" },
    "value": { "type": "object" },
    "version": { "type": "integer" },
    "lastModifiedBy": { "type": "string" }
  },
  "required": ["key", "value"]
}

TypeScript Interface

interface SharedStateEntry {
  key: string;
  value: V;
  version: number;
  lastModifiedBy: string;
}

Example Implementation

class Blackboard {
  private store = new Map();
  update(key: string, value: any, agentId: string) {
    const current = this.store.get(key) || { key, value, version: 0, lastModifiedBy: agentId };
    this.store.set(key, {
      ...current,
      value,
      version: current.version + 1,
      lastModifiedBy: agentId
    });
  }
}

4. Delegation (CEO-Worker)

A hierarchical model where a "Manager" agent breaks a goal into sub-tasks and assigns them to specialized "Worker" agents.

JSON Schema

{
  "type": "object",
  "properties": {
    "delegationId": { "type": "string" },
    "instruction": { "type": "string" },
    "context": { "type": "array", "items": { "type": "string" } },
    "deadline": { "type": "string" }
  },
  "required": ["delegationId", "instruction"]
}

TypeScript Interface

interface DelegationTask {
  delegationId: string;
  instruction: string;
  context: string[];
  deadline?: string;
  priority: 'low' | 'medium' | 'high';
}

Example Implementation

class CEOAgent {
  async delegate(worker: WorkerAgent, task: string) {
    const delegation: DelegationTask = {
      delegationId: Math.random().toString(36),
      instruction: task,
      context: ["Project Alpha docs", "Previous logs"],
      priority: 'high'
    };
    return await worker.execute(delegation);
  }
}

5. Consensus (Voting/Quorum)

Agents collaborate to reach a single decision. Essential for high-stakes actions where a single agent's hallucination could be catastrophic.

JSON Schema

{
  "type": "object",
  "properties": {
    "proposalId": { "type": "string" },
    "proposal": { "type": "string" },
    "votes": { 
      "type": "array", 
      "items": {
        "type": "object",
        "properties": {
          "agentId": { "type": "string" },
          "vote": { "enum": ["approve", "reject", "abstain"] }
        }
      }
    }
  },
  "required": ["proposalId", "proposal"]
}

TypeScript Interface

type Vote = 'approve' | 'reject' | 'abstain';
interface ConsensusProposal {
  proposalId: string;
  content: any;
  votes: Record;
  threshold: number; // e.g., 0.66 for 2/3 majority
}

Example Implementation

function checkConsensus(proposal: ConsensusProposal): boolean {
  const approvals = Object.values(proposal.votes).filter(v => v === 'approve').length;
  const totalVotes = Object.keys(proposal.votes).length;
  return (approvals / totalVotes) >= proposal.threshold;
}

Decision Matrix: Choosing a Pattern

| Pattern | Latency | Complexity | Best For | | :--- | :--- | :--- | :--- | | Request/Response | Low | Low | Direct queries, API-like interactions. | | Event-Driven | Medium | Medium | Logging, monitoring, loosely coupled systems. | | Shared State | High | Medium | Long-running tasks, shared memory, context persistence. | | Delegation | Medium | High | Complex problem solving, hierarchical workflows. | | Consensus | High | High | Critical decisions, safety checks, hallucination mitigation. |
